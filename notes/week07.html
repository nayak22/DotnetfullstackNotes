DAY 1 · MON

Threads, tasks and the thread pool

GoalUnderstand what a thread is, why .NET code almost always uses Task instead, and how to tell CPU-bound work (needs a core) from I/O-bound work (needs waiting) — the single most important distinction in async programming.

Key definitions

Process
A running program with its own memory space. One process contains one or more threads.
Thread
An independent path of execution with its own stack. The OS scheduler decides which threads run on which CPU cores.
Foreground / background thread
The process stays alive until all foreground threads finish; background threads are killed when the process exits. Thread-pool threads are background threads.
Context switch
The OS pausing one thread and resuming another on a core. Cheap, but not free; thousands of threads mean lots of switching.
Thread pool
A shared set of reusable worker threads managed by .NET. It grows and shrinks based on load so you don't create threads yourself.
Task
An object representing an operation that will complete in the future: it has a status, may hold an exception, and can be awaited.
Task<TResult>
A Task that also produces a value of type TResult when it completes.
Task.Run
Queues a delegate to run on a thread-pool thread and returns a Task for it. Use it for CPU-bound work.
CPU-bound
Work limited by processor speed: calculations, compression, image resizing, parsing huge files in memory.
I/O-bound
Work that mostly waits for something outside the CPU: network, disk, database. No thread needs to be busy while waiting.
Concurrency
Several operations in progress during the same period of time (they may take turns on one core).
Parallelism
Several operations literally executing at the same instant on different cores. A subset of concurrency.
TaskStatus
The lifecycle state of a task: Created, WaitingForActivation, WaitingToRun, Running, RanToCompletion, Faulted, Canceled.
AggregateException
An exception that wraps one or more inner exceptions. Blocking APIs like Wait() and .Result throw it; await unwraps it.
ValueTask<T>
A struct alternative to Task<T> that avoids a heap allocation when the result is often available immediately.
Quick notes
  • You will rarely write new Thread(...) in modern .NET. Use Task and async/await.
  • Task.Run is for CPU-bound work. For I/O, call the library's async method (ReadAllTextAsync, GetAsync, ToListAsync).
  • While an I/O operation is in flight, no thread is sitting there waiting for it. That's why async scales.
  • A task that throws doesn't crash anything immediately: the exception is stored inside the task until someone awaits it.
  • await rethrows the original exception; .Wait() and .Result wrap it in AggregateException (and block a thread).
  • Default to Task/Task<T>. Reach for ValueTask only on hot paths that usually complete synchronously.

1. Threads: the raw building block

A thread is the unit the operating system schedules onto a CPU core. Your console app starts with one (the main thread). You can create more yourself, and seeing it once makes everything else this week easier to picture.

ThreadDemo.cs
Console.WriteLine($"Main thread id: {Environment.CurrentManagedThreadId}");

var printer = new Thread(() =>
{
    for (int i = 1; i <= 3; i++)
    {
        Console.WriteLine($"  Printing invoice INV-{i:000} on thread {Environment.CurrentManagedThreadId}");
        Thread.Sleep(200);                     // blocks THIS thread only
    }
})
{
    Name = "InvoicePrinter",
    IsBackground = false                       // foreground (the default): the process waits for it
};

printer.Start();
Console.WriteLine("Main thread carries on...");
printer.Join();                                // block the main thread until the printer finishes
Console.WriteLine("All invoices printed");

// Main thread id: 1
// Main thread carries on...                   ← these two lines can appear in either order:
//   Printing invoice INV-001 on thread 10     ← the OS decides who runs first (id varies)
//   Printing invoice INV-002 on thread 10
//   Printing invoice INV-003 on thread 10
// All invoices printed

Why not do this everywhere? Each thread reserves its own stack (around 1 MB or more of address space), takes time to create, and adds context switching. A web server handling 5,000 requests with 5,000 threads would spend more effort juggling threads than doing work. The thread pool and tasks solve this.

2. The thread pool and Task

The thread pool keeps a small set of worker threads alive and hands them short pieces of work. A Task is the object you get back: it tells you when the work is done, carries its result or exception, and can be awaited.

TaskBasics.cs
// Old style: queue work to the pool. No result, no way to await it, exceptions crash the process.
ThreadPool.QueueUserWorkItem(_ =>
    Console.WriteLine($"Pool thread {Environment.CurrentManagedThreadId}"));

// Modern style: Task.Run queues the same kind of work but gives you a Task back
Task log = Task.Run(() =>
    Console.WriteLine($"Task on thread {Environment.CurrentManagedThreadId}, " +
                      $"pool thread? {Thread.CurrentThread.IsThreadPoolThread}"));   // True
await log;                                     // wait without blocking (Tuesday explains how)

// Task<T>: the work produces a value
Task<decimal> totalTask = Task.Run(() =>
{
    decimal sum = 0;
    for (int i = 1; i <= 1_000_000; i++) sum += i % 1000 * 1.18m;   // CPU work: price incl. 18% GST
    return sum;
});

decimal total = await totalTask;
Console.WriteLine($"Total: ₹{total:N2}");

3. CPU-bound vs I/O-bound — and concurrency vs parallelism

Ask one question about any slow operation: is the CPU busy, or is it waiting?

CpuVsIo.cs
// CPU-bound: the CPU is busy the whole time → move it off the current thread with Task.Run
static decimal CalculateGst(IReadOnlyList<decimal> amounts)
{
    decimal gst = 0;
    foreach (decimal a in amounts) gst += Math.Round(a * 0.18m, 2);
    return gst;
}

List<decimal> amounts = Enumerable.Range(1, 2_000_000).Select(i => (decimal)(i % 5000)).ToList();

Console.WriteLine($"GST: ₹{gst:N2}");

await File.WriteAllTextAsync("invoices.csv", "INV-001,Asha Rao,1180.00\n");

await Task.Delay(500);                                      // a timer, not a sleeping thread

// ❌ Wrapping I/O in Task.Run: a pool thread now sits blocked waiting for the disk
string wasteful = await Task.Run(() => File.ReadAllText("invoices.csv"));

{
    await Task.Delay(50);
    throw new KeyNotFoundException($"No GST registration for state {stateCode}");
}

// await threw KeyNotFoundException
// Wait() threw AggregateException with 1 inner
Gotcha. A faulted task that nobody ever awaits or inspects is an unobserved exception: the error silently disappears (the TaskScheduler.UnobservedTaskException event fires much later, when the GC collects the task). Always await the tasks you start, or deliberately log their failures.

AggregateException exists because one task can represent many operations (e.g. Task.WhenAll, Wednesday), so it can hold many failures. Use ex.Flatten() when aggregates are nested, and ex.InnerExceptions to see them all.

5. ValueTask<T> — awareness, not a default

Every Task<T> is a heap object. If a method is called millions of times and usually has the answer ready (a cache hit), those allocations add up. ValueTask<T> is a struct that can hold the result directly, and only wraps a real Task when work is actually pending.

GstRateCache.cs
var cache = new GstRateCache();
Console.WriteLine(await cache.GetRateAsync("0401"));   // 0.05 (slow path, 100 ms)
Console.WriteLine(await cache.GetRateAsync("0401"));   // 0.05 (fast path, no allocation)

public class GstRateCache
{
    // Single-threaded demo; Friday shows ConcurrentDictionary for shared caches
    private readonly Dictionary<string, decimal> _rates = new(StringComparer.OrdinalIgnoreCase);

    public ValueTask<decimal> GetRateAsync(string hsnCode)
    {
        if (_rates.TryGetValue(hsnCode, out decimal rate))
            return ValueTask.FromResult(rate);                 // cache hit: no allocation, completes synchronously

        return new ValueTask<decimal>(LoadAndCacheAsync(hsnCode));   // cache miss: wrap a real Task
    }

    private async Task<decimal> LoadAndCacheAsync(string hsnCode)
    {
        await Task.Delay(100);                                 // pretend: call the GST rate service
        decimal rate = hsnCode.StartsWith("04") ? 0.05m : 0.18m;   // dairy 5%, everything else 18%
        _rates[hsnCode] = rate;
        return rate;
    }
}

Common mistakes

  • Using Task.Run to "make I/O async" — it just blocks a pool thread instead of the caller's thread.
  • Creating new Thread for short jobs instead of using tasks and the pool.
  • Starting a task and never awaiting it, so its exception is silently lost.
  • Catching AggregateException around await (await throws the inner exception) or the specific type around .Wait() (it throws AggregateException).
  • Returning ValueTask everywhere "for performance" and then awaiting it twice.

Self-check questions

Why does Task.Run not make a database call faster?The call is I/O-bound: the time is spent waiting for the database. Task.Run only moves the waiting onto a pool thread. Use the async database API so no thread waits at all.
What does await do with an exception stored in a faulted task?It rethrows the original exception (first inner exception), with its stack trace preserved, so you catch the real type like KeyNotFoundException.
When is ValueTask<T> worth using?On hot paths that very often complete synchronously (cache hits, buffered reads), where avoiding a Task allocation per call measurably helps.

Interview questions

Answer out loud first, then open each one to compare.

BasicWhat is the difference between a Thread and a Task?
A Thread is an OS-level execution path you create and manage directly. A Task is a higher-level promise of a future result: it's usually run on pooled threads (or, for async I/O, no thread at all while waiting), carries its result and exceptions, supports cancellation, and composes with await, WhenAll and WhenAny. Modern .NET code uses tasks.
BasicWhat is the difference between CPU-bound and I/O-bound work, and when should you use Task.Run?
CPU-bound work keeps a core busy (calculations, compression); I/O-bound work waits on network, disk or a database. Use Task.Run to offload CPU-bound work (for example, to keep a UI thread responsive). For I/O-bound work, await the library's async API directly; wrapping it in Task.Run wastes a thread.
BasicExplain concurrency vs parallelism.
Concurrency means multiple operations are in progress during overlapping time periods, possibly interleaved on one core (e.g. 50 awaited HTTP calls). Parallelism means operations execute at literally the same time on multiple cores (e.g. Parallel.For over a big array). Parallelism is one way of achieving concurrency.
IntermediateWhat happens when code inside a Task throws?
The exception is caught by the task infrastructure and stored; the task moves to Faulted and task.Exception holds an AggregateException. Awaiting the task rethrows the original inner exception; .Wait() and .Result throw the AggregateException. If nobody observes it, the error is lost and only the UnobservedTaskException event reports it later.
IntermediateWhat is ValueTask and what are its restrictions?
A struct that can hold a result directly or wrap a Task/IValueTaskSource, avoiding allocations when an async method usually completes synchronously. Restrictions: await it only once, never concurrently, don't block on it before it's complete; call AsTask() if you need Task semantics. Default to Task unless profiling shows allocation pressure.
IntermediateWhy is Task.Run around I/O an anti-pattern in ASP.NET Core?
ASP.NET Core requests already run on pool threads. Task.Run just switches to another pool thread, which then blocks on synchronous I/O, so you use two threads instead of zero and add scheduling overhead. Under load this leads to thread-pool starvation. Use true async APIs end to end.
DAY 2 · TUE

async/await: how it works and how to use it well

GoalKnow exactly what happens when execution hits an await, what the compiler generates, where the code after an await runs, and the handful of rules (async all the way, no .Result, no async void, ConfigureAwait in libraries) that prevent deadlocks and crashes.

Key definitions

async
A modifier that lets a method use await. It does not by itself make anything run on another thread.
await
Pauses the method until the awaited task completes, without blocking the thread; then resumes with the result or rethrows the exception.
Awaitable
Anything with a GetAwaiter() method: Task, Task<T>, ValueTask, Task.Yield(), and more.
Continuation
The rest of the method after an await, packaged up to run when the awaited operation completes.
State machine
The struct/class the compiler generates for an async method; it stores locals as fields and a state number recording which await to resume after.
SynchronizationContext
An object that says where continuations should run, e.g. "back on the UI thread". Console apps and ASP.NET Core don't have one.
TaskScheduler
Decides where tasks run when there's no SynchronizationContext; the default schedules onto the thread pool.
ConfigureAwait(false)
Tells await not to capture the current SynchronizationContext, so the continuation can run on any pool thread.
Sync-over-async
Blocking on async code with .Result, .Wait() or GetAwaiter().GetResult(). Causes deadlocks and thread starvation.
Async all the way
If a method awaits, its caller should be async and await it too, up to the entry point (Main, controller action, event handler).
async void
An async method returning void. Can't be awaited; its exceptions are raised directly on the SynchronizationContext or thread pool, usually crashing the app.
Fire-and-forget
Starting async work without awaiting it. Dangerous unless failures are explicitly handled.
Task.CompletedTask / Task.FromResult
Ready-made completed tasks for implementing async signatures synchronously.
Quick notes
  • An async method runs synchronously until the first await on an incomplete task. Only then does it return to its caller.
  • Awaiting an already-completed task continues immediately on the same thread — no pause, no thread switch.
  • After an await the code may resume on a different thread (console, ASP.NET Core) or back on the UI thread (WinForms, WPF, MAUI).
  • Name async methods with the Async suffix and return Task, Task<T> or ValueTask<T>.
  • Libraries: ConfigureAwait(false) on every await. ASP.NET Core and console app code: not needed.
  • async void only for event handlers. Everything else returns Task.

1. What await actually does

AwaitDemo.cs
Console.WriteLine($"1. Before call     thread {Environment.CurrentManagedThreadId}");
string report = await BuildSalesReportAsync();
Console.WriteLine($"4. Got the report  thread {Environment.CurrentManagedThreadId}: {report}");

static async Task<string> BuildSalesReportAsync()
{
    Console.WriteLine($"2. Method started  thread {Environment.CurrentManagedThreadId}");
    await Task.Delay(500);         // incomplete task → method pauses here and RETURNS to the caller
    Console.WriteLine($"3. Method resumed  thread {Environment.CurrentManagedThreadId}");
    return "Sales ₹4,52,000";
}

// 1. Before call     thread 1
// 2. Method started  thread 1     ← synchronous up to the first real await
// 3. Method resumed  thread 6     ← console app: no SynchronizationContext → any pool thread
// 4. Got the report  thread 6: Sales ₹4,52,000

Step by step, when execution reaches await someTask:

  1. Check someTask.IsCompleted. If it's already done, take the result and keep going on the same thread — no pause at all.
  2. If not, capture the current SynchronizationContext (if any), register "the rest of this method" as a continuation on the task, and return an incomplete Task to the caller. The thread is now free to do other work (serve another request, repaint the window).
  3. When the operation finishes (a timer fires, a network packet arrives), the continuation is scheduled: back on the captured context if there was one, otherwise on a thread-pool thread.
  4. The method resumes after the await with its locals intact, either getting the result or having the original exception rethrown.
Tip. There's no thread sitting inside Task.Delay(500) or a pending HTTP call. The OS notifies .NET when the I/O completes. That's how a server with 30 pool threads can have 10,000 requests waiting on a database at once.

2. What the compiler generates

The compiler rewrites every async method into a state machine. Locals become fields (so they survive the pause), and each await becomes a numbered resume point. You never write this, but knowing its shape explains every behaviour above.

StateMachine (pseudo-code)
// What you write
public async Task<decimal> GetInvoiceTotalAsync(int invoiceId)
{
    Invoice invoice = await _repository.LoadAsync(invoiceId);
    decimal rate = await _gst.GetRateAsync(invoice.StateCode);
    return invoice.Amount * (1 + rate);
}

// Roughly what the compiler generates (simplified pseudo-code, not compilable)
struct GetInvoiceTotalAsync_StateMachine : IAsyncStateMachine
{
    public int state;                                 // -1 running, 0 = paused at await #1, 1 = at await #2
    public AsyncTaskMethodBuilder<decimal> builder;   // creates the Task the caller receives, completes it later
    public int invoiceId;                             // parameters and locals are FIELDS now
    private Invoice invoice;
    private TaskAwaiter<Invoice> awaiter1;
    private TaskAwaiter<decimal> awaiter2;

    public void MoveNext()                            // called once to start, then once per resume
    {
        try
        {
            if (state == 0) goto Resume1;
            if (state == 1) goto Resume2;

            awaiter1 = _repository.LoadAsync(invoiceId).GetAwaiter();
            if (!awaiter1.IsCompleted)
            {
                state = 0;
                builder.AwaitUnsafeOnCompleted(ref awaiter1, ref this);   // "call MoveNext again when done"
                return;                                                     // ← the thread leaves here
            }
        Resume1:
            invoice = awaiter1.GetResult();           // returns the value or rethrows the original exception

            awaiter2 = _gst.GetRateAsync(invoice.StateCode).GetAwaiter();
            if (!awaiter2.IsCompleted) { state = 1; builder.AwaitUnsafeOnCompleted(ref awaiter2, ref this); return; }
        Resume2:
            decimal rate = awaiter2.GetResult();
            builder.SetResult(invoice.Amount * (1 + rate));   // completes the caller's Task<decimal>
        }
        catch (Exception ex)
        {
            builder.SetException(ex);                 // exceptions go INTO the task (Monday) instead of propagating
        }
    }
}

Consequences you can now explain: exceptions end up inside the returned task; an async method with no awaits runs fully synchronously (and the compiler warns CS1998); ref/out parameters aren't allowed in async methods (they can't be stored as fields); and in Release builds the state machine is a struct, so the fast path where everything completes synchronously allocates nothing extra.

4. Async all the way — never .Result or .Wait()

Blocking on async code is called sync-over-async. With a SynchronizationContext it deadlocks; without one it wastes threads.

Deadlock (WinForms fragment)
// ❌ The classic deadlock (WinForms/WPF or classic ASP.NET)
private void btnTotal_Click(object sender, EventArgs e)
{
    decimal total = GetTotalAsync().Result;   // (1) UI thread BLOCKS, waiting for the task
    lblTotal.Text = total.ToString("N2");
}

private async Task<decimal> GetTotalAsync()
{
    await Task.Delay(1000);                   // (2) captures the UI context
    return 1180m;                             // (3) continuation must run on the UI thread...
}                                             //     ...which is blocked in (1) → both wait forever. App freezes.

// ✓ Make the caller async too
private async void btnTotal_Click(object sender, EventArgs e)
{
    decimal total = await GetTotalAsync();
    lblTotal.Text = total.ToString("N2");
}

In ASP.NET Core and console apps the same code won't deadlock (no context), but each blocked request holds a pool thread hostage. Under load the pool runs dry, new requests queue up, and response times explode — thread-pool starvation. The fix is the same everywhere: make the caller async and await.

BasicWhat does the await keyword do?
It checks whether the awaited task is complete. If so, it continues immediately. If not, it registers the rest of the method as a continuation, returns an incomplete task to the caller and frees the thread. When the task completes, the method resumes (on the captured context if any, otherwise a pool thread), returning the result or rethrowing the original exception.
BasicWhy should you avoid async void?
Callers can't await it, so they don't know when it finishes, and exceptions can't be caught by the caller; they're raised on the SynchronizationContext or thread pool and typically crash the process. It's also hard to test. Use async Task; async void is only for event handlers, whose signature demands void.
BasicWhat does "async all the way" mean?
Once a method is async, its callers should also be async and await it, up to the entry point (async Main, controller action, event handler). Mixing in blocking calls like .Result breaks the chain and causes deadlocks or thread starvation.
IntermediateExplain the deadlock caused by calling .Result in a UI or classic ASP.NET app.
The UI thread calls .Result and blocks. Inside the async method, an await captured the UI SynchronizationContext, so its continuation must run on the UI thread. That thread is blocked waiting for the task, and the task can't finish without that thread, so both wait forever. Fix: await instead of blocking; libraries can also use ConfigureAwait(false).
IntermediateWhat is ConfigureAwait(false) and when should you use it?
It tells the await not to resume on the captured SynchronizationContext, letting the continuation run on any pool thread. Use it in general-purpose library code for performance and to avoid deadlocks when callers block. Don't use it in UI code that must update controls afterwards. In ASP.NET Core app code it has no effect because there is no context.
IntermediateHow does the compiler implement async methods?
It generates a state machine type implementing IAsyncStateMachine. Locals and parameters become fields, each await becomes a numbered state, and MoveNext runs the code up to the next incomplete await, registers itself as the continuation via an AsyncTaskMethodBuilder and returns. When the awaited task completes, MoveNext is called again and jumps to the saved state. Exceptions are caught and stored in the returned task via SetException.

Task.WhenAll, Task.WhenAny, cancellation and timeouts

GoalRun independent operations at the same time, handle all of their failures, stop work cleanly with CancellationToken, and put a time limit on anything that might hang.

Key definitions

Task.WhenAll
Returns a task that completes when all the given tasks complete. For Task<T> inputs, its result is a T[] in input order.
Task.WhenAny
Returns a task that completes when any one of the given tasks completes; its result is the winning task itself.
Task.WhenEach
.NET 9: an IAsyncEnumerable that yields tasks one by one in the order they complete.
CancellationTokenSource (CTS)
The object that requests cancellation: Cancel(), CancelAfter(). Owned by whoever decides to stop. Disposable.
CancellationToken
A read-only struct handed to the work so it can observe cancellation: IsCancellationRequested, ThrowIfCancellationRequested(), Register().
Cooperative cancellation
Nothing is forcibly killed. The work checks the token and stops itself at a safe point.
OperationCanceledException
The standard exception meaning "stopped because cancellation was requested". A task that throws it with its token ends in the Canceled state.
TaskCanceledException
A subclass of OperationCanceledException thrown by Task.Delay, HttpClient and others. Catch the base type.
CancelAfter
Schedules the CTS to cancel itself after a time span — the standard way to implement timeouts.
Linked token source
CancellationTokenSource.CreateLinkedTokenSource(a, b): cancelled when any source token is cancelled. Used to combine "caller cancelled" with "our timeout".
Task.WaitAsync
.NET 6: returns a task that completes when the original does, or throws TimeoutException / OperationCanceledException if the time or token runs out first.
CancellationToken.None
An empty token that is never cancelled; the default value for optional token parameters.
Quick notes
  • Start every independent task first, then await them together. Awaiting one by one makes them sequential.
  • await Task.WhenAll(...) throws only one of the exceptions (don't rely on which); all of them are in the WhenAll task's .Exception.
  • Task.WhenAny never throws. Await the winner to get its result, and cancel the losers yourself.
  • Accept a CancellationToken as the last parameter of every async method, and pass it to everything you call.
  • Catch OperationCanceledException, not TaskCanceledException, so you handle both.
  • WaitAsync stops you waiting; it doesn't stop the operation. Prefer passing a token when the API accepts one.

static decimal ReconcileLedger(IReadOnlyList<decimal> entries, CancellationToken ct)

5. Timeouts: CancelAfter, linked tokens and WaitAsync

Most real methods have two reasons to stop: the caller cancelled (user clicked Cancel, HTTP request aborted) or our own time limit ran out. Link them:

static async Task<decimal> GetUsdInrRateAsync(CancellationToken callerToken)
{
    using var cts = CancellationTokenSource.CreateLinkedTokenSource(callerToken);
    cts.CancelAfter(TimeSpan.FromSeconds(2));                // our own limit for this call

    try
    {
        await Task.Delay(3000, cts.Token);                   // pretend: slow exchange-rate service
        return 83.20m;
    }
    catch (OperationCanceledException) when (!callerToken.IsCancellationRequested)
    {
        // The caller didn't cancel, so it must have been our timeout → report it as a timeout
        throw new TimeoutException("Exchange-rate service took longer than 2 s");
    }
}

5. IAsyncEnumerable<T> and await foreach

Last week's yield return produced items lazily, but each item had to be ready synchronously. An async iterator can await between items — perfect for paged APIs, database cursors and log tails. The consumer processes page 1 while page 2 hasn't even been requested.

using System.Runtime.CompilerServices;

await foreach (Order order in GetAllOrdersAsync())

// async + IAsyncEnumerable<T> + yield return = async iterator
static async IAsyncEnumerable<Order> GetAllOrdersAsync(
    [EnumeratorCancellation] CancellationToken ct = default)
{
    for (int page = 1; ; page++)
    {
        Order[] batch = await FetchPageAsync(page, ct);    // one "API call" per page
        if (batch.Length == 0) yield break;
        foreach (Order order in batch)
            yield return order;                            // hand over items while later pages aren't fetched yet
    }
}

static async Task<Order[]> FetchPageAsync(int page, CancellationToken ct)
{
    await Task.Delay(300, ct);
    Console.WriteLine($"  [fetched page {page}]");

    return Enumerable.Range((page - 1) * 2 + 1, 2)
                     .Select(i => new Order(i, $"Customer {i}", 1000m * i))

BasicWhy shouldn't you create a new HttpClient for every request?
Each disposed client closes its connections, which remain in TIME_WAIT on the OS for a while. Under load you exhaust available sockets and requests start failing; you also pay TCP/TLS setup every time. Reuse a single client (or use IHttpClientFactory), which pools connections and is safe for concurrent requests.
BasicWhat does HttpClient do when a request returns 404?
GetAsync/SendAsync return normally with StatusCode = NotFound; no exception. GetStringAsync and GetFromJsonAsync, or calling EnsureSuccessStatusCode, throw HttpRequestException with StatusCode 404. Network failures (DNS, refused connection) always throw HttpRequestException with a null StatusCode.
BasicWhat is IAsyncEnumerable<T> and when would you use it?
An asynchronous sequence consumed with await foreach, where getting each item may involve awaiting. Use it for paged APIs, streaming database results, reading large files or real-time feeds, so consumers can process items as they arrive with low memory instead of waiting for a whole list.
IntermediateWhat problems does IHttpClientFactory solve?
It pools HttpMessageHandlers and rotates them periodically, avoiding both socket exhaustion (from creating many clients) and stale DNS (from one client living forever). It also centralises configuration as named or typed clients and integrates with DI, logging and resilience handlers like Polly.
IntermediateHow do you implement per-request timeouts with HttpClient and tell them apart from cancellation?
Create a CTS linked to the caller's token, call CancelAfter(timeout), and pass its token to the request. If OperationCanceledException is thrown and the caller's token is not cancelled, it was the timeout. For HttpClient.Timeout itself, .NET 5+ throws TaskCanceledException with an inner TimeoutException.
IntermediateHow do you pass a CancellationToken into an async iterator?
Add a CancellationToken parameter marked [EnumeratorCancellation]. Callers can pass it directly as an argument, or use source.WithCancellation(token) in await foreach; the attribute makes the compiler combine that token with the parameter. Pass the token to every await inside the iterator.

Thread safety, concurrent collections and Parallel

GoalSee a race condition happen, fix it with lock, Interlocked or a concurrent collection, throttle async work with SemaphoreSlim, use Parallel.For/ForEach/ForEachAsync for the right kind of work, and recognise and prevent deadlocks.

Key definitions

Shared state
Data that more than one thread can read and write at the same time, e.g. a field, a static, or a captured local.
Race condition
A bug where the result depends on the unpredictable timing of threads, e.g. two increments overlapping so one is lost.
Atomic operation
An operation that happens completely or not at all, with no other thread able to see it half-done.
Critical section
A block of code that only one thread may execute at a time.
lock / Monitor
C#'s lock statement: Monitor.Enter/Exit in a try/finally on a private object. Mutual exclusion for synchronous code.
System.Threading.Lock
.NET 9 + C# 13: a dedicated lock type. lock(_lock) on it uses Lock.EnterScope(), which is faster and clearer than locking an object.
Interlocked
Static methods (Increment, Add, Exchange, CompareExchange) that perform single updates atomically using CPU instructions, without a lock.
ConcurrentDictionary<K,V>
A thread-safe dictionary with atomic helpers like GetOrAdd, AddOrUpdate, TryRemove.
ConcurrentQueue<T>
A thread-safe FIFO queue (Enqueue, TryDequeue) — lock-free for producers and consumers.
SemaphoreSlim
Allows up to N callers into a section at once. WaitAsync makes it the standard tool for async throttling and async locks.
Parallel.For / ForEach
Run a loop body on multiple threads for CPU-bound work, blocking until all iterations finish.
Parallel.ForEachAsync
.NET 6: run an async body for each item with a cap on how many run at once (MaxDegreeOfParallelism).
Deadlock
Two or more threads each waiting for something another holds, so none can ever proceed.
Thread-safe
Behaves correctly when called from multiple threads at once, without extra synchronisation by the caller.
Quick notes
  • count++ is three steps (read, add, write). Two threads can interleave them and lose updates.
  • The best shared state is no shared state: give each task its own data, then combine results at the end.
  • lock on a private readonly object (or a .NET 9 Lock), never on this, a type, or a string.
  • You can't await inside a lock. Use SemaphoreSlim(1, 1) with WaitAsync for async code.
  • Concurrent collections make each call atomic, not a sequence of calls. Use their combined methods (GetOrAdd, AddOrUpdate).
  • Parallel.ForEach with an async lambda is async void. Use Parallel.ForEachAsync.

The classic real-world version is check-then-act: two threads both see enough balance, and both withdraw. A lock makes the check and the update one indivisible step:

Wallet.cs
var wallet = new Wallet(openingBalance: 1_000m);
int paid = 0;

Parallel.For(0, 100, _ =>                      // 100 simultaneous ₹50 UPI payments
{
    if (wallet.TryPay(50m)) Interlocked.Increment(ref paid);
});
Console.WriteLine($"{paid} payments, balance ₹{wallet.Balance}");   // 20 payments, balance ₹0 — every time

public class Wallet(decimal openingBalance)
{
    private readonly object _sync = new();     // private: no outside code can lock on it
    private decimal _balance = openingBalance;

    public decimal Balance { get { lock (_sync) return _balance; } }

    public bool TryPay(decimal amount)
    {
        lock (_sync)                           // one thread at a time in here
        {
            if (_balance < amount) return false;   // check...
            _balance -= amount;                    // ...and act, as one atomic unit
            return true;
        }
    }
}

.NET 9 (with C# 13) adds a purpose-built lock type. The syntax stays the same; the compiler sees the type and generates faster code:

WalletNet9.cs
public class WalletNet9(decimal openingBalance)
{
    private readonly Lock _sync = new();       // System.Threading.Lock (.NET 9+)
    private decimal _balance = openingBalance;

    public bool TryPay(decimal amount)
    {
        lock (_sync)                           // compiles to: using (_sync.EnterScope()) { ... }
        {
            if (_balance < amount) return false;
            _balance -= amount;
            return true;
        }
    }
}
Rule. await inside a lock is a compile error (CS1996): a lock is owned by a thread, and after an await you may be on a different thread. Use SemaphoreSlim (section 4) for async critical sections.

    Console.WriteLine($"{city}: {count}");

// Delhi: 2
// Chennai: 1
// Kochi: 1

string report = reports.GetOrAdd(2026, year => new Lazy<string>(() => $"Annual report {year}")).Value;

// ConcurrentQueue: many producers, many consumers, no locks
var printQueue = new ConcurrentQueue<string>();
Parallel.For(1, 6, i => printQueue.Enqueue($"INV-{i:000}"));

4. SemaphoreSlim: async throttling and async locks

Starting 500 HTTP calls at once with WhenAll may get you rate-limited (429) or overload a partner API. A semaphore with N slots lets at most N callers in at a time; the rest asynchronously wait their turn.

Throttling.cs
var gate = new SemaphoreSlim(initialCount: 3, maxCount: 3);   // the e-invoice portal allows 3 parallel calls
int inFlight = 0;

await Task.WhenAll(Enumerable.Range(1, 10).Select(SubmitInvoiceAsync));
Console.WriteLine("All submitted");

async Task SubmitInvoiceAsync(int invoiceNo)
{
    await gate.WaitAsync();                  // take a slot, or wait (no thread blocked) until one frees up
    try
    {
        int now = Interlocked.Increment(ref inFlight);
        Console.WriteLine($"Submitting INV-{invoiceNo:000} (in flight: {now})");
        await Task.Delay(500);               // pretend: HTTP POST to the portal
    }
    finally
    {
        Interlocked.Decrement(ref inFlight);
        gate.Release();                      // ALWAYS in finally, or a failure leaks a slot forever
    }
}

// "in flight" never exceeds 3; 10 invoices take ~2 s (4 waves × 500 ms) instead of 0.5 s unthrottled
// or 5 s sequential

{

    private string? _token;
    private DateTime _expiresUtc;

    public async Task<string> GetTokenAsync(CancellationToken ct = default)
    {

        try
        {
            if (_token is null || DateTime.UtcNow >= _expiresUtc)

            return _token;
        }
        finally { _mutex.Release(); }
    }
}

6. Deadlocks

A deadlock needs threads holding one resource while waiting for another, in a cycle. Bank transfers locking two accounts are the textbook case:

Deadlock.cs
var sb1001 = new Account("SB1001", 5_000m);
var sb1002 = new Account("SB1002", 5_000m);

// ❌ Locks taken in "from, to" order: two opposite transfers can deadlock
static void Transfer(Account from, Account to, decimal amount)
{
    lock (from.Sync)
    {
        Thread.Sleep(10);                  // widen the window so it happens reliably in the demo
        lock (to.Sync)
        {
            from.Balance -= amount;
            to.Balance += amount;
        }
    }
}
// Task t1 = Task.Run(() => Transfer(sb1001, sb1002, 100));   // holds SB1001, waits for SB1002
// Task t2 = Task.Run(() => Transfer(sb1002, sb1001, 200));   // holds SB1002, waits for SB1001
// await Task.WhenAll(t1, t2);                                  // never completes

// ✓ Always lock in a global order (here: by account number), whatever the direction
static void SafeTransfer(Account from, Account to, decimal amount)
{
    var (first, second) = string.CompareOrdinal(from.Number, to.Number) < 0 ? (from, to) : (to, from);
    lock (first.Sync)
    lock (second.Sync)
    {
        from.Balance -= amount;
        to.Balance += amount;
    }
}

await Task.WhenAll(
    Task.Run(() => SafeTransfer(sb1001, sb1002, 100)),
    Task.Run(() => SafeTransfer(sb1002, sb1001, 200)));

Is ConcurrentDictionary.GetOrAdd's factory guaranteed to run once?No. Under contention several threads may run it; only one value is stored and returned to everyone. Use Lazy<T> values if the factory must run once.
Which Parallel API for 200 HTTP calls with at most 8 at once?Parallel.ForEachAsync with MaxDegreeOfParallelism = 8, or SemaphoreSlim(8) + Task.WhenAll. Not Parallel.ForEach.

Interview questions

Answer out loud first, then open each one to compare.

BasicWhat is a race condition? Give an example.
A bug where correctness depends on thread timing. Example: two threads run balance -= amount after both checked the balance was sufficient; or two threads run counter++ and one increment is lost because read-modify-write steps interleave. Fix by making the operation atomic (lock, Interlocked) or by not sharing the state.
BasicWhat is the difference between lock and Interlocked?
lock gives mutual exclusion over any block of code, so it can protect several fields and check-then-act logic, at the cost of possible contention. Interlocked performs a single operation (increment, add, exchange, compare-exchange) atomically on one variable using CPU instructions, without blocking; it can't protect multi-step logic.
BasicHow do you limit the number of concurrent async operations?
Use SemaphoreSlim(n): await WaitAsync() before each operation and Release() in a finally, combined with Task.WhenAll. Or use Parallel.ForEachAsync with ParallelOptions.MaxDegreeOfParallelism = n (.NET 6+).
IntermediateWhat does the System.Threading.Lock type in .NET 9 change?
It's a dedicated lock object. When a lock statement targets a Lock (with C# 13), the compiler calls Lock.EnterScope() and disposes the scope instead of using Monitor on an arbitrary object, which is faster and makes intent explicit. The same rules apply: keep sections short and never await inside.
IntermediateCompare Parallel.ForEach, Parallel.ForEachAsync and Task.WhenAll.
Parallel.ForEach is for CPU-bound synchronous bodies and blocks the caller until done. Parallel.ForEachAsync runs async bodies with a degree-of-parallelism cap and returns a Task, ideal for throttled I/O. Task.WhenAll awaits tasks you've already started; it has no built-in limit, so pair it with SemaphoreSlim for large batches.
IntermediateWhat is a deadlock and how do you prevent it?
Two or more threads each hold a resource and wait for one held by another, forming a cycle, so none can continue. Prevent it with a global lock order, holding locks briefly without calling external code, using timeouts (Monitor.TryEnter, WaitAsync(timeout)), reducing shared state, and avoiding sync-over-async blocking such as .Result on a context-bound task.

namespace Downloader.Core;

/// <summary>
/// Simulates a web server so the project runs without internet.
/// Hosts ending in .invalid fail like a DNS error; /status/NNN returns that status;
/// /delay/N waits N extra seconds (same conventions as httpbin.org).
/// </summary>
public sealed class FakePageSource(int minDelayMs = 200, int maxDelayMs = 1200, double transientFailureRate = 0)
    : IPageSource
{
    public async Task<PageContent> GetAsync(Uri url, CancellationToken ct)
    {
        int delay = Random.Shared.Next(minDelayMs, maxDelayMs + 1);
        await Task.Delay(delay, ct);                                   // "network latency"; honours cancellation

        if (url.Host.EndsWith(".invalid", StringComparison.OrdinalIgnoreCase))
            throw new HttpRequestException($"Name or service not known ({url.Host}:{url.Port})");

        string path = url.AbsolutePath;
        if (path.StartsWith("/status/") && int.TryParse(path["/status/".Length..], out int code))
            return new PageContent(code, []);
        if (path.StartsWith("/delay/") && int.TryParse(path["/delay/".Length..], out int seconds))
            await Task.Delay(TimeSpan.FromSeconds(seconds), ct);

        if (Random.Shared.NextDouble() < transientFailureRate)
            return new PageContent(503, []);                           // Service Unavailable: worth retrying (Sunday)

        string html = $"<!doctype html><title>{url.Host}</title><h1>{url}</h1>" +
                      $"<p>Fake page served in {delay} ms.</p>" + new string(' ', delay * 10);
        return new PageContent(200, Encoding.UTF8.GetBytes(html));
    }
}

using System.Security.Cryptography;
using System.Text;

namespace Downloader.Core;

public static class FileNames
{
    private static readonly char[] Invalid = Path.GetInvalidFileNameChars();

    // https://learn.microsoft.com/en-us/dotnet/  →  learn.microsoft.com_en-us_dotnet.html
    public static string FromUrl(Uri url)
    {
        string path = url.AbsolutePath.Trim('/');
        string raw = path.Length == 0 ? url.Host : $"{url.Host}_{path}";

        var sb = new StringBuilder(raw.Length);
        foreach (char c in raw)
            sb.Append(c is '/' or '\\' or ':' || Array.IndexOf(Invalid, c) >= 0 ? '_' : c);
        string name = sb.Length > 80 ? sb.ToString(0, 80) : sb.ToString();

        if (url.Query.Length > 1)   // ?page=2 and ?page=3 must not overwrite each other
        {
            byte[] hash = SHA256.HashData(Encoding.UTF8.GetBytes(url.Query));
            name += "_" + Convert.ToHexString(hash)[..8].ToLowerInvariant();
        }

        return name.EndsWith(".html", StringComparison.OrdinalIgnoreCase) ? name : name + ".html";
    }
}
Downloader.Core/UrlList.cs
namespace Downloader.Core;

public sealed record UrlListResult(IReadOnlyList<Uri> Urls, IReadOnlyList<string> Rejected);

public static class UrlList
{
    public static async Task<UrlListResult> LoadAsync(string path, CancellationToken ct = default)
    {
        var urls = new List<Uri>();
        var rejected = new List<string>();
        var seen = new HashSet<string>(StringComparer.Ordinal);
        int lineNo = 0;

        await foreach (string raw in File.ReadLinesAsync(path, ct))       // .NET 7+: an async stream of lines
        {
            lineNo++;
            string line = raw.Trim();
            if (line.Length == 0 || line.StartsWith('#')) continue;        // blank lines and comments

            if (!Uri.TryCreate(line, UriKind.Absolute, out Uri? uri) || uri.Scheme is not ("http" or "https"))
                rejected.Add($"line {lineNo}: not an http(s) URL → {line}");
            else if (!seen.Add(uri.AbsoluteUri))
                rejected.Add($"line {lineNo}: duplicate → {line}");
            else
                urls.Add(uri);
        }
        return new UrlListResult(urls, rejected);
    }
}
Tip. The scheme check matters: on Linux and macOS, Uri.TryCreate("/etc/passwd", UriKind.Absolute, ...) succeeds and produces a file:// URI. Never let a URL list read local files.

Step 4 — PageDownloader: sequential, SemaphoreSlim and Parallel.ForEachAsync

Downloader.Core/PageDownloader.cs
using System.Diagnostics;

namespace Downloader.Core;

public sealed class PageDownloader(IPageSource source, DownloadOptions options)
{
    // Baseline: one at a time
    public async Task<DownloadSummary> DownloadSequentialAsync(IReadOnlyList<Uri> urls, CancellationToken ct = default)
    {
        Directory.CreateDirectory(options.OutputDirectory);
        var sw = Stopwatch.StartNew();
        var results = new List<DownloadResult>(urls.Count);
        foreach (Uri url in urls)
            results.Add(await DownloadOneAsync(url, ct));
        return new DownloadSummary(results, sw.Elapsed);
    }

    // Strategy 1: start a task per URL, but let only MaxConcurrency past the gate at once
    public async Task<DownloadSummary> DownloadWithSemaphoreAsync(IReadOnlyList<Uri> urls, CancellationToken ct = default)
    {
        Directory.CreateDirectory(options.OutputDirectory);
        var sw = Stopwatch.StartNew();
        using var gate = new SemaphoreSlim(options.MaxConcurrency, options.MaxConcurrency);

        async Task<DownloadResult> ThrottledAsync(Uri url)
        {
            await gate.WaitAsync(ct);
            try { return await DownloadOneAsync(url, ct); }
            finally { gate.Release(); }
        }

        DownloadResult[] results = await Task.WhenAll(urls.Select(ThrottledAsync));   // results in input order
        return new DownloadSummary(results, sw.Elapsed);
    }

    // Strategy 2: let Parallel.ForEachAsync (.NET 6+) manage the workers
    public async Task<DownloadSummary> DownloadWithParallelAsync(IReadOnlyList<Uri> urls, CancellationToken ct = default)
    {
        Directory.CreateDirectory(options.OutputDirectory);
        var sw = Stopwatch.StartNew();
        var results = new DownloadResult[urls.Count];        // each index written by exactly one worker → no lock
        var po = new ParallelOptions { MaxDegreeOfParallelism = options.MaxConcurrency, CancellationToken = ct };

        await Parallel.ForEachAsync(Enumerable.Range(0, urls.Count), po, async (i, token) =>
        {
            results[i] = await DownloadOneAsync(urls[i], token);
        });
        return new DownloadSummary(results, sw.Elapsed);
    }

    private async Task<DownloadResult> DownloadOneAsync(Uri url, CancellationToken ct)
    {
        var sw = Stopwatch.StartNew();
        try
        {
            PageContent page = await source.GetAsync(url, ct);
            if (page.StatusCode is < 200 or > 299)
                return new DownloadResult(url, DownloadStatus.Failed, sw.Elapsed, page.StatusCode, Error: $"HTTP {page.StatusCode}");

            string path = Path.Combine(options.OutputDirectory, FileNames.FromUrl(url));
            await File.WriteAllBytesAsync(path, page.Body, ct);
            return new DownloadResult(url, DownloadStatus.Succeeded, sw.Elapsed, page.StatusCode, page.Body.LongLength, path);
        }
        catch (OperationCanceledException) when (ct.IsCancellationRequested)
        {
            throw;                                            // the CALLER cancelled: stop the whole batch
        }
        catch (Exception ex) when (ex is HttpRequestException or OperationCanceledException or IOException or UnauthorizedAccessException)
        {
            // HttpRequestException: DNS / connection failure. OperationCanceledException (caller didn't cancel):
            // HttpClient.Timeout. IOException / UnauthorizedAccessException (read-only folder): couldn't write the file. One bad URL must not stop the rest.
            return new DownloadResult(url, DownloadStatus.Failed, sw.Elapsed, Error: ex.Message);
        }
    }
}

Why two concurrent strategies? They're the two idioms you'll meet in real code. SemaphoreSlim creates every task up front (cheap for hundreds of URLs, wasteful for millions) and gives an ordered array from WhenAll. Parallel.ForEachAsync keeps exactly N workers pulling items and needs you to store results yourself.

Interview questions

BasicWhy are concurrent downloads faster even on a single-core machine?
Downloading is I/O-bound: almost all the time is spent waiting for the network, during which no thread is busy. With async I/O, one core can have many requests in flight and handle each response as it arrives, so total time approaches the slowest request instead of the sum.
BasicWhy does DownloadOneAsync return a result instead of throwing for a 404 or DNS failure?
Failures of individual URLs are expected outcomes in a batch, not exceptional conditions for the whole run. Returning a DownloadResult keeps one bad URL from aborting the others (awaiting WhenAll would surface only one exception) and gives the report per-URL detail. Only caller cancellation is allowed to propagate.
IntermediateSemaphoreSlim + Task.WhenAll vs Parallel.ForEachAsync for this tool — which would you choose?
Both cap concurrency. SemaphoreSlim + WhenAll creates all tasks immediately and returns results in input order — simple and fine for hundreds of URLs. Parallel.ForEachAsync keeps a fixed number of workers pulling from the source, so it scales to huge or streaming inputs (IAsyncEnumerable) with constant memory, but you store results yourself. For a big crawl I'd pick Parallel.ForEachAsync.
IntermediateIs writing results[i] from many workers in Parallel.ForEachAsync thread-safe?
Yes, because each index is written by exactly one worker and array element writes don't interfere with each other; the array itself isn't resized. Adding to a shared List<T> instead would be a race. The completed ForEachAsync task also guarantees all writes are visible to the code after the await.

Cancellation, timeouts, retries, progress — and revision

GoalMake the downloader production-shaped: Ctrl+C cancels cleanly and still reports what finished, each request has its own timeout, transient failures are retried with exponential backoff, and progress is shown live. Then document it, push it and revise the week.

Key definitions

Graceful shutdown
Stopping on request (Ctrl+C) by cancelling work cooperatively, finishing or abandoning in-flight items, and still reporting results.
Console.CancelKeyPress
Event raised on Ctrl+C / Ctrl+Break. Setting e.Cancel = true stops the process from terminating immediately.
Transient fault
A temporary failure likely to succeed on retry: timeouts, connection resets, 408, 429, 502, 503, 504.
Exponential backoff
Waiting longer between each retry (e.g. 0.5 s, 1 s, 2 s) so a struggling server gets breathing room.
Jitter
A small random addition to each backoff delay so many clients don't all retry at the same instant.
IProgress<T>
Interface with one method, Report(T value), for publishing progress from work to whoever displays it.
Progress<T>
Built-in IProgress<T> that invokes a handler on the SynchronizationContext captured when it was created — or on the thread pool if there wasn't one.
Idempotent
Safe to repeat: doing it twice has the same effect as once. GET requests are; "charge ₹500" is not — only retry idempotent operations blindly.
Quick notes
  • Ctrl+C → cancel the token; work stops at the next await; the summary still prints.
  • A linked token per attempt gives each request its own timeout while still honouring Ctrl+C.
  • Retry only transient failures, a limited number of times, with growing delays and jitter.
  • In a console app Progress<T> runs handlers on pool threads — possibly concurrently and out of order. A tiny custom IProgress<T> that prints synchronously under a lock keeps lines from interleaving.
  • Polly (Week 43) does retries, timeouts and circuit breakers properly; writing a simple version first shows you what it's doing.

2. PageDownloader with cancellation, per-request timeout, retry and progress

Downloader.Core/PageDownloader.cs
using System.Diagnostics;

namespace Downloader.Core;

public sealed class PageDownloader(IPageSource source, DownloadOptions options, IProgress<DownloadProgress>? progress = null)
{
    private int _completed;

    public async Task<DownloadSummary> DownloadSequentialAsync(IReadOnlyList<Uri> urls, CancellationToken ct = default)
    {
        Prepare();
        var sw = Stopwatch.StartNew();
        var results = new List<DownloadResult>(urls.Count);
        foreach (Uri url in urls)
            results.Add(await DownloadOneAsync(url, urls.Count, ct));    // after Ctrl+C these return "cancelled" instantly
        return new DownloadSummary(results, sw.Elapsed);
    }

    public async Task<DownloadSummary> DownloadWithSemaphoreAsync(IReadOnlyList<Uri> urls, CancellationToken ct = default)
    {
        Prepare();
        var sw = Stopwatch.StartNew();
        using var gate = new SemaphoreSlim(options.MaxConcurrency, options.MaxConcurrency);

        async Task<DownloadResult> ThrottledAsync(Uri url)
        {
            try { await gate.WaitAsync(ct); }
            catch (OperationCanceledException) { return Report(DownloadResult.Cancelled(url), urls.Count); }   // never got a slot
            try { return await DownloadOneAsync(url, urls.Count, ct); }
            finally { gate.Release(); }
        }

        DownloadResult[] results = await Task.WhenAll(urls.Select(ThrottledAsync));
        return new DownloadSummary(results, sw.Elapsed);
    }

    public async Task<DownloadSummary> DownloadWithParallelAsync(IReadOnlyList<Uri> urls, CancellationToken ct = default)
    {
        Prepare();
        var sw = Stopwatch.StartNew();
        var results = new DownloadResult[urls.Count];
        // No token in ParallelOptions on purpose: every item still runs and records "cancelled",
        // so the summary is complete instead of ForEachAsync throwing away partial results
        var po = new ParallelOptions { MaxDegreeOfParallelism = options.MaxConcurrency };

        await Parallel.ForEachAsync(Enumerable.Range(0, urls.Count), po, async (i, _) =>
        {
            results[i] = await DownloadOneAsync(urls[i], urls.Count, ct);
        });
        return new DownloadSummary(results, sw.Elapsed);
    }

    private void Prepare()
    {
        Directory.CreateDirectory(options.OutputDirectory);
        Interlocked.Exchange(ref _completed, 0);
    }

    private async Task<DownloadResult> DownloadOneAsync(Uri url, int total, CancellationToken ct) =>
        Report(await DownloadWithRetryAsync(url, ct), total);

    private DownloadResult Report(DownloadResult result, int total)
    {
        int done = Interlocked.Increment(ref _completed);              // many workers finish at once
        progress?.Report(new DownloadProgress(done, total, result));
        return result;
    }

    private async Task<DownloadResult> DownloadWithRetryAsync(Uri url, CancellationToken ct)
    {
        var sw = Stopwatch.StartNew();
        string? lastError = null;
        int? lastStatus = null;
        int attempts = 0;

        while (attempts <= options.MaxRetries)
        {
            if (ct.IsCancellationRequested) return DownloadResult.Cancelled(url, sw.Elapsed, attempts);
            attempts++;

            // One token per attempt: fires on Ctrl+C (ct) OR when this attempt's time is up
            using var attemptCts = CancellationTokenSource.CreateLinkedTokenSource(ct);
            attemptCts.CancelAfter(options.PerRequestTimeout);

            try
            {
                PageContent page = await source.GetAsync(url, attemptCts.Token);
                if (page.StatusCode is >= 200 and <= 299)
                {
                    string path = Path.Combine(options.OutputDirectory, FileNames.FromUrl(url));
                    await File.WriteAllBytesAsync(path, page.Body, ct);
                    return new DownloadResult(url, DownloadStatus.Succeeded, sw.Elapsed,
                        page.StatusCode, page.Body.LongLength, path, Attempts: attempts);
                }

                lastStatus = page.StatusCode;
                lastError = $"HTTP {page.StatusCode}";
                if (!IsTransient(page.StatusCode)) break;               // 404, 403…: retrying won't help
            }
            catch (OperationCanceledException) when (ct.IsCancellationRequested)
            {
                return DownloadResult.Cancelled(url, sw.Elapsed, attempts);   // Ctrl+C
            }
            catch (OperationCanceledException)
            {
                lastError = $"timed out after {options.PerRequestTimeout.TotalSeconds:0.#} s";   // our timeout
            }
            catch (HttpRequestException ex)
            {
                lastError = ex.Message;                                  // DNS failure, connection refused/reset
            }
            catch (Exception ex) when (ex is IOException or UnauthorizedAccessException)   // a read-only folder throws the latter
            {
                lastError = $"disk error: {ex.Message}";                 // not transient: don't retry
                break;
            }

            if (attempts <= options.MaxRetries)
            {
                try { await Task.Delay(Backoff(attempts), ct); }
                catch (OperationCanceledException) { return DownloadResult.Cancelled(url, sw.Elapsed, attempts); }
            }
        }

        return new DownloadResult(url, DownloadStatus.Failed, sw.Elapsed, lastStatus, Error: lastError, Attempts: attempts);
    }

    // 408 Request Timeout, 429 Too Many Requests, and every 5xx are worth another try
    private static bool IsTransient(int statusCode) => statusCode is 408 or 429 or >= 500;

    // 500 ms, 1 s, 2 s, 4 s… plus 0–20% random jitter
    private TimeSpan Backoff(int attempt)
    {
        double ms = options.BaseRetryDelay.TotalMilliseconds * Math.Pow(2, attempt - 1);
        return TimeSpan.FromMilliseconds(ms + Random.Shared.NextDouble() * ms * 0.2);
    }
}

3. Live progress

Progress<T> captures SynchronizationContext.Current when it's created. In a WinForms app that's the UI thread, so its handler can safely update a progress bar. In a console app there is none, so every Report is posted to the thread pool: handlers can run concurrently and out of order (you might see 7/10 printed before 6/10). For console output, a tiny synchronous implementation is clearer:

Downloader.App/ConsoleProgress.cs
using Downloader.Core;

namespace Downloader.App;

/// <summary>Prints each report immediately, one at a time, in the order Report is called.</summary>
public sealed class ConsoleProgress : IProgress<DownloadProgress>
{
    private readonly object _sync = new();        // on .NET 9: private readonly Lock _sync = new();

    public void Report(DownloadProgress p)
    {
        lock (_sync)                               // workers report from many threads at once
        {
            (string mark, ConsoleColor color) = p.Last.Status switch
            {
                DownloadStatus.Succeeded => ("✓", ConsoleColor.Green),
                DownloadStatus.Failed    => ("✗", ConsoleColor.Red),
                _                        => ("–", ConsoleColor.DarkYellow)
            };
            Console.ForegroundColor = color;
            Console.Write($"  [{p.Completed,2}/{p.Total}] {mark} ");
            Console.ResetColor();
            string tries = p.Last.Attempts > 1 ? $" · {p.Last.Attempts} attempts" : "";
            string info = p.Last.Success ? $"{p.Last.Bytes:N0} bytes" : p.Last.Error ?? "";
            Console.WriteLine($"{p.Last.Url} ({p.Last.Elapsed.TotalMilliseconds:N0} ms{tries}) {info}");
        }
    }
}

BasicHow do you handle Ctrl+C gracefully in a .NET console app?
Create a CancellationTokenSource, subscribe to Console.CancelKeyPress, set e.Cancel = true so the process isn't killed, and call cts.Cancel(). Pass the token through all async work so it stops at the next await, then let the program print what finished and exit with a suitable code. Hosted apps (Generic Host) do this for you via IHostApplicationLifetime.
IntermediateWhich failures should you retry, and why use exponential backoff with jitter?
Only transient ones: network errors, timeouts, 408, 429 and 5xx — and only for idempotent operations, or ones protected by an idempotency key. Backoff gives an overloaded server time to recover instead of hammering it; jitter spreads retries from many clients so they don't all hit the server at the same instant (thundering herd). Always cap the number of attempts.
IntermediateHow does the downloader tell a per-request timeout from a user cancellation?
Each attempt uses a CTS linked to the user's token with CancelAfter(timeout). When OperationCanceledException is thrown, an exception filter checks the user's token: if it's cancelled, the user pressed Ctrl+C and the item is marked cancelled; otherwise the attempt timed out, which is treated as transient and retried.
IntermediateWhat's the difference between Progress<T> and a custom IProgress<T> in a console app?
Progress<T> posts each Report to the SynchronizationContext captured at construction. In UI apps that marshals to the UI thread, which is what you want. Console apps have no context, so handlers are queued to the thread pool and can run concurrently or out of order. A custom IProgress<T> that runs the handler synchronously under a lock prints each report immediately and never interleaves lines (counter numbers can still, rarely, appear one out of order, because two workers may increment before either takes the lock).
