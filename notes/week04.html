DAY 1 · MON

List<T>, Dictionary<TKey,TValue> and HashSet<T>

GoalUse the three collections you'll write every day, know their costs, and pick the right one for lookups, ordering and uniqueness.

Key definitions

Collection
An object that stores and manages a group of items.
Generic collection
A collection typed by a parameter, e.g. List<Order>, giving type safety with no boxing.
List<T>
An ordered, index-accessible, resizable array.
Capacity
The size of a List's internal array; it doubles when full. Count is how many items are actually stored.
Dictionary<TKey,TValue>
A hash table mapping unique keys to values with near-constant-time lookup.
KeyValuePair<TKey,TValue>
The element type you get when iterating a dictionary.
HashSet<T>
An unordered collection of unique items with fast Contains, plus set operations.
Hash table
Structure that uses an item's hash code to jump straight to a bucket instead of scanning.
Bucket
A slot in a hash table holding items whose hash codes map to it.
Collision
Two different items landing in the same bucket; resolved by comparing with Equals.
Big-O
Notation for how cost grows with size: O(1) constant, O(n) linear, O(log n) logarithmic.
Comparer
An object that defines equality or order, e.g. StringComparer.OrdinalIgnoreCase.
Quick notes
  • List = ordered and indexed; Dictionary = lookup by key; HashSet = uniqueness and membership.
  • list.Contains is O(n); set.Contains and dict.ContainsKey are O(1) on average.
  • Use TryGetValue instead of ContainsKey + indexer (one lookup instead of two).
  • The dictionary indexer throws on a missing key when reading, but adds or overwrites when writing.
  • Pass StringComparer.OrdinalIgnoreCase for case-insensitive string keys.
  • Don't add or remove items while looping over a collection with foreach.

2. List<T>

ListDemo.cs
var cart = new List<string> { "Pen", "Notebook" };
List<string> tags = ["dotnet", "csharp"];          // collection expression (C# 12)

cart.Add("Stapler");                    // end:    O(1) amortised
cart.Insert(0, "Bag");                  // front:  O(n) — shifts everything

cart.RemoveAt(0);

Console.WriteLine(cart.Count);          // 3
Console.WriteLine(cart[1]);             // Notebook — O(1) by index

string? found = cart.Find(i => i.Length > 5);       // first match or null
List<string> longOnes = cart.FindAll(i => i.Length > 3);

// Group orders by customer: Dictionary<string, List<T>>
var ordersByCustomer = new Dictionary<string, List<int>>();

{
    if (!ordersByCustomer.TryGetValue(customer, out var list))
    {
        list = [];
        ordersByCustomer[customer] = list;
    }
    list.Add(orderId);
}

5. How hashing makes lookups fast

  1. GetHashCode() turns the key into an int.
  2. The int picks a bucket (roughly hash % bucketCount).
  3. Only items in that bucket are compared with Equals.
  4. With a good hash, buckets hold about one item, so lookup is O(1) regardless of size.

This is why last week's Equals/GetHashCode rules matter: a bad or mutable hash code breaks Dictionary and HashSet.

Common mistakes

Self-check questions

What does the dictionary indexer do on a missing key?Reading throws KeyNotFoundException; assigning adds the key.
Why is HashSet.Contains faster than List.Contains?HashSet uses hashing to go straight to one bucket (O(1) average); List compares every element until it finds a match (O(n)).

BasicWhat is the difference between an array and a List<T>?
An array has a fixed length set at creation. List<T> wraps an array and resizes it automatically, adding methods like Add, Remove, Insert and Find. Both give O(1) index access.
BasicHow does a Dictionary work internally?
It's a hash table: the key's GetHashCode selects a bucket, and Equals resolves collisions within it. With well-distributed hashes, add, lookup and remove are O(1) on average.
BasicWhen would you use a HashSet?
When you need uniqueness or fast membership tests: deduplicating, tracking visited items, checking permissions, or set operations like union and intersection.
IntermediateWhy prefer TryGetValue over ContainsKey + indexer?
It does one hash lookup instead of two and avoids the race in concurrent scenarios where the key could be removed between the two calls.
IntermediateWhat is the time complexity of List.Insert(0, x) and why?
O(n): every existing element must shift one position right in the underlying array. Prefer adding at the end, or use LinkedList/Queue/Deque-like structures when you need fast front insertion.
IntermediateHow do you make a Dictionary with case-insensitive string keys?
Pass a comparer to the constructor: new Dictionary<string, T>(StringComparer.OrdinalIgnoreCase). The comparer supplies both GetHashCode and Equals for keys.
DAY 2 · TUE

Queue, Stack, LinkedList, SortedDictionary and choosing the right collection

GoalRecognise FIFO, LIFO, priority and sorted problems, and reach for the matching collection instead of forcing everything into a List.

Key definitions

Queue<T>
First-in, first-out (FIFO) collection: Enqueue at the back, Dequeue from the front.
Stack<T>
Last-in, first-out (LIFO) collection: Push on top, Pop from the top.
PriorityQueue<TElement,TPriority>
.NET 6+ queue that always dequeues the item with the lowest priority value.
Peek
Look at the next item without removing it.
LinkedList<T>
Doubly linked list of nodes; O(1) insert/remove when you hold the node, no index access.
LinkedListNode<T>
A node with Value, Next and Previous.
SortedDictionary<K,V>
Key-value pairs kept sorted by key, backed by a red-black tree (O(log n)).
SortedList<K,V>
Sorted key-value pairs in two arrays; less memory, slower inserts, index access.
SortedSet<T>
Unique items kept in sorted order, with range queries like GetViewBetween.
Deque
Double-ended queue (add/remove at both ends); .NET has no built-in one, LinkedList can serve.
FIFO / LIFO
Processing order: first in first out (queues) vs last in first out (stacks).
Quick notes
  • Queue for jobs processed in arrival order; Stack for undo, backtracking and nested structures.
  • PriorityQueue when "most urgent first" matters more than arrival order.
  • Use the Try* methods (TryDequeue, TryPop, TryPeek) to avoid exceptions on empty collections.
  • LinkedList only wins when you keep node references and insert/remove in the middle often.
  • Need sorted keys? SortedDictionary for frequent inserts, SortedList for mostly-read data.
  • When unsure, start with List or Dictionary and change only if profiling shows a need.

2. PriorityQueue — most urgent first

Triage.cs
// Lower priority number = served first
var triage = new PriorityQueue<string, int>();
triage.Enqueue("Sprained ankle", 3);
triage.Enqueue("Chest pain", 1);
triage.Enqueue("Fever", 2);
triage.Enqueue("Cardiac arrest", 0);

while (triage.TryDequeue(out string? patient, out int priority))
    Console.WriteLine($"P{priority}: {patient}");
// P0: Cardiac arrest
// P1: Chest pain
// P2: Fever
// P3: Sprained ankle
Note. PriorityQueue is not stable: two items with the same priority may come out in any order. Add a tie-breaker (e.g. a tuple priority (severity, arrivalNumber)) if order matters.

3. Stack<T> — last in, first out

StackDemo.cs
// Undo for a text editor
var history = new Stack<string>();
string doc = "";

void Type(string text) { history.Push(doc); doc += text; }
void Undo() { if (history.TryPop(out var previous)) doc = previous; }

Type(", world");
Type("!!!");

Console.WriteLine(doc);     // Hello, world

// Bracket matching — classic interview problem
static bool IsBalanced(string s)
{
    var open = new Stack<char>();
    foreach (char c in s)
    {
        if (c is '(' or '[' or '{') { open.Push(c); continue; }
        if (c is ')' or ']' or '}')
        {
            if (!open.TryPop(out char top)) return false;
            if ((top, c) is not (('(', ')') or ('[', ']') or ('{', '}'))) return false;
        }
    }
    return open.Count == 0;
}

Console.WriteLine(IsBalanced("var x = list[(a + b)];"));   // True
Console.WriteLine(IsBalanced("if (x > 0] {"));             // False

What does Peek do?Returns the next item (front of a queue, top of a stack) without removing it; throws if empty, so prefer TryPeek.

Interview questions

Answer out loud first, then open each one to compare.

BasicWhat is the difference between a Queue and a Stack?
A Queue is FIFO: the first item added is the first removed (Enqueue/Dequeue). A Stack is LIFO: the last item added is the first removed (Push/Pop). Queues model waiting lines; stacks model undo history and nested calls.
BasicGive real-world uses for Stack<T>.
Undo/redo, browser back navigation, matching brackets or HTML tags, depth-first search, evaluating expressions, and the call stack itself.
BasicWhat is a PriorityQueue and how is it implemented?
A queue that dequeues by priority rather than arrival order. .NET's PriorityQueue is an array-backed min-heap (quaternary heap) with O(log n) enqueue/dequeue.
IntermediateSortedDictionary vs SortedList vs Dictionary?
Dictionary: unordered, O(1) average. SortedDictionary: red-black tree, sorted, O(log n) insert/lookup. SortedList: sorted arrays, O(log n) lookup but O(n) insert, less memory and index access. Pick by insert frequency and whether you need order.
IntermediateHow would you design an LRU cache in C#?
Combine Dictionary<K, LinkedListNode<(K, V)>> for O(1) lookup with a LinkedList ordered by recent use. On get, move the node to the front; on put, add to the front and, if over capacity, remove the last node and its dictionary entry.
IntermediateWhy can List outperform LinkedList even for some inserts?
List stores elements contiguously, so it's CPU-cache friendly and memory-light. LinkedList allocates a node per item scattered around the heap, causing cache misses and GC pressure; finding the insertion point is O(n) anyway unless you hold the node.
DAY 3 · WED

Generics: classes, methods and constraints

GoalWrite your own reusable, type-safe generic types and methods, and restrict type parameters with constraints so the compiler can help you.

Key definitions

Generics
Writing types and methods with type parameters, filled in by the caller: List<T>.
Type parameter
The placeholder, conventionally T, TKey, TResult.
Type argument
The real type supplied: in List<Order>, Order is the type argument.
Open vs closed type
List<T> is open; List<int> is closed (all arguments supplied).
Generic method
A method with its own type parameters: T Max<T>(T a, T b).
Type inference
The compiler working out type arguments from the method arguments.
Constraint
A where clause limiting what types are allowed and unlocking their members.
default(T)
The default value of T: null for references, zero for value types.
Reification
In .NET, generic types exist at runtime with their real type arguments (unlike Java's erasure).
Covariance (out)
Allows IEnumerable<Derived> to be used as IEnumerable<Base>.
Contravariance (in)
Allows IComparer<Base> to be used as IComparer<Derived>.
Invariance
Neither: List<Derived> is not a List<Base>.
Quick notes
  • Generics give you reuse without giving up type safety or performance.
  • Without constraints you can only use members of object on T.
  • Add the minimum constraints needed; each one narrows who can use your code.
  • Static fields are per closed type: Cache<int> and Cache<string> don't share them.
  • Generic methods usually don't need explicit type arguments; inference handles it.
  • List<Derived> isn't List<Base>, but IEnumerable<Derived> is IEnumerable<Base>.

1. The problem generics solve

// Without generics: one class per type, or `object` and casting
public class IntBox    { public int Value { get; set; } }
public class StringBox { public string Value { get; set; } = ""; }
public class ObjectBox { public object? Value { get; set; } }   // boxing + casts + runtime errors

// With generics: one definition, any type, fully typed
public class Box<T>
{
    public T Value { get; set; }
    public Box(T value) => Value = value;
}

var price = new Box<decimal>(499m);
decimal p = price.Value;          // no cast, no boxing
var name = new Box<string>("Pen");

3. Generic methods and inference

Util.cs
public static class Util
{
    public static void Swap<T>(ref T a, ref T b) => (a, b) = (b, a);

    public static T FirstOr<T>(IEnumerable<T> items, T fallback)
    {
        foreach (var item in items) return item;
        return fallback;
    }

    public static Dictionary<TKey, List<T>> GroupBy<T, TKey>(IEnumerable<T> items, Func<T, TKey> keyOf)
        where TKey : notnull
    {
        var groups = new Dictionary<TKey, List<T>>();
        foreach (var item in items)
        {
            var key = keyOf(item);
            if (!groups.TryGetValue(key, out var list)) groups[key] = list = [];
            list.Add(item);
        }
        return groups;
    }
}

4. Constraints

Without constraints, T could be anything, so the compiler only lets you use object members. Constraints promise more, unlocking more.

// ❌ Won't compile: the compiler doesn't know T can be compared

static T Max<T>(T a, T b) where T : IComparable<T> => a.CompareTo(b) >= 0 ? a : b;

5. Iterator pitfalls

// ❌ Validation is deferred: no exception until someone iterates
static IEnumerable<int> Range(int start, int count)
{
    if (count < 0) throw new ArgumentOutOfRangeException(nameof(count));
    for (int i = 0; i < count; i++) yield return start + i;
}
var r = Range(1, -5);        // no error here!
// foreach (var i in r) {}   // error only now, far from the cause

// ✓ Split: eager validation + private lazy iterator
static IEnumerable<int> SafeRange(int start, int count)
{
    ArgumentOutOfRangeException.ThrowIfNegative(count);   // runs immediately
    return Iterate();

    IEnumerable<int> Iterate()
    {
        for (int i = 0; i < count; i++) yield return start + i;
    }
}

// ❌ Multiple enumeration repeats the work

1. IComparable<T> — natural order

public record Version(int Major, int Minor, int Patch) : IComparable<Version>
{
    public int CompareTo(Version? other)
    {
        if (other is null) return 1;
        int c = Major.CompareTo(other.Major);
        if (c != 0) return c;
        c = Minor.CompareTo(other.Minor);
        return c != 0 ? c : Patch.CompareTo(other.Patch);
    }

    public static Version Parse(string s)
    {
        var p = s.Split('.').Select(int.Parse).ToArray();
        return new(p[0], p[1], p[2]);
    }

    public override string ToString() => $"{Major}.{Minor}.{Patch}";
}

3. IEqualityComparer<T> — your own definition of "same"

GmailAddressComparer.cs
public sealed class GmailAddressComparer : IEqualityComparer<string>
{
    public bool Equals(string? x, string? y) =>
        string.Equals(Normalize(x), Normalize(y), StringComparison.Ordinal);

    public int GetHashCode(string obj) => Normalize(obj)?.GetHashCode() ?? 0;

    private static string? Normalize(string? email)
    {
        if (email is null) return null;
        var parts = email.Trim().ToLowerInvariant().Split('@');
        if (parts is not [var local, "gmail.com"]) return email.Trim().ToLowerInvariant();
        local = local.Split('+')[0].Replace(".", "");
        return $"{local}@gmail.com";
    }
}

var signups = new HashSet<string>(new GmailAddressComparer())
{
    "snayak@gmail.com",
    "s.nayak+jobs@gmail.com",     // same person → not added
    "S.Nayak@Gmail.com"           // same person → not added
};
Console.WriteLine(signups.Count);   // 1

var distinct = new[] { "a.b@gmail.com", "ab@gmail.com" }.Distinct(new GmailAddressComparer()).Count();   // 1

using Library.Core.Interfaces;

namespace Library.Core.Services;

public class InMemoryRepository<T> : IRepository<T> where T : class, IEntity
{
    private readonly Dictionary<int, T> _store = new();

    public int Count => _store.Count;

    public virtual void Add(T entity)
    {
        ArgumentNullException.ThrowIfNull(entity);
        if (!_store.TryAdd(entity.Id, entity))
            throw new InvalidOperationException($"{typeof(T).Name} with id {entity.Id} already exists");
    }

    public T? GetById(int id) => _store.GetValueOrDefault(id);

    public virtual bool Remove(int id) => _store.Remove(id);

    public IReadOnlyList<T> GetAll() => _store.Values.ToList();

    public IReadOnlyList<T> Find(Func<T, bool> predicate)
    {
        var results = new List<T>();
        foreach (var item in _store.Values)
            if (predicate(item)) results.Add(item);
        return results;
    }
}

Step 4 — LibraryService with indexed loans and reservations

Library.Core/Services/LibraryService.cs
using Library.Core.Interfaces;
using Library.Core.Models;

namespace Library.Core.Services;

public class LibraryService(ItemRepository items, MemberRepository members, IClock clock)
{
    private readonly InMemoryRepository<Loan> _loans = new();
    private readonly Dictionary<int, Loan> _openLoanByItem = new();             // itemId → open loan
    private readonly Dictionary<int, List<Loan>> _openLoansByMember = new();    // memberId → open loans
    private readonly Dictionary<int, Queue<int>> _reservations = new();         // itemId → waiting memberIds

    public IReadOnlyList<Loan> OpenLoans => _openLoanByItem.Values.ToList();
    public IReadOnlyList<Loan> Overdue => _openLoanByItem.Values.Where(l => l.DaysOverdue(clock.Today) > 0).ToList();

    public Result<Loan> Borrow(int memberId, int itemId)
    {
        if (members.GetById(memberId) is not { } member) return Result<Loan>.Fail($"No member with id {memberId}");
        if (items.GetById(itemId) is not { } item)       return Result<Loan>.Fail($"No item with id {itemId}");
        if (_openLoanByItem.ContainsKey(itemId))         return Result<Loan>.Fail($"'{item.Title}' is already on loan");

        // Reserved? Only the member at the front of the queue may take it
        if (_reservations.TryGetValue(itemId, out var queue) && queue.TryPeek(out int nextInLine) && nextInLine != memberId)
            return Result<Loan>.Fail($"'{item.Title}' is reserved for member {nextInLine}");

        var memberLoans = OpenLoansOf(memberId);
        if (memberLoans.Count >= Member.MaxLoans)
            return Result<Loan>.Fail($"{member.Name} already has {Member.MaxLoans} items out");
        if (memberLoans.Any(l => l.DaysOverdue(clock.Today) > 0))
            return Result<Loan>.Fail($"{member.Name} has an overdue item; return it first");

        var loan = new Loan(item, member, clock.Today);
        _loans.Add(loan);
        _openLoanByItem[itemId] = loan;
        memberLoans.Add(loan);
        item.IsAvailable = false;
        queue?.TryDequeue(out _);                       // their reservation is fulfilled
        return Result<Loan>.Ok(loan);
    }

    public Result<decimal> Return(int itemId)
    {
        if (!_openLoanByItem.Remove(itemId, out var loan))
            return Result<decimal>.Fail($"Item {itemId} isn't on loan");

        decimal fee = loan.Close(clock.Today);
        OpenLoansOf(loan.Member.Id).Remove(loan);
        loan.Item.IsAvailable = true;
        return Result<decimal>.Ok(fee);
    }

    public Result<int> Reserve(int memberId, int itemId)
    {
        if (members.GetById(memberId) is null) return Result<int>.Fail($"No member with id {memberId}");
        if (items.GetById(itemId) is not { } item) return Result<int>.Fail($"No item with id {itemId}");
        if (item.IsAvailable) return Result<int>.Fail($"'{item.Title}' is available — borrow it instead");

        if (!_reservations.TryGetValue(itemId, out var queue))
            _reservations[itemId] = queue = new Queue<int>();
        if (queue.Contains(memberId)) return Result<int>.Fail("You're already in the queue");

        queue.Enqueue(memberId);
        return Result<int>.Ok(queue.Count);            // position in line
    }

    public IReadOnlyList<ISearchable> Search(string term)
    {
        if (string.IsNullOrWhiteSpace(term)) return [];
        var hits = new List<ISearchable>();
        hits.AddRange(items.Find(i => i.Matches(term)));
        hits.AddRange(members.Find(m => m.Matches(term)));
        return hits;
    }

    private List<Loan> OpenLoansOf(int memberId)
    {
        if (!_openLoansByMember.TryGetValue(memberId, out var list))
            _openLoansByMember[memberId] = list = [];
        return list;
    }
}

BasicWhat is the Repository pattern?
An abstraction over data storage that exposes collection-like operations (Add, GetById, Find, Remove) for entities, so business logic doesn't depend on whether data lives in memory, SQL Server or an API.
BasicWhy constrain IRepository<T> with where T : class, IEntity?
IEntity guarantees an Id the repository can key on; class allows returning null for 'not found' (T?) and matches how entities are modelled.
IntermediateWhat are the criticisms of a generic repository over EF Core?
DbContext/DbSet is already a repository and unit of work, so a thin generic wrapper often adds little, hides useful features (Include, projections, IQueryable) and leaks abstractions. Many teams prefer specific repositories or query objects per use case.
IntermediateWhy keep secondary indexes like _openLoanByItem, and what's the risk?
They turn O(n) scans into O(1) lookups. The risk is consistency: every add/remove must update all indexes, so mutations should be centralised in one place — exactly what a database does for you with indexes and transactions.

BasicYou need to check whether 1 million order IDs were already processed. What do you use?
A HashSet<long> (or HashSet<Guid>): O(1) Contains and Add, and Add returns false for duplicates so check-and-insert is one call. For persistence across restarts, a unique index in the database.
IntermediateDesign an LRU cache with O(1) get and put.
Dictionary from key to LinkedListNode, plus a LinkedList ordered by recency. Get: look up the node, move it to the front, return the value. Put: update or add at the front; if over capacity, remove the last node and its dictionary entry. Both are O(1).
IntermediateHow would you make Money safe as a dictionary key?
Make it immutable (readonly record struct Money(decimal Amount, string Currency)), so Equals and GetHashCode are value-based and can't change after insertion. Normalise the currency code (upper case) in the constructor.
IntermediateInterface or abstract class for payment gateways?
An interface (IPaymentGateway) as the contract consumers depend on and tests mock, optionally with an abstract base class implementing the shared steps (logging, retries, validation) via Template Method for concrete gateways to inherit.
