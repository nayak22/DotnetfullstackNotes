DAY 1 · MON

Setup, the dotnet CLI and your first program

GoalBy the end you can create, build and run a console app from the terminal, understand every file it generated, and push it to GitHub.

Key definitions

SDK
Software Development Kit: compiler (Roslyn), dotnet CLI, templates and build tools needed to create apps.
Runtime
The minimum needed to run a compiled app: the CLR plus the base libraries.
CLR
Common Language Runtime: the virtual machine that loads assemblies, JIT-compiles IL, manages memory (GC), enforces type safety and handles exceptions.
IL / MSIL / CIL
Intermediate Language: CPU-independent instructions the C# compiler emits into a .dll.
JIT
Just-In-Time compiler: turns IL into native machine code the first time a method runs.
Assembly
The compiled unit of deployment (.dll or .exe) containing IL plus metadata and a manifest.
BCL
Base Class Library: the standard types every app gets (System, System.IO, System.Collections…).
NuGet
The .NET package manager and package format (.nupkg); packages come from nuget.org.
Project (.csproj)
An MSBuild file describing one buildable unit: target framework, references, packages, settings.
Solution (.sln)
A container that groups related projects so they build and open together.
Target Framework Moniker (TFM)
The framework a project builds for, e.g. net8.0, net9.0.
Top-level statements
C# 9+ feature letting Program.cs contain statements directly; the compiler generates the Main method.
Implicit usings
Global using directives (System, System.Linq, …) added automatically when <ImplicitUsings> is enabled.
Quick notes
  • C# source → Roslyn compiler → IL in an assembly → CLR + JIT → native code.
  • Install the SDK on dev machines, only the runtime on servers (or ship self-contained).
  • dotnet new creates, dotnet build compiles, dotnet run builds + runs, dotnet watch hot-reloads.
  • bin/ and obj/ are build output — always ignored by Git.
  • One solution → many projects; projects reference each other with dotnet add reference.
  • Prefer LTS releases (8, 10) for production work.

1. What .NET actually is

.NET is a free, cross-platform runtime plus a large standard library. You write C#, the compiler turns it into IL (Intermediate Language) stored in a .dll, and at run time the CLR (Common Language Runtime) compiles that IL to machine code with the JIT compiler. You will study these internals in Week 8; for now remember the pipeline.

NuGetThe package manager, like npm for .NET

4. Top-level statements vs the classic Main method

Since C# 9, Program.cs can contain statements directly. The compiler wraps them in a hidden Main method. Both versions below compile to the same thing.

Program.cs — modern
Console.WriteLine("What's your name?");
string? name = Console.ReadLine();
Console.WriteLine($"Hello, {name}! Today is {DateTime.Now:dddd}.");
Program.cs — classic (what the compiler generates)
using System;

namespace HelloDotnet;

internal class Program
{
    static void Main(string[] args)
    {
        Console.WriteLine("What's your name?");
        string? name = Console.ReadLine();
        Console.WriteLine($"Hello, {name}!");
    }
}
Tip. args still works in top-level programs. Run dotnet run -- Samrath and read it with args[0].

Self-check questions

What is the difference between the SDK and the runtime?The SDK contains the compiler, CLI and templates needed to build apps. The runtime only contains what's needed to execute already-compiled apps.
What does the compiler produce from C# code?IL (Intermediate Language) inside an assembly (.dll). The CLR's JIT compiler turns that IL into native machine code when it runs.
What does <Nullable>enable</Nullable> do?It turns on nullable reference types: the compiler warns when you might dereference null, and you mark nullable references explicitly with ? (e.g. string?).

Interview questions

Answer out loud first, then open each one to compare.

BasicWhat is .NET and how is it different from .NET Framework?
.NET Framework (4.x) is the original Windows-only implementation, now in maintenance. .NET (Core → 5, 6, 7, 8, 9…) is the open-source, cross-platform, modular successor with better performance, side-by-side installs and container support. All new development targets .NET 8+.
BasicExplain the compilation process of a C# program.
The C# compiler (Roslyn) compiles source into IL stored in an assembly with metadata. At runtime the CLR loads the assembly and the JIT compiles each method to native code on first call. Tiered compilation first produces quick code, then re-optimises hot methods. ReadyToRun/Native AOT can pre-compile to reduce startup.
BasicWhat is the CLR responsible for?
Loading assemblies, JIT compilation, garbage collection, type safety and verification, exception handling, thread management and security boundaries.
IntermediateWhat is the difference between managed and unmanaged code?
Managed code runs under the CLR, which handles memory, type safety and exceptions. Unmanaged code (C/C++, Win32 APIs) runs directly on the OS; you manage memory yourself and call it through P/Invoke or COM interop.
IntermediateFramework-dependent vs self-contained deployment?
Framework-dependent apps are small but need the matching runtime installed. Self-contained apps bundle the runtime for a specific OS/CPU (-r linux-x64 --self-contained), so they're bigger but run anywhere. Native AOT goes further, producing a single native binary.
IntermediateWhat does the .csproj contain and what is MSBuild?
MSBuild is the build engine; the .csproj is its XML input with properties (TargetFramework, Nullable, OutputType), item groups (PackageReference, ProjectReference) and targets. SDK-style projects keep it short by importing defaults from Microsoft.NET.Sdk.
DAY 2 · TUE

Variables, types, value vs reference, conversion

GoalPick the right built-in type, explain where value and reference types live in memory, and convert between types safely.

Key definitions

Variable
A named storage location with a fixed type.
Value type
A type whose variable holds the data itself; assignment copies the data. Structs, enums and primitives like int, double, bool.
Reference type
A type whose variable holds a reference to an object on the managed heap; assignment copies the reference. Classes, string, arrays, delegates, records (class).
Stack
Fast LIFO memory for method calls and their local value-type variables; freed automatically when the method returns.
Managed heap
Memory where reference-type objects live, managed by the garbage collector.
var
Implicitly typed local; the compiler infers a fixed type from the initializer. Still strongly typed.
const
Compile-time constant baked into the IL; must be a primitive or string.
readonly
A field that can be assigned only at declaration or in the constructor; evaluated at runtime.
Implicit conversion
Automatic, lossless conversion (int → long).
Explicit conversion (cast)
Conversion that may lose data and must be written out: (int)9.7.
Boxing
Wrapping a value type in an object on the heap so it can be treated as object.
Unboxing
Extracting the value type back out of a boxed object with an explicit cast to the exact type.
Default value
What an unassigned field holds: 0, false, '\0', or null for references.
Quick notes
  • Value types copy data; reference types copy the reference — the core idea for the whole course.
  • Use decimal for money, double for measurements, int/long for counts.
  • TryParse for user input; Parse only when bad input is truly exceptional.
  • const = compile time, readonly = set once at runtime.
  • Integer overflow wraps silently unless you use checked.
  • Boxing allocates on the heap — avoid it in loops; generics prevent it.

// var still requires an initializer and the type never changes:
var count = 10;
// count = "ten";          // ❌ compile error: cannot convert string to int

3. Value types vs reference types

This is the single most-asked C# fundamentals interview question.

  • Value types (int, double, bool, char, struct, enum) hold the data itself. Assigning copies the data.
  • Reference types (class, string, arrays, object, delegates) hold a reference to an object on the managed heap. Assigning copies the reference, so both variables point to the same object.
ValueVsReference.cs
// Value type: copy of the data
int a = 10;
int b = a;
b = 20;
Console.WriteLine(a); // 10 — a is untouched

// Reference type: copy of the reference
var p1 = new Point { X = 1 };
var p2 = p1;          // both point to the SAME object
p2.X = 99;
Console.WriteLine(p1.X); // 99 — changed through p2

// Struct is a value type even though it looks like a class
var s1 = new PointStruct { X = 1 };
var s2 = s1;          // full copy
s2.X = 99;
Console.WriteLine(s1.X); // 1

class Point { public int X; }
struct PointStruct { public int X; }
Precise wording. "Value types live on the stack" is only partly true. Local value-type variables usually live on the stack, but a value-type field inside a class lives on the heap with that object. Say: "value types are copied by value; reference types are copied by reference."

string is a special reference type

string s1 = "hello";
string s2 = s1;
s2 = "world";            // creates a NEW string; s1 still "hello"
Console.WriteLine(s1);   // hello — strings are immutable, so they behave like values
Console.WriteLine("ab" == "a" + "b"); // True — == compares content for strings

4. Type conversion

// Implicit: safe, no data loss
int i = 42;
long l = i;
double d = i;

// Explicit cast: possible data loss
double price = 9.99;
int whole = (int)price;           // 9 (truncates, doesn't round)

// Parse: throws FormatException on bad input
int n1 = int.Parse("123");

// TryParse: the safe way for user input
if (int.TryParse(Console.ReadLine(), out int n2))
    Console.WriteLine($"You typed {n2}");
else
    Console.WriteLine("Not a number");

// Convert class: handles null (returns 0) and rounds
int r = Convert.ToInt32(9.6);     // 10 (banker's rounding: 2.5 → 2)

// Culture matters for decimals: "1,5" vs "1.5"
using System.Globalization;
double x = double.Parse("1.5", CultureInfo.InvariantCulture);

5. Boxing and unboxing (preview)

int v = 5;
object o = v;      // boxing: value copied into a new heap object
int back = (int)o; // unboxing: must cast to the exact type
// long bad = (long)o; // ❌ InvalidCastException

Boxing allocates memory, so avoid it in hot loops. Generic collections (List<int>) exist largely to avoid it.

Common mistakes

  • Using int.Parse on user input — prefer TryParse.
  • Expecting (int)9.99 to round — it truncates.
  • Assuming changing a copied class variable won't affect the original.

Self-check questions

Why is string a reference type but behaves like a value type?It's immutable. Any "change" creates a new string object, so other variables referencing the old one are never affected. == is overloaded to compare content.
When would you choose a struct over a class?For small (≈16 bytes or less), immutable values that represent a single value, like a coordinate or money amount, and are created often — to avoid heap allocations.
What's the difference between Parse, TryParse and Convert?Parse throws on bad input; TryParse returns false and gives the value through out; Convert handles null (returns default) and rounds floating values.

Interview questions

Answer out loud first, then open each one to compare.

BasicWhat is the difference between value types and reference types?
Value types store their data directly and are copied on assignment; reference types store a reference to a heap object and assignment copies only the reference, so both variables see changes. Value types can't be null unless nullable (int?); reference types default to null.
Basicconst vs readonly?
const is a compile-time constant, implicitly static, restricted to primitives/strings, and its value is copied into callers' IL (changing it requires recompiling callers). readonly is set at declaration or in a constructor, can hold any type, and is evaluated at runtime.
BasicWhy use decimal instead of double for money?
double is binary floating point and can't represent many base-10 fractions exactly (0.1 + 0.2 ≠ 0.3). decimal is a 128-bit base-10 type with 28–29 significant digits, so currency arithmetic is exact. The cost is speed and range.
IntermediateIs it true that value types always live on the stack?
No. Local value-type variables usually live on the stack (or in registers), but a value-type field of a class lives on the heap inside that object, and boxed values and array elements of value types are on the heap too. The real distinction is copy semantics, not location.
IntermediateWhat is boxing and why is it a performance concern?
Boxing allocates a heap object and copies the value into it when a value type is converted to object or an interface. It creates GC pressure and costs CPU, which is why non-generic ArrayList was replaced by List<T>.
IntermediateIs var dynamic typing?
No. var is resolved at compile time to one fixed type. dynamic defers type checking to runtime via the DLR. Use var when the type is obvious from the right-hand side.

Operators, if/switch, loops and switch expressions

GoalWrite branching and looping logic idiomatically, including modern switch expressions and pattern-based conditions.

Key definitions

Operator
A symbol that performs an operation on operands (+, ==, &&).
Operator precedence
The order operators are evaluated: * / % before + −, comparison before && before ||.
Short-circuit evaluation
&& and || stop evaluating as soon as the result is known.
Ternary operator
condition ? a : b — an expression that picks one of two values.
Guard clause
An early return or throw at the top of a method that removes deep nesting.
switch statement
Branches execution to a matching case block; each must end with break/return/throw.
switch expression
C# 8+ expression that maps an input to a value using pattern arms (=>).
Pattern matching
Testing a value's type, shape or range in conditions (is, relational >= 90, logical and/or/not).
Discard (_)
A placeholder meaning "any value I don't care about"; the default arm in a switch expression.
Iteration statement
A loop: for, foreach, while, do-while.
break / continue
break exits the loop; continue skips to the next iteration.
Quick notes
  • Integer division truncates: 7 / 2 == 3; make one operand double to get 3.5.
  • % gives the remainder — useful for even/odd and "every Nth item".
  • Prefer switch expressions when mapping input → output; the compiler warns on missing cases.
  • Use guard clauses instead of nested if/else pyramids.
  • for when you need the index, foreach for collections, while for unknown counts, do-while for menus.
  • Never modify a collection inside its own foreach.

4. Switch expressions and patterns (C# 8+)

Switch expressions return a value, are shorter, and the compiler warns if you miss a case. Prefer them for mapping input to output.

string Grade(int score) => score switch
{
    >= 90           => "A",
    >= 75 and < 90  => "B",
    >= 50           => "C",
    < 0 or > 100    => throw new ArgumentOutOfRangeException(nameof(score)),
    _               => "Fail"        // _ is the discard: "anything else"
};

decimal ShippingCost(string country, decimal weightKg) => (country, weightKg) switch
{
    ("IN", <= 1)  => 50m,
    ("IN", _)     => 50m + (weightKg - 1) * 20m,
    ("US", _)     => 900m,
    _             => 1500m
};

Console.WriteLine(Grade(82));               // B
Console.WriteLine(ShippingCost("IN", 3));   // 90

5. Loops

// for: when you need the index
for (int i = 1; i <= 5; i++)
    Console.Write($"{i} ");           // 1 2 3 4 5

// foreach: iterate a collection (read-only loop variable)
string[] topics = { "C#", "SQL", "Web API" };
foreach (var topic in topics)
    Console.WriteLine(topic);

// while: unknown number of repetitions
int balance = 1000;
int months = 0;
while (balance < 2000)
{
    balance = (int)(balance * 1.08);
    months++;
}

// do-while: runs at least once — perfect for menus
string? input;
do
{
    Console.Write("Type 'q' to quit: ");
    input = Console.ReadLine();
} while (input != "q");

// break and continue
for (int n = 1; n <= 20; n++)
{
    if (n % 2 == 0) continue;   // skip evens
    if (n > 11) break;          // stop entirely
    Console.Write($"{n} ");     // 1 3 5 7 9 11
}

Common mistakes

  • Integer division surprises: 5 / 2 * 2.0 is 4.0, not 5.0.
  • Off-by-one: i <= array.Length throws IndexOutOfRangeException.
  • Modifying a collection inside foreach — throws InvalidOperationException.

Self-check questions

Switch statement vs switch expression?The statement executes blocks and needs break. The expression returns a value, uses => arms, supports relational and logical patterns, and warns when not exhaustive.
What does short-circuit evaluation mean?In a && b, if a is false, b never runs. This lets you write obj != null && obj.IsActive safely.

Interview questions

Answer out loud first, then open each one to compare.

BasicWhat's the difference between == and Equals()?
For value types both compare values. For reference types == compares references by default unless overloaded (string overloads it to compare content); Equals() can be overridden to compare content. Records generate value-based equality for both.
BasicWhat is the difference between & and &&?
&& is the conditional (short-circuit) AND; the right side runs only if needed. & on bools evaluates both sides, and on integers is bitwise AND.
BasicDifference between break and continue?
break exits the innermost loop or switch; continue skips the rest of the current iteration and moves to the next.
IntermediateSwitch statement vs switch expression — when do you use each?
Use the expression when each branch produces a value: it's concise, supports relational/logical/tuple/property patterns and warns if not exhaustive. Use the statement when branches run multiple statements or side effects.
Intermediateforeach vs for — which is faster?
For arrays the JIT optimises both similarly. foreach is clearer and avoids index bugs; for gives you the index and allows modifying elements by position. Neither allows adding/removing items from a List while iterating with foreach.
IntermediateWhat patterns can a switch expression use?
Constant, type (Car c), relational (> 100), logical (and, or, not), property ({ Status: "Paid" }), positional/tuple (("IN", _)), list patterns ([1, .., 9], C# 11) and discard _.
DAY 4 · THU

Strings, interpolation, StringBuilder and arrays

GoalManipulate text efficiently, know when to switch to StringBuilder, and work with single and multi-dimensional arrays.

Key definitions

string
An immutable sequence of UTF-16 chars (System.String), a reference type.
Immutability
An object's state can't change after creation; "modifying" a string creates a new one.
String interning
The runtime keeps one shared instance of each identical string literal to save memory.
String interpolation
$"Hi {name}" — embeds expressions in a string literal with optional format specifiers.
Verbatim string
@"C:\path" — backslashes are literal; newlines allowed.
Raw string literal
C# 11 """…""" — no escaping at all; ideal for JSON, SQL and multi-line text.
Format specifier
A code after a colon that controls output: :C currency, :N2, :yyyy-MM-dd.
StringBuilder
A mutable character buffer (System.Text) for building strings in loops without repeated allocations.
StringComparison
An enum telling comparisons how to treat case and culture, e.g. OrdinalIgnoreCase.
Array
A fixed-size, zero-indexed collection of one element type; a reference type.
Jagged array
An array of arrays (int[][]) whose rows can differ in length.
Multidimensional array
A rectangular block (int[,]) with equal-length rows.
Index / Range
^1 means last element; a..b slices from a up to (not including) b.
Quick notes
  • Strings are immutable: every +, Replace or ToUpper allocates a new string.
  • Concatenating in a loop → use StringBuilder.
  • Compare with string.Equals(a, b, StringComparison.OrdinalIgnoreCase), not ToLower().
  • Validate input with string.IsNullOrWhiteSpace.
  • Arrays are fixed size and reference types — assigning copies the reference; use Clone() or ToArray() to copy.
  • Use [^1] for the last element and ranges for slices.

3. Immutability and StringBuilder

Every concatenation creates a new string. In a loop of 10,000 iterations that is 10,000 allocations. StringBuilder keeps one growable buffer.

Self-check questions

Why are strings immutable in .NET?Thread safety, safe use as dictionary keys, and string interning (identical literals share one instance). The trade-off is allocation on every modification.

Interview questions

Answer out loud first, then open each one to compare.

BasicWhy are strings immutable in C#?
Immutability makes strings thread-safe, safe as dictionary keys (hash never changes), and enables interning so identical literals share memory. The downside is that each change allocates a new string.
BasicWhen would you use StringBuilder over string?
When building a string through many appends, especially in loops or when the number of pieces is unknown. For a handful of fixed pieces, interpolation is clearer and just as fast.
BasicDifference between string and String?
None functionally: string is the C# keyword alias for System.String. Convention is string for declarations and String.Method or string.Method for static calls.
IntermediateString.Empty vs "" vs null?

It allocates two new strings and is culture-sensitive (the Turkish dotted/dotless i breaks it). Ordinal comparisons with StringComparison are faster and predictable.

Key definitions

Method
A named block of code that performs a task, optionally takes parameters and returns a value.

A method's name plus its parameter types and modifiers — not the return type.

Parameters are in the declaration; arguments are the actual values passed at the call.

The default: the method receives a copy of the variable (for references, a copy of the reference).

  • A method should do one thing; name it with a verb.

Interview questions

Answer out loud first, then open each one to compare.

BasicWhat is the difference between ref and out?
Both pass by reference. ref requires the caller to initialise the variable and the method may read or change it. out doesn't require initialisation but the method must assign it before returning; it's used to return extra values, like TryParse.
BasicWhat is method overloading?
Defining multiple methods with the same name but different parameter types, counts or order. The compiler chooses the best match at compile time. Return type alone can't distinguish overloads.
BasicWhat does the ?? operator do?
Null-coalescing: returns the left operand if it isn't null, otherwise the right operand. ??= assigns the right operand only when the left is null.
IntermediateIf you pass an object to a method without ref and the method changes a property, does the caller see it?
Yes. The reference is copied, but both copies point to the same object. If the method assigns a new object to the parameter, the caller does not see that unless the parameter is ref.
IntermediateWhat's the difference between int? and string? under nullable reference types?
int? compiles to Nullable<int>, a struct with HasValue/Value. string? is an annotation only: at runtime it's still System.String; the compiler uses it for warnings.
IntermediateWhen would you use the in modifier?
For large readonly structs passed frequently in performance-sensitive code, to avoid copying while guaranteeing the method can't modify them. For small types it gives no benefit.

namespace Toolkit.Core;

public static class Calculator
{
    public static bool TryCalculate(double a, char op, double b, out double result, out string? error)
    {
        error = null;
        result = op switch
        {
            '+' => a + b,
            '-' => a - b,
            '*' or 'x' => a * b,
            '/' when b == 0 => double.NaN,
            '/' => a / b,
            '%' when b == 0 => double.NaN,
            '%' => a % b,
            '^' => Math.Pow(a, b),
            _ => double.NaN
        };

        if (double.IsNaN(result))
        {
            error = (op is '/' or '%') && b == 0
                ? "Cannot divide by zero."
                : $"Unknown operator '{op}'. Use + - * / % ^";
            return false;
        }
        return true;
    }
}

Step 2 — Unit converter (Core)

Toolkit.Core/UnitConverter.cs
namespace Toolkit.Core;

public enum Unit { Km, Mile, Meter, Foot, Kg, Pound, Celsius, Fahrenheit, Kelvin }

public static class UnitConverter
{
    private const double KmPerMile = 1.609344;
    private const double FeetPerMeter = 3.28084;
    private const double PoundsPerKg = 2.20462;

    public static bool TryConvert(double value, Unit from, Unit to, out double result)
    {
        result = (from, to) switch
        {
            (Unit.Km, Unit.Mile)       => value / KmPerMile,
            (Unit.Mile, Unit.Km)       => value * KmPerMile,
            (Unit.Meter, Unit.Foot)    => value * FeetPerMeter,
            (Unit.Foot, Unit.Meter)    => value / FeetPerMeter,
            (Unit.Kg, Unit.Pound)      => value * PoundsPerKg,
            (Unit.Pound, Unit.Kg)      => value / PoundsPerKg,
            (Unit.Celsius, _) or (Unit.Fahrenheit, _) or (Unit.Kelvin, _)
                                       => ConvertTemperature(value, from, to),
            _                          => double.NaN
        };
        return !double.IsNaN(result);
    }

    private static double ConvertTemperature(double value, Unit from, Unit to)
    {
        // Normalise to Celsius first, then convert out — avoids 6 separate formulas
        double celsius = from switch
        {
            Unit.Celsius    => value,
            Unit.Fahrenheit => (value - 32) * 5 / 9,
            Unit.Kelvin     => value - 273.15,
            _               => double.NaN
        };
        if (celsius < -273.15) return double.NaN;   // below absolute zero

        return to switch
        {
            Unit.Celsius    => celsius,
            Unit.Fahrenheit => celsius * 9 / 5 + 32,
            Unit.Kelvin     => celsius + 273.15,
            _               => double.NaN
        };
    }
}

Step 3 — History with a fixed-size array (Core)

Toolkit.Core/History.cs
namespace Toolkit.Core;

public class History
{
    private readonly string[] _items;
    private int _count;
    private int _next;               // circular buffer index

    public History(int capacity = 10) => _items = new string[capacity];

    public void Add(string entry)
    {
        _items[_next] = $"{DateTime.Now:HH:mm:ss}  {entry}";
        _next = (_next + 1) % _items.Length;     // wrap around
        if (_count < _items.Length) _count++;
    }

    public string[] GetAll()
    {
        var result = new string[_count];
        int start = _count < _items.Length ? 0 : _next;   // oldest item
        for (int i = 0; i < _count; i++)
            result[i] = _items[(start + i) % _items.Length];
        return result;
    }
}

using System.Globalization;

namespace Toolkit.App;

internal static class ConsoleInput
{
    public static double ReadDouble(string prompt)
    {
        while (true)
        {
            Console.Write(prompt);
            string? text = Console.ReadLine();
            if (double.TryParse(text, NumberStyles.Float, CultureInfo.InvariantCulture, out double value))
                return value;
            Console.WriteLine("  ✗ Please enter a valid number (e.g. 12.5).");
        }
    }

    public static char ReadOperator(string prompt)
    {
        while (true)
        {
            Console.Write(prompt);
            string? text = Console.ReadLine()?.Trim();
            if (text is { Length: 1 } && "+-*x/%^".Contains(text[0]))
                return text[0];
            Console.WriteLine("  ✗ Use one of: + - * / % ^");
        }
    }

    public static int ReadChoice(string prompt, int min, int max)
    {
        while (true)
        {
            Console.Write(prompt);
            if (int.TryParse(Console.ReadLine(), out int n) && n >= min && n <= max)
                return n;
            Console.WriteLine($"  ✗ Choose a number from {min} to {max}.");
        }
    }
}

BasicHow do you validate numeric user input in C#?
Read the string, reject null/whitespace, use TryParse with the right NumberStyles and CultureInfo, then check range (and IsInfinity/IsNaN for doubles). Re-prompt on failure instead of throwing.
BasicWhat makes a good commit message?
A short imperative summary under ~50 chars ("Add unit converter"), optionally a blank line and a body explaining why. One logical change per commit.
IntermediateExceptions vs Try-pattern for validation — which is better?
Exceptions are for exceptional, unexpected failures and are expensive. Expected failures like bad user input should use Try-patterns or result objects; they're faster and make the control flow obvious.
IntermediateWeek 1 recap: what happens from dotnet run to your code executing?
MSBuild restores packages and compiles with Roslyn to IL in a .dll, the host (dotnet) starts the CLR, the CLR loads the assembly, finds the entry point, JIT-compiles Main and runs it, with the GC managing memory along the way.
