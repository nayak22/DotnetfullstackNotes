DAY 1 · MON

Delegates in depth: Func, Action, Predicate, variance and higher-order functions

GoalGo beyond Week 3's intro: understand what a delegate really is, use the built-in generic delegates fluently, know how method groups and variance convert, and use delegates as strategies, callbacks and function-returning functions.

Key definitions

Delegate
A type-safe object that points to one or more methods with a specific signature. The compiler turns each delegate type into a sealed class deriving from System.MulticastDelegate.
Generic delegate
A delegate type with type parameters, e.g. delegate TResult Transformer<in T, out TResult>(T input);
Func<T1…T16, TResult>
Built-in delegates for methods that return a value. The last type argument is the return type.
Action<T1…T16>
Built-in delegates for methods that return void.
Predicate<T>
A delegate bool (T obj), used by List<T>.FindAll, RemoveAll, Array.Exists.
Comparison<T>
A delegate int (T x, T y) used by List<T>.Sort and Array.Sort.
Converter<TIn,TOut>
A delegate TOut (TIn input) used by List.ConvertAll and Array.ConvertAll.
Method group
A method name without parentheses, such as int.Parse. It may stand for several overloads.
Method group conversion
The compiler turning a method group into a delegate instance by picking the overload that matches the delegate's signature.
Target / Method
Properties on every delegate: the object the method runs on (null for static methods) and the MethodInfo it calls.
Invocation list
The ordered list of methods inside a multicast delegate, returned by GetInvocationList().
Delegate variance
Return types may be more derived (covariance) and parameter types less derived (contravariance) than the delegate declares.
Callback
A delegate passed to a method so that the method can call your code back at the right moment.
Higher-order function
A function that takes a function as a parameter, returns one, or both.
Strategy (delegate style)
Swapping an algorithm by passing a different delegate instead of a different interface implementation.
Quick notes
  • Prefer Func/Action over custom delegate types unless a name adds real meaning (e.g. EventHandler).
  • Two delegate types with identical signatures are still different types: Predicate<T> doesn't convert to Func<T,bool>.
  • A method group with several overloads has no natural type, so var f = int.Parse; doesn't compile.
  • Generic variance only works for reference types: Func<string> → Func<object> works, Func<int> → Func<object> doesn't.
  • A delegate to an instance method keeps that object alive for as long as the delegate is alive.
  • Delegates are the foundation of LINQ: every Where, Select and OrderBy takes a Func.

1. What a delegate really is

When you declare a delegate type, the compiler generates a sealed class with an Invoke method that has your signature. A delegate instance stores two things: the method to call and the target object to call it on. Calling d(x) is shorthand for d.Invoke(x).

DelegateAnatomy.cs
// Statements first (top-level program), type declarations at the bottom
Transformer<decimal, decimal> gst = Pricing.AddGst;
Console.WriteLine(gst(1000m));                    // 1180.00
Console.WriteLine(gst.Invoke(500m));              // 590.00 — identical to gst(500m)

Console.WriteLine(gst.GetType().BaseType);        // System.MulticastDelegate
Console.WriteLine(gst.Method.Name);               // AddGst
Console.WriteLine(gst.Target is null);            // True — static methods have no target

var cart = new Cart();
cart.Add(1_499m);
Func<decimal> total = cart.Total;                 // instance method: the delegate remembers `cart`
cart.Add(250m);
Console.WriteLine(total());                       // 1749 — it calls Total() on the live object
Console.WriteLine(ReferenceEquals(total.Target, cart));   // True

// A custom generic delegate with variance annotations (more on `in`/`out` below)
public delegate TResult Transformer<in T, out TResult>(T input);

public static class Pricing
{
    public static decimal AddGst(decimal amount) => amount * 1.18m;
}

public class Cart
{
    private readonly List<decimal> _items = [];
    public void Add(decimal price) => _items.Add(price);
    public decimal Total() => _items.Sum();
}
Tip. In a top-level Program.cs, statements must come before any type declarations (error CS8803 otherwise). In real projects, put types in their own files.

3. Method group conversion and natural types

You rarely need a lambda that only forwards its arguments. Pass the method group and the compiler picks the overload that matches the delegate the parameter expects. Since C# 10, lambdas and method groups with a single candidate also have a natural type, so var works.

string[] rawQty = ["120", "45", "980"];
int[] qty = Array.ConvertAll(rawQty, int.Parse);        // picks int.Parse(string) — no lambda needed
List<string> cities = ["Pune", "Indore", "Kochi"];
cities.ForEach(Console.WriteLine);                       // picks Console.WriteLine(string)

// Same thing written with forwarding lambdas — works, but noisier
int[] qty2 = Array.ConvertAll(rawQty, s => int.Parse(s));

// Natural types (C# 10+)
var addGst = Pricing.AddGst;                     // Func<decimal, decimal> — only one AddGst exists
var label = (Order o) => $"#{o.Id}";             // Func<Order, string>
var log = (string msg) => Console.WriteLine(msg);// Action<string>
// var parse = int.Parse;                        // ❌ CS8917: several overloads, delegate type can't be inferred
// var square = x => x * x;                      // ❌ CS8917: parameter type unknown

Func<string, int> parse = int.Parse;             // ✓ the target type picks the overload
Note. Every method group conversion to an instance method creates a new delegate object. Inside a hot loop, create the delegate once outside the loop. (Since C# 11 the compiler caches conversions of static method groups, as it always has for non-capturing lambdas.)

4. Delegate variance

Variance answers: "can I use a delegate built for one type where another is expected?" It works in two places: when converting a method group to a delegate, and between generic delegate types whose type parameters are marked out (covariant) or in (contravariant). Func is declared Func<in T, out TResult> and Action is Action<in T>.

Variance.cs
// 1. Generic variance between delegate types
Func<UpiPayment> makeUpi = () => new UpiPayment(499m, "asha@okaxis");
Func<Payment> makeAny = makeUpi;            // ✓ covariance: something that produces UPI produces a Payment

Action<Payment> audit = p => Console.WriteLine($"Audit ₹{p.Amount:N2}");
Action<UpiPayment> auditUpi = audit;        // ✓ contravariance: anything that handles any Payment handles UPI

// 2. Method-group variance (works even for non-generic delegate types)
PaymentFactory factory = CreateCard;        // ✓ method returns CardPayment; delegate promises Payment
PaymentHandler handler = LogAnyPayment;     // ✓ method accepts Payment; delegate passes CardPayment

handler(factory() as CardPayment ?? new CardPayment(0, "0000"));   // Logged ₹1,250.00

// 3. Where variance stops
// Func<int> one = () => 1;
// Func<object> boxed = one;                // ❌ variance is reference-types only (int would need boxing)
// Factory<UpiPayment> f1 = ...;
// Factory<Payment> f2 = f1;                // ❌ Factory<T> has no `out`, so it's invariant

static CardPayment CreateCard() => new(1_250m, "4242");
static void LogAnyPayment(Payment p) => Console.WriteLine($"Logged ₹{p.Amount:N2}");

delegate Payment PaymentFactory();
delegate void PaymentHandler(CardPayment payment);
delegate T Factory<T>();                    // invariant: no in/out annotation

abstract record Payment(decimal Amount);
record UpiPayment(decimal Amount, string Vpa) : Payment(Amount);
record CardPayment(decimal Amount, string Last4) : Payment(Amount);

5. Delegates as strategies

In Week 2 you used an interface for each interchangeable behaviour. When the behaviour is a single method with no state, a delegate is lighter: no class per variant, and the strategies can live in a dictionary.

Strategies.cs
// Shipping cost strategies: weight in kg → charge in ₹
var shippingRules = new Dictionary<string, Func<decimal, decimal>>(StringComparer.OrdinalIgnoreCase)
{
    ["standard"] = kg => 40m + 15m * kg,
    ["express"]  = kg => 99m + 25m * kg,
    ["pickup"]   = _ => 0m,
};

decimal Quote(string method, decimal kg) =>
    shippingRules.TryGetValue(method, out var rule)
        ? rule(kg)
        : throw new ArgumentException($"Unknown shipping method '{method}'");

Console.WriteLine(Quote("express", 2m));     // 149
Console.WriteLine(Quote("Standard", 2m));    // 70

// A pipeline of pricing rules applied in order
var rules = new List<Func<decimal, decimal>>
{
    p => p >= 5_000m ? p * 0.90m : p,        // 10% off orders ≥ ₹5,000
    p => p - 200m,                           // festive coupon
    p => Math.Round(p * 1.18m, 2)            // GST last
};

decimal price = 6_000m;
foreach (var rule in rules) price = rule(price);
Console.WriteLine(price);                    // 6136.00

6. Callbacks and higher-order functions

A higher-order function takes or returns functions. You use them every day (Where takes a function); writing your own removes repetition such as retry loops, timing and caching.

Toolkit/Functional/Fn.cs
namespace Toolkit.Functional;

public static class Fn
{
    // Takes a function, returns a function that caches results
    public static Func<T, TResult> Memoize<T, TResult>(Func<T, TResult> f) where T : notnull
    {
        var cache = new Dictionary<T, TResult>();
        return x => cache.TryGetValue(x, out var hit) ? hit : cache[x] = f(x);
    }

    // Composition: first, then second (an extension method — Tuesday)
    public static Func<T, TOut> Then<T, TMid, TOut>(this Func<T, TMid> first, Func<TMid, TOut> second) =>
        x => second(first(x));

    // Callback: the caller decides what to do on each failed attempt
    public static T Retry<T>(Func<T> operation, int attempts, Action<int, Exception>? onRetry = null)
    {
        for (int attempt = 1; ; attempt++)
        {
            try { return operation(); }
            catch (Exception ex) when (attempt < attempts)
            {
                onRetry?.Invoke(attempt, ex);
            }
        }
    }

    public static TimeSpan Time(Action work)
    {
        var sw = System.Diagnostics.Stopwatch.StartNew();
        work();
        return sw.Elapsed;
    }
}
Program.cs
using Toolkit.Functional;

// Memoize: an expensive delivery-rate lookup by PIN code
Func<string, decimal> slowRate = pin =>
{
    Console.WriteLine($"  (looking up {pin}…)");
    return pin.StartsWith('4') ? 60m : 45m;
};
var rate = Fn.Memoize(slowRate);
Console.WriteLine(rate("411001"));    //   (looking up 411001…)  then 60
Console.WriteLine(rate("411001"));    // 60 — cached, no lookup message

// Compose
Func<decimal, decimal> withGst = p => p * 1.18m;
var finalPrice = withGst.Then(p => Math.Round(p, 0));
Console.WriteLine(finalPrice(849m));  // 1002

// Retry with a callback
int calls = 0;
string status = Fn.Retry(() =>
{
    if (++calls < 3) throw new HttpRequestException("Gateway timeout");
    return "PAID";
}, attempts: 5, onRetry: (n, ex) => Console.WriteLine($"  attempt {n} failed: {ex.Message}"));
Console.WriteLine(status);
//   attempt 1 failed: Gateway timeout
//   attempt 2 failed: Gateway timeout
// PAID

Console.WriteLine(Fn.Time(() => Thread.Sleep(50)).TotalMilliseconds >= 50);   // True
Tip. The exception filter when (attempt < attempts) lets the last failure propagate with its original stack trace — no rethrow needed.

Common mistakes

  • Writing x => Foo(x) when the method group Foo would do.
  • Expecting Predicate<T> and Func<T,bool> to be interchangeable.
  • Expecting variance to work with value types (Func<int> → Func<object>).
  • Combining (+=) variant delegates of different runtime types and getting an ArgumentException.
  • Keeping a delegate to an instance method in a static field, which keeps the whole object alive (a leak).

Self-check questions

What two things does a delegate instance store?The method to call (Method) and the object to call it on (Target, null for static methods). Multicast delegates hold an invocation list of such pairs.
Why doesn't var f = int.Parse; compile?int.Parse has several overloads, so the method group has no single natural type. Give it a target type: Func<string, int> f = int.Parse;

Interview questions

Answer out loud first, then open each one to compare.

BasicWhat is a delegate and what does the compiler generate for one?
A delegate is a type-safe reference to a method. For each delegate type the compiler generates a sealed class deriving from MulticastDelegate with an Invoke method matching the signature (plus BeginInvoke/EndInvoke, which aren't supported on .NET Core). Instances store Target and Method, and can hold several methods in an invocation list.
BasicWhen would you declare your own delegate type instead of using Func/Action?
When a name documents intent better (e.g. PriceRule), when you need ref/out/in parameters or params (Func/Action can't express them), or for events following a convention. Otherwise Func/Action are preferred for consistency.
BasicWhat is method group conversion?
Using a method name without parentheses where a delegate is expected. The compiler picks the overload matching the delegate's signature and creates the delegate, e.g. Array.ConvertAll(strings, int.Parse).
IntermediateExplain covariance and contravariance for delegates.
Covariance (out) lets a delegate returning a more derived type be used where a less derived return is expected: Func<UpiPayment> as Func<Payment>. Contravariance (in) lets a delegate accepting a base type be used where a derived parameter is passed: Action<Payment> as Action<UpiPayment>. It only applies to reference types, and only for type parameters marked in/out.
IntermediateDelegate or interface for a strategy — how do you decide?
Use a delegate for small, stateless, single-method behaviour chosen at runtime (pricing rules, sort keys). Use an interface when the behaviour has several related methods, needs dependencies through DI, should be named and discoverable, or is mocked in tests as a unit.
IntermediateWhat is a higher-order function? Give a real example.
A function that takes and/or returns functions. Examples: LINQ's Where (takes a predicate), a Retry helper that takes the operation plus an onRetry callback, or Memoize that takes a function and returns a caching version of it.
DAY 2 · TUE

Lambdas, closures, local functions and extension methods

GoalWrite lambdas in all their forms, understand exactly what a closure captures (and the classic loop bug), choose between lambdas and local functions, and add your own extension methods and fluent APIs.

Key definitions

Lambda expression
An anonymous function written inline: (a, b) => a + b. Converts to a delegate or an expression tree.
Expression lambda
A lambda whose body is a single expression: o => o.Amount > 1000.
Statement lambda
A lambda with a block body { … } and explicit return.
Natural type
Since C# 10, a lambda whose parameter types are known (explicitly typed, or no parameters) has a default delegate type, so var works.
Closure
A lambda (or local function) together with the outer variables it uses.
Captured variable
An outer local or parameter used inside a lambda. The lambda captures the variable, not a copy of its value.
Display class
The hidden class the compiler generates to hold captured variables as fields.
Loop-closure gotcha
All lambdas created in a for loop share the one loop variable, so they see its final value.
Static lambda
C# 9 static x => …: a lambda that is forbidden from capturing locals or this.
Discard parameters
C# 9 (_, _) => 0: parameters you don't use.
Local function
A named method declared inside another method; can be generic, recursive and static.
Extension method
A static method whose first parameter has this, callable as if it were an instance method.
Fluent API
An API whose methods return an object you can keep calling on: builder.A().B().C().
Lambda default parameters
C# 12: (decimal amt, decimal rate = 0.18m) => …
Quick notes
  • Closures capture variables, not values: later changes are visible to the lambda.
  • for shares one loop variable across iterations; foreach (since C# 5) gives a fresh one each time.
  • Mark lambdas static when they shouldn't capture: it documents intent and avoids hidden allocations.
  • Prefer local functions for named helpers inside a method; use lambdas when you need a delegate value.
  • Extension methods need their namespace imported, and a real instance method with the same signature always wins.
  • Every LINQ operator is an extension method on IEnumerable<T> — tomorrow will feel familiar.

1. Lambda syntax, all forms

Func<decimal, decimal> gst = p => p * 1.18m;                       // expression lambda, inferred type
Func<int, int, int> add = (a, b) => a + b;                          // two parameters need parentheses
Func<DateOnly> today = () => DateOnly.FromDateTime(DateTime.Today); // no parameters
Func<string, bool> isPin = (string s) => s.Length == 6;             // explicit parameter type

Func<decimal, string> slab = income =>                              // statement lambda
{
    if (income <= 300_000m) return "Nil";
    if (income <= 700_000m) return "5%";
    return "Higher slab";
};

Func<int, int, int> first = (a, _) => a;                            // discard (C# 9)

// C# 10: natural types and explicit return types
var greet = (string name) => $"Namaste, {name}";                    // Func<string, string>
var pick = object (bool b) => b ? 1 : "one";                        // explicit return type

// C# 12: default parameter values
var withGst = (decimal amount, decimal rate = 0.18m) => amount * (1 + rate);
Console.WriteLine(withGst(1000m));          // 1180.00
Console.WriteLine(withGst(1000m, 0.05m));   // 1050.00

withGst has a default parameter, which Func can't express, so its natural type is a compiler-generated delegate type rather than Func<decimal, decimal, decimal>.

2. Closures: capturing variables

Closures.cs
decimal rate = 0.18m;
Func<decimal, decimal> tax = amount => amount * rate;   // captures the variable `rate`
Console.WriteLine(tax(100m));   // 18.00
rate = 0.05m;
Console.WriteLine(tax(100m));   // 5.00 — the lambda sees the new value

// A captured variable outlives the method that declared it
Func<string> MakeTokenGenerator(string prefix)
{
    int next = 0;                                // lives on inside the closure
    return () => $"{prefix}-{++next:D4}";
}

var counterA = MakeTokenGenerator("A");
var counterB = MakeTokenGenerator("B");
Console.WriteLine(counterA());   // A-0001
Console.WriteLine(counterA());   // A-0002
Console.WriteLine(counterB());   // B-0001 — each call to MakeTokenGenerator gets its own `next`

What the compiler does, roughly: it moves captured locals into fields of a hidden class and turns the lambda into a method on that class.

// Simplified view of the generated code for MakeTokenGenerator
private sealed class DisplayClass
{
    public string prefix = "";
    public int next;
    public string Lambda() => $"{prefix}-{++next:D4}";
}
// MakeTokenGenerator now does: var d = new DisplayClass { prefix = prefix }; return d.Lambda;

Two consequences: (1) a capturing lambda costs an allocation for the display class plus the delegate; (2) everything captured stays alive as long as the delegate does.

3. The loop-closure gotcha

LoopClosure.cs
var printers = new List<Action>();
for (int i = 0; i < 3; i++)
    printers.Add(() => Console.Write($"{i} "));
printers.ForEach(p => p());              // 3 3 3  — ONE shared i, read when the lambda runs

printers.Clear();
for (int i = 0; i < 3; i++)
{
    int copy = i;                        // a new variable per iteration
    printers.Add(() => Console.Write($"{copy} "));
}
printers.ForEach(p => p());              // 0 1 2

printers.Clear();
foreach (int n in new[] { 0, 1, 2 })     // C# 5+: foreach variable is fresh each iteration
    printers.Add(() => Console.Write($"{n} "));
printers.ForEach(p => p());              // 0 1 2
Real-world. The same bug appears with Task.Run(() => Send(invoices[i])) inside a for loop: tasks start later, by which time i may equal invoices.Length → IndexOutOfRangeException. Copy to a local or use foreach.

4. Static lambdas and avoiding hidden captures

const decimal GstRate = 0.18m;
decimal festiveDiscount = 0.10m;

Func<decimal, decimal> a = static p => p * (1 + GstRate);          // ✓ constants are fine
// Func<decimal, decimal> b = static p => p * (1 - festiveDiscount); // ❌ CS8820: can't capture 'festiveDiscount'

// Pass the state in instead of capturing it
Func<decimal, decimal, decimal> c = static (p, discount) => p * (1 - discount);
Console.WriteLine(c(1000m, festiveDiscount));   // 900.00

A non-capturing lambda is created once and cached by the compiler; a capturing one allocates every time the enclosing code runs. static turns accidental captures (including a hidden this) into compile errors — useful in hot paths and in library code.

5. Local functions vs lambdas

GoalUse the everyday LINQ operators confidently, know which ones throw on empty input, and understand exactly when a query runs.

6. Deferred vs immediate execution

Most operators return an object describing the query. Nothing runs until something enumerates it. This is the yield return behaviour you saw last Thursday.

Deferred.cs
var numbers = new List<int> { 1, 2, 3 };

var evens = numbers.Where(n =>
{
    Console.Write($"[check {n}]");
    return n % 2 == 0;
});
Console.WriteLine("query built");     // nothing checked yet
numbers.Add(4);                       // the query will see this!

foreach (var e in evens) Console.Write($" →{e} ");
// query built
// [check 1][check 2] →2 [check 3][check 4] →4

var cached = evens.ToList();          // run once, store results; later reads are free

Where, Select, SelectMany, OfType, CastToList, ToArray, ToDictionary, ToHashSet, ToLookup

OrderBy and GroupBy are deferred, but when they do run they read the whole source before yielding anything (buffering). Where and Select stream one item at a time.

  • Calling Count() > 0 instead of Any().
  • Enumerating the same expensive query several times (in a loop condition, then a foreach, then Count).
  • Expecting FirstOrDefault on an int sequence to return null.

BasicWhat does GroupBy return?
A sequence of IGrouping<TKey, TElement>. Each grouping has a Key and is itself an IEnumerable of the elements with that key. It is deferred, and groups appear in order of first key appearance.
BasicWhat is the difference between Select and SelectMany?
Select maps each element to exactly one result, so mapping to a collection gives a sequence of collections. SelectMany maps each element to a sequence and flattens the results into one sequence.
BasicUnion vs Concat?
Concat appends one sequence to another and keeps duplicates. Union returns the distinct elements of both, using the default (or supplied) equality comparer.
IntermediateHow do you write a left outer join in LINQ?
GroupJoin the outer to the inner sequence, then SelectMany over each group with DefaultIfEmpty() so an empty group yields one null, and handle the null in the result selector. In query syntax: join … into g from x in g.DefaultIfEmpty(). .NET 10 also offers a built-in LeftJoin.
IntermediateToDictionary vs ToLookup?
ToDictionary maps each key to one value, is mutable and throws on duplicate keys. ToLookup maps each key to a sequence, is immutable, allows duplicates and returns an empty sequence for missing keys.
IntermediateHow does LINQ's Join perform?
It builds a hash-based lookup of the inner sequence by key, then streams the outer sequence probing that lookup: about O(n + m), much better than nested loops' O(n × m). The inner sequence is fully buffered.
DAY 5 · FRI

Query syntax, IEnumerable vs IQueryable, expression trees and LINQ performance

GoalRead and write query syntax, know exactly how it maps to method calls, understand why EF Core needs IQueryable and expression trees, and avoid the common LINQ performance traps.

Key definitions

Query syntax
SQL-like LINQ form: from … where … select …. The compiler translates it into method calls.
Method syntax
Calling the extension methods directly: orders.Where(…).Select(…).
Range variable
The variable introduced by from o in orders; it refers to the current element.
let
Introduces a computed variable inside a query, usable in later clauses.
into
Continues a query after group, select or join under a new name.
Transparent identifier
Compiler-generated anonymous type carrying several range variables through a translated query (from let/multiple from).
IQueryable<T>
A query against a provider (EF Core, OData). Holds an Expression and a Provider that translates and executes it.
Expression tree
Code represented as data: a tree of Expression nodes that can be inspected, translated (to SQL) or compiled.
Expression<Func<…>>
The type that makes the compiler build an expression tree from a lambda instead of a delegate.
Query provider
The component (e.g. EF Core) that turns an expression tree into something executable such as SQL.
AsEnumerable / AsQueryable
Switch a query between LINQ to Objects (in-memory) and provider-based execution.
Multiple enumeration
Running the same deferred query more than once, repeating its work (or its database round trip).
Quick notes
  • Query and method syntax compile to the same thing; pick whichever reads better.
  • Query syntax shines with joins, let and multiple from; method syntax is needed for Take, Count, First, Distinct, MinBy…
  • IEnumerable methods take Func (code). IQueryable methods take Expression<Func> (data).
  • Passing a Func to an EF query silently switches to in-memory filtering after loading all rows.
  • Materialise once (ToList) when you'll enumerate more than once.
  • Measure before optimising: LINQ is fast enough for most code; avoid it only in proven hot paths.

4. Expression trees: Func vs Expression<Func>

The same lambda can become two very different things depending on the target type. As a Func it is compiled IL you can only run. As an Expression<Func> the compiler builds a tree of objects describing the code, which a library can walk and translate — for example into SQL.

Step 4 — CSV parser with line-level errors

GradeAnalyzer.Core/Parsing/CsvStudentParser.cs
using GradeAnalyzer.Core.Models;

namespace GradeAnalyzer.Core.Parsing;

public sealed record ParseError(int LineNumber, string Line, string Reason);

public sealed record ParseResult(
    IReadOnlyList<Student> Students,
    IReadOnlyList<string> Subjects,
    IReadOnlyList<ParseError> Errors);

public static class CsvStudentParser
{
    private static readonly string[] FixedColumns = ["RollNo", "Name", "Class", "Section"];

    public static ParseResult ParseFile(string path) => Parse(File.ReadLines(path));

    public static ParseResult Parse(IEnumerable<string> lines)
    {
        // Keep original line numbers for error messages, then drop blank lines
        var numbered = lines
            .Select((text, index) => (Number: index + 1, Text: text.Trim()))
            .Where(l => l.Text.Length > 0)
            .ToList();

        if (numbered.Count == 0)
            throw new FormatException("The file is empty.");

        string[] header = numbered[0].Text.Split(',', StringSplitOptions.TrimEntries);
        bool headerOk = header.Length > FixedColumns.Length &&
                        header.Take(FixedColumns.Length).SequenceEqual(FixedColumns, StringComparer.OrdinalIgnoreCase);
        if (!headerOk)
            throw new FormatException($"Header must start with {string.Join(",", FixedColumns)} followed by at least one subject.");

        string[] subjects = header[FixedColumns.Length..];
        if (subjects.Distinct(StringComparer.OrdinalIgnoreCase).Count() != subjects.Length)
            throw new FormatException("Each subject column must appear only once.");

        var students = new List<Student>();
        var errors = new List<ParseError>();
        var seenRollNos = new HashSet<int>();

        foreach (var (number, text) in numbered.Skip(1))
        {
            string? problem = TryParseRow(text, subjects, out Student? student);

            if (problem is not null)
                errors.Add(new ParseError(number, text, problem));
            else if (!seenRollNos.Add(student!.RollNo))
                errors.Add(new ParseError(number, text, $"Duplicate roll number {student.RollNo}"));
            else
                students.Add(student);
        }

        return new ParseResult(students, subjects, errors);
    }

    // Returns null on success, or a reason the row was rejected
    private static string? TryParseRow(string text, string[] subjects, out Student? student)
    {
        student = null;
        string[] cells = text.Split(',', StringSplitOptions.TrimEntries);

        int expected = FixedColumns.Length + subjects.Length;
        if (cells.Length != expected)
            return $"Expected {expected} columns, found {cells.Length}";

        if (!int.TryParse(cells[0], out int rollNo) || rollNo <= 0)
            return $"Invalid roll number '{cells[0]}'";
        if (cells[1].Length == 0)
            return "Name is empty";
        if (cells[2].Length == 0 || cells[3].Length == 0)
            return "Class or section is empty";

        var marks = new List<Mark>(subjects.Length);
        for (int i = 0; i < subjects.Length; i++)
        {
            string raw = cells[FixedColumns.Length + i];
            if (!int.TryParse(raw, out int score))
                return $"{subjects[i]}: '{raw}' is not a number";
            if (score is < 0 or > Grading.MaxMarks)
                return $"{subjects[i]}: {score} is outside 0–{Grading.MaxMarks}";
            marks.Add(new Mark(subjects[i], score));
        }

        student = new Student(rollNo, cells[1], cells[2], cells[3].ToUpperInvariant(), marks);
        return null;
    }
}

This simple Split(',') doesn't support quoted fields like "Iyer, Ananya". That's acceptable for a file you control; for real CSV from Excel use a library such as CsvHelper (Week 6).

using GradeAnalyzer.Core.Models;

namespace GradeAnalyzer.Core.Reports;

public class GradeReports(IReadOnlyList<Student> students, IReadOnlyList<string> subjects)
{
    // GroupBy + Average + Count(predicate)
    public IReadOnlyList<ClassAverage> ClassAverages() =>
        students
            .GroupBy(s => s.ClassSection)
            .OrderBy(g => g.Key, StringComparer.Ordinal)
            .Select(g => new ClassAverage(
                g.Key,
                g.Count(),
                Math.Round(g.Average(s => s.Percentage), 2),
                Math.Round(100m * g.Count(s => !s.HasFailed) / g.Count(), 1)))
            .ToList();

    // Max, then Where to keep every student who tied for the top score
    public IReadOnlyList<SubjectTopper> SubjectToppers() =>
        subjects
            .Select(subject =>
            {
                int best = students.Max(s => s.ScoreIn(subject));
                var names = students.Where(s => s.ScoreIn(subject) == best).Select(s => s.Name).ToList();
                return new SubjectTopper(subject, best, names);
            })
            .ToList();

    // GroupBy → dictionary, then project over ALL grades so empty grades show 0
    public IReadOnlyList<GradeCount> GradeDistribution()
    {
        Dictionary<string, int> counts = students
            .GroupBy(s => s.Grade)
            .ToDictionary(g => g.Key, g => g.Count());

        return Grading.AllGrades
            .Select(grade => new GradeCount(grade, counts.GetValueOrDefault(grade)))
            .ToList();
    }

    public IReadOnlyList<FailureEntry> Failures() =>
        students
            .Where(s => s.HasFailed)
            .OrderBy(s => s.ClassSection, StringComparer.Ordinal)
            .ThenBy(s => s.RollNo)
            .Select(s => new FailureEntry(s, s.FailedSubjects.ToList()))
            .ToList();

    // Competition ranking (1, 2, 2, 4): sort once, then one pass comparing with the previous student
    public IReadOnlyList<RankEntry> RankList()
    {
        List<Student> ordered = students
            .OrderByDescending(s => s.Total)
            .ThenBy(s => s.Name, StringComparer.Ordinal)
            .ToList();

        var ranks = new List<RankEntry>(ordered.Count);
        for (int i = 0; i < ordered.Count; i++)
        {
            bool tiedWithPrevious = i > 0 && ordered[i].Total == ordered[i - 1].Total;
            int rank = tiedWithPrevious ? ranks[i - 1].Rank : i + 1;
            ranks.Add(new RankEntry(rank, ordered[i]));
        }
        return ranks;
    }
}
Tip. A one-line LINQ ranking exists — students.Select(s => new RankEntry(1 + students.Count(o => o.Total > s.Total), s)) — but it's O(n²). Fine for a class of 40, slow for a board of 2 lakh students. Know both and say which you'd pick.

Interview questions

Answer out loud first, then open each one to compare.

BasicWhy are Student and Mark records?
They're data carriers created once from the CSV and never modified. Records give concise positional syntax, immutability by default, value-based equality and a readable ToString for debugging.
BasicWhy does the parser collect errors instead of throwing on the first bad row?
One typo shouldn't block a whole class's report. Row-level problems are expected input errors, so they're returned with line numbers; only a structural problem (empty file, wrong header) throws, because nothing useful can be done then.
IntermediateHow do you report all tied toppers, not just one?
Compute the maximum score per subject, then filter with Where for everyone equal to it. MaxBy alone would return only the first student with the top score.
IntermediateYour rank list must handle 2 lakh students. What changes?
Keep the sort-once, single-pass ranking (O(n log n)) rather than counting higher scores per student (O(n²)); stream the CSV row by row (File.ReadLines is lazy, but Parse currently calls ToList() on all lines, so process rows as they arrive instead); and cache computed properties like Total if profiling shows the repeated Sum matters.

using GradeAnalyzer.Core.Models;

namespace GradeAnalyzer.Core.Reports;

public class AdvancedReports(IReadOnlyList<Student> students, IReadOnlyList<string> subjects)
{
    // 1. Pivot: one row per section, one average per subject
    public IReadOnlyList<SectionSubjectAverages> SubjectAveragesBySection() =>
        students
            .GroupBy(s => s.ClassSection)
            .OrderBy(g => g.Key, StringComparer.Ordinal)
            .Select(g => new SectionSubjectAverages(
                g.Key,
                subjects.ToDictionary(
                    sub => sub,
                    sub => Math.Round((decimal)g.Average(s => s.ScoreIn(sub)), 1))))
            .ToList();

    // 2. Which section leads each subject (ties: MaxBy keeps the first section seen)
    public IReadOnlyList<SectionLeader> BestSectionPerSubject() =>
        subjects
            .Select(sub => students
                .GroupBy(s => s.ClassSection)
                .Select(g => new SectionLeader(sub, g.Key, Math.Round((decimal)g.Average(s => s.ScoreIn(sub)), 1)))
                .MaxBy(x => x.Average)!)
            .ToList();

    // 3. Top N per section using a lookup (built once, immediate)
    public IReadOnlyList<SectionToppers> TopPerSection(int n = 3)
    {
        ArgumentOutOfRangeException.ThrowIfNegativeOrZero(n);
        ILookup<string, Student> bySection = students.ToLookup(s => s.ClassSection);

        return bySection
            .OrderBy(g => g.Key, StringComparer.Ordinal)
            .Select(g => new SectionToppers(
                g.Key,
                g.OrderByDescending(s => s.Total).ThenBy(s => s.Name, StringComparer.Ordinal).Take(n).ToList()))
            .ToList();
    }

    // 4. Compartment: failed exactly one subject
    public IReadOnlyList<FailureEntry> Compartment() =>
        students
            .Where(s => s.FailedSubjects.Count() == 1)
            .Select(s => new FailureEntry(s, s.FailedSubjects.ToList()))
            .ToList();

    // 5. Strongest and weakest subject for every student, biggest gap first
    public IReadOnlyList<SubjectSpread> StrongestAndWeakest() =>
        students
            .Select(s => new SubjectSpread(s, s.Marks.MaxBy(m => m.Score)!, s.Marks.MinBy(m => m.Score)!))
            .OrderByDescending(x => x.Gap)
            .ToList();

    // 6. Pass percentage per subject, weakest subject first
    public IReadOnlyList<SubjectPassRate> PassRateBySubject() =>
        subjects
            .Select(sub => new SubjectPassRate(
                sub,
                students.Count(s => s.ScoreIn(sub) >= Grading.PassMark),
                students.Count))
            .OrderBy(r => r.Percent)
            .ToList();

    // 7. All-rounders: strictly above their own section's average in EVERY subject
    public IReadOnlyList<Student> AllRounders()
    {
        // section → (subject → average), computed once
        Dictionary<string, Dictionary<string, double>> averages = students
            .GroupBy(s => s.ClassSection)
            .ToDictionary(
                g => g.Key,
                g => subjects.ToDictionary(sub => sub, sub => g.Average(s => s.ScoreIn(sub))));

        return students
            .Where(s => subjects.All(sub => s.ScoreIn(sub) > averages[s.ClassSection][sub]))
            .OrderBy(s => s.ClassSection, StringComparer.Ordinal)
            .ThenBy(s => s.RollNo)
            .ToList();
    }

    // 8. Histogram of one subject in bands of 10; GroupJoin keeps bands with zero students
    public IReadOnlyList<ScoreBand> ScoreBands(string subject)
    {
        IEnumerable<int> bandStarts = Enumerable.Range(0, 10).Select(i => i * 10);   // 0, 10, … 90

        return bandStarts
            .GroupJoin(
                students,
                start => start,
                s => Math.Min(s.ScoreIn(subject) / 10 * 10, 90),       // 100 belongs to the 90–100 band
                (start, inBand) => new ScoreBand(start, start == 90 ? 100 : start + 9, inBand.Count()))
            .ToList();
    }

    // 9. Most consistent: lowest standard deviation of a student's marks
    public IReadOnlyList<Consistency> MostConsistent(int n = 3) =>
        students
            .Select(s =>
            {
                double mean = s.Marks.Average(m => m.Score);
                double sumOfSquares = s.Marks.Aggregate(0.0, (acc, m) => acc + Math.Pow(m.Score - mean, 2));
                return new Consistency(s, mean, Math.Sqrt(sumOfSquares / s.Marks.Count));
            })
            .OrderBy(c => c.StdDev)
            .Take(n)
            .ToList();

    // 10. Rank k of section A vs rank k of section B; Zip stops at the smaller section
    public IReadOnlyList<HeadToHeadRow> SectionHeadToHead(string sectionA, string sectionB)
    {
        IEnumerable<Student> Ranked(string section) =>
            students
                .Where(s => s.ClassSection.Equals(section, StringComparison.OrdinalIgnoreCase))
                .OrderByDescending(s => s.Total)
                .ThenBy(s => s.Name, StringComparer.Ordinal);

        return Ranked(sectionA)
            .Zip(Ranked(sectionB))
            .Select((pair, index) => new HeadToHeadRow(index + 1, pair.First, pair.Second))
            .ToList();
    }
}

Interview questions

BasicWhy build the menu as a Dictionary<int, (string, Action)> instead of a switch?
Each option is data: adding a report means adding one entry, and the loop that prints and dispatches never changes (open/closed principle). It's the delegate-as-strategy pattern from Monday.
BasicWhy does report 8 use GroupJoin instead of GroupBy?
GroupBy only produces groups for bands that have students, so empty bands disappear from the histogram. GroupJoin starts from the full list of bands (the outer sequence) and pairs each with its possibly-empty group, so every band shows, including zeros.
IntermediateReport 7 could be written with a nested Average inside All. Why precompute a dictionary?
Inside All, the average would be recomputed for every student and subject: O(students² × subjects). Precomputing section → subject → average once makes each check an O(1) lookup — the same idea as ToLookup instead of a nested Where.
IntermediateHow would these reports change if the data lived in SQL Server via EF Core?
Most of them (GroupBy with aggregates, Where, OrderBy, Take, Count) translate to SQL if written against IQueryable, so the database does the work. Computed properties like Student.Total and helpers like ScoreIn wouldn't translate; you'd model marks as a table and express them as Sum/joins in the query, or materialise a filtered set first and finish in memory.
