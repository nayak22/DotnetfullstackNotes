DAY 1 · MON

Structs, records, tuples and deconstruction

GoalChoose between class, struct, record and tuple for a given piece of data, and use with-expressions and deconstruction fluently.

Key definitions

struct
A user-defined value type. Copied on assignment, allocated inline (stack or inside its container), can't inherit.
readonly struct
A struct whose fields are all readonly, so it's immutable and the compiler avoids defensive copies.
record
A reference type (record class) with compiler-generated value equality, ToString, Deconstruct and with-expression support.
Positional record
A record declared with parameters, e.g. record Customer(string Name, string Email); generates init-only properties.
record struct
A value-type record (C# 10). readonly record struct makes it immutable.
Value equality
Two instances are equal when their data is equal, not when they are the same object.
with-expression
Creates a copy of a record or struct with some properties changed: c with { Email = "x" }.
Non-destructive mutation
Producing a modified copy instead of changing the original.
Tuple (ValueTuple)
A lightweight value type grouping values, e.g. (string Name, int Age).
Named tuple elements
Giving tuple fields names instead of Item1/Item2.
Deconstruction
Unpacking an object or tuple into separate variables: var (name, age) = person;
Deconstruct method
A method void Deconstruct(out T1 a, out T2 b) that enables deconstruction on any type.
Discard
_ — ignore a value you don't need while deconstructing or pattern matching.
Quick notes
  • Class: identity and behaviour. Struct: small immutable value. Record: data with value equality. Tuple: temporary grouping.
  • Keep structs small (≈16 bytes or less) and make them readonly.
  • Records compare by value: two records with the same data are ==.
  • Use with to change a copy; the original stays the same.
  • Return a named tuple for quick multi-value results inside a class; use a record when the shape is shared across your code.
  • Deconstruction works on tuples, records and anything with a Deconstruct method.

1. Structs

A struct is a value type: assignment copies the whole value. Use one for small, immutable values that represent a single concept, like a coordinate, money or a date range.

GeoPoint.cs
public readonly struct GeoPoint
{
    public double Lat { get; }
    public double Lng { get; }

    public GeoPoint(double lat, double lng)
    {
        if (lat is < -90 or > 90) throw new ArgumentOutOfRangeException(nameof(lat));
        if (lng is < -180 or > 180) throw new ArgumentOutOfRangeException(nameof(lng));
        Lat = lat;
        Lng = lng;
    }

    // Haversine distance in km
    public double DistanceTo(GeoPoint other)
    {
        const double R = 6371;
        double dLat = ToRad(other.Lat - Lat), dLng = ToRad(other.Lng - Lng);
        double a = Math.Pow(Math.Sin(dLat / 2), 2) +
                   Math.Cos(ToRad(Lat)) * Math.Cos(ToRad(other.Lat)) * Math.Pow(Math.Sin(dLng / 2), 2);
        return 2 * R * Math.Asin(Math.Sqrt(a));
    }

    private static double ToRad(double deg) => deg * Math.PI / 180;
    public override string ToString() => $"({Lat:F4}, {Lng:F4})";
}
var bengaluru = new GeoPoint(12.9716, 77.5946);
var mumbai    = new GeoPoint(19.0760, 72.8777);
Console.WriteLine($"{bengaluru.DistanceTo(mumbai):F0} km");   // ≈ 845 km

GeoPoint copy = bengaluru;      // full copy — independent value
GeoPoint empty = default;       // (0, 0): every struct has a zero value that skips your constructor
Use a struct when…Use a class when…
It represents one small value (≈16 bytes or less)It has identity or a lifecycle (Customer, Order)
It's immutableIt's mutable or large
You create millions and want to avoid heap allocationsIt's shared and passed around a lot
It doesn't need inheritanceYou need inheritance or polymorphism
Avoid. Mutable structs cause confusing bugs: changing a copy (e.g. an item pulled from a List) doesn't change the original. Make structs readonly.

2. Records

Records are built for data. The compiler generates value equality, a readable ToString(), a Deconstruct method and support for with.

Records.cs
// Positional record: one line gives you a constructor, init-only properties, equality, ToString, Deconstruct
public record Customer(string Name, string Email, string City = "Bengaluru");

var a = new Customer("Asha", "asha@example.com");
var b = new Customer("Asha", "asha@example.com");

Console.WriteLine(a == b);              // True  — compared by value
Console.WriteLine(ReferenceEquals(a, b)); // False — still two objects
Console.WriteLine(a);                   // Customer { Name = Asha, Email = asha@example.com, City = Bengaluru }

// a.Email = "new@example.com";         // ❌ init-only
var moved = a with { City = "Pune" };   // copy with one change
Console.WriteLine(moved.City);          // Pune
Console.WriteLine(a.City);              // Bengaluru — original untouched

Records with extra members and validation

public record Money(decimal Amount, string Currency)
{
    // Validate by re-declaring the property with an initializer
    public decimal Amount { get; init; } = Amount >= 0
        ? Amount
        : throw new ArgumentOutOfRangeException(nameof(Amount));

    public Money Add(Money other) =>
        other.Currency == Currency
            ? this with { Amount = Amount + other.Amount }
            : throw new InvalidOperationException("Currency mismatch");

    public override string ToString() => $"{Amount:N2} {Currency}";   // customise output
}

// Nominal record: properties instead of a parameter list
public record OrderLine
{
    public required string Sku { get; init; }
    public int Quantity { get; init; } = 1;
    public decimal UnitPrice { get; init; }
    public decimal Total => Quantity * UnitPrice;
}

Record inheritance

public abstract record Payment(decimal Amount);
public record UpiPayment(decimal Amount, string Vpa) : Payment(Amount);
public record CardPayment(decimal Amount, string Last4) : Payment(Amount);

Payment p = new UpiPayment(499m, "asha@okbank");
Console.WriteLine(p);   // UpiPayment { Amount = 499, Vpa = asha@okbank }

// Equality also checks the runtime type:
Console.WriteLine(new UpiPayment(1, "x") == (Payment)new UpiPayment(1, "x"));   // True

4. Tuples

ValueTuple groups values without declaring a type. Name the elements; Item1/Item2 are hard to read.

// Return several values from a method
static (decimal Subtotal, decimal Gst, decimal Total) PriceCart(decimal[] prices)
{
    decimal subtotal = prices.Sum();
    decimal gst = Math.Round(subtotal * 0.18m, 2);
    return (subtotal, gst, subtotal + gst);
}

var bill = PriceCart([499m, 1299m, 89m]);
Console.WriteLine($"{bill.Subtotal} + {bill.Gst} = {bill.Total}");   // 1887 + 339.66 = 2226.66

// Tuple equality compares element by element (C# 7.3)
Console.WriteLine((1, "a") == (1, "a"));   // True

// Swap without a temp variable
int x = 1, y = 2;
(x, y) = (y, x);
Console.WriteLine($"{x} {y}");             // 2 1
Tip. Tuples are great inside one class or method. Once the same shape appears in several places or crosses a public API, promote it to a record.

Common mistakes

  • Making large or mutable structs.
  • Forgetting that a struct always has a default value that skips your constructor's validation.
  • Using records for EF Core entities that get updated: their value equality confuses change tracking. Use classes for entities.
  • Returning unnamed tuples from public methods (Item1, Item2).
  • Expecting with to deep-copy: it copies references to nested objects (shallow).

BasicWhat is the difference between a class and a struct?
A class is a reference type allocated on the heap, copied by reference, supports inheritance and can be null. A struct is a value type stored inline, copied by value, can't inherit, and always has a default value. Use structs for small immutable values and classes for everything else.
BasicWhat is a record and when would you use one?
A record is a type whose equality is based on its data. The compiler generates Equals, GetHashCode, ==, ToString, Deconstruct and with-support. Use records for immutable data carriers: DTOs, API contracts, domain events and value objects.
BasicWhat does the with expression do?
It creates a shallow copy of a record (or struct, or anonymous type) with the specified properties changed, leaving the original unchanged. Under the hood it calls a generated clone method then sets the init properties.
Intermediaterecord vs record struct vs class — how do you choose?
Class for entities with identity and mutable state. Record class for immutable data with value equality, passed by reference (cheap to pass, allocates on the heap). Readonly record struct for very small value objects where you want value semantics and no heap allocation.
IntermediateWhy shouldn't you use records as EF Core entities?
Entities have identity (their key) and are mutated and tracked. Record value equality makes two entities with the same data look equal, conflicting with identity semantics and change tracking, and with-expressions produce new untracked instances.
IntermediateWhat is the default value problem with structs?
Every struct has a default (all zero bits) created by default, array allocation or uninitialised fields. It bypasses your constructor, so validation can't guarantee invariants. Design structs so that zero is a valid state, or validate at use.
DAY 2 · TUE

Pattern matching in depth

GoalReplace nested if/else and casting with expressive patterns: type, property, relational, logical, positional and list patterns.

Key definitions

Pattern
A test that a value has a certain shape, with optional variable capture.
Declaration pattern
x is Circle c — tests the type and assigns a typed variable.
Type pattern
x is Circle or a switch arm Circle => … — tests the type only.
Constant pattern
Compares against a constant: is null, is 0, "IN" =>.
Relational pattern
<, >, <=, >= against a constant (C# 9).
Logical pattern
Combine patterns with and, or, not (C# 9).
Property pattern
{ Status: "Paid", Total: > 1000 } — matches property values.
Extended property pattern
{ Address.City: "Pune" } — nested member access (C# 10).
Positional pattern
Matches using Deconstruct: ("IN", > 1) or Point(0, 0).
List pattern
Matches arrays/lists by element: [1, .., 9], [var first, ..] (C# 11).
Slice pattern
.. inside a list pattern matches zero or more elements; .. var rest captures them.
Case guard (when)
An extra boolean condition on a switch arm.
Exhaustiveness
The compiler warns when a switch expression doesn't cover all inputs.
Quick notes
  • Use is null / is not null for null checks; they can't be fooled by an overloaded ==.
  • Switch expressions + patterns turn business rules into readable tables.
  • Order arms from most specific to least specific; the compiler errors on unreachable arms.
  • End with _ => or throw, unless the compiler confirms you're exhaustive.
  • Property patterns read nested data without null checks: a null object simply doesn't match.
  • List patterns are great for parsing commands and arguments.

1. Type and declaration patterns, and null checks

object input = 42;

    Console.WriteLine($"Positive int {n}");

    Console.WriteLine("Not a string");

Customer? customer = FindCustomer(7);

    string { Length: 0 } => "empty string",
    string s        => $"text '{s}'",
    IEnumerable<int> nums => $"{nums.Count()} numbers",

4. Positional patterns and tuple switches

Switching on a tuple turns a state machine into a readable table.

OrderStateMachine.cs
public enum OrderState { Placed, Paid, Shipped, Delivered, Cancelled }
public enum OrderAction { Pay, Ship, Deliver, Cancel }

OrderState Next(OrderState state, OrderAction action) => (state, action) switch
{
    (OrderState.Placed,  OrderAction.Pay)     => OrderState.Paid,
    (OrderState.Paid,    OrderAction.Ship)    => OrderState.Shipped,
    (OrderState.Shipped, OrderAction.Deliver) => OrderState.Delivered,
    (OrderState.Placed or OrderState.Paid, OrderAction.Cancel) => OrderState.Cancelled,
    _ => throw new InvalidOperationException($"Can't {action} an order that is {state}")
};

Console.WriteLine(Next(OrderState.Placed, OrderAction.Pay));      // Paid
// Next(OrderState.Shipped, OrderAction.Cancel);                  // throws

5. List patterns (C# 11)

int[] nums = [1, 2, 3, 4, 5];

Console.WriteLine(nums is [1, 2, 3, 4, 5]);     // True — exact
Console.WriteLine(nums is [1, ..]);             // True — starts with 1
Console.WriteLine(nums is [.., 5]);             // True — ends with 5
Console.WriteLine(nums is [_, _, ..]);          // True — at least 2 elements
if (nums is [var first, .. var middle, var last])
    Console.WriteLine($"{first} | {string.Join(",", middle)} | {last}");   // 1 | 2,3,4 | 5

// Parse console commands
string Run(string[] args) => args switch
{
    []                                  => "Usage: lib <command>",
    ["list"]                            => "Listing all items",
    ["borrow", var member, var item]    => $"Member {member} borrows {item}",
    ["return", var item]                => $"Returning {item}",
    ["search", .. var words] when words.Length > 0 => $"Searching '{string.Join(' ', words)}'",
    [var cmd, ..]                       => $"Unknown command '{cmd}'"
};

Console.WriteLine(Run("borrow 1001 5".Split(' ')));      // Member 1001 borrows 5
Console.WriteLine(Run("search clean code".Split(' ')));  // Searching 'clean code'

Common mistakes

  • Writing an arm that's already covered by an earlier one (CS8510 unreachable).
  • Forgetting the _ arm; a missing case throws SwitchExpressionException at runtime.
  • Using == null on types that overload ==; prefer is null.
  • Over-nesting patterns until nobody can read them; extract a well-named method.
  • Using patterns to select behaviour that belongs in a virtual method (Week 2, Day 4).

BasicWhat is pattern matching in C#?
A set of language features (is, switch statements/expressions) that test a value against a shape — type, constant, range, property values, position or list elements — and optionally extract parts of it into variables, replacing manual casts and nested ifs.
BasicWhy prefer 'is null' over '== null'?
== can be overloaded by a type and may behave unexpectedly; is null always performs a true null check. It also reads consistently with is not null.
BasicWhat are relational and logical patterns?
Relational patterns compare with <, >, <=, >= against constants; logical patterns combine patterns with and, or and not. Example: score is >= 0 and <= 100.
IntermediateWhat are list patterns and give a use case.
C# 11 patterns that match sequences by elements and length, with .. for slices. Use cases: parsing command-line arguments, validating fixed-format codes, checking prefixes/suffixes of arrays.
IntermediateHow would you implement a state machine with pattern matching?
Switch on a tuple of (currentState, trigger), with one arm per valid transition returning the next state and a final arm that throws for invalid transitions. It's compact, readable and easy to review against a state diagram.
IntermediateWhen is a switch expression not exhaustive even with enums?
Enums can hold any value of their underlying type, not just named members, so the compiler still requires a discard arm (or warns) even if every named value is listed.

Enums, object, Equals/GetHashCode and boxing

GoalUse enums and flags correctly, implement equality that works with dictionaries and sets, and spot hidden boxing.

Key definitions

enum
A value type defining a set of named integral constants, e.g. OrderStatus.Paid.
Underlying type
The integral type behind an enum, int by default; can be byte, short, long etc.
[Flags]
An attribute marking an enum whose values are bit flags that can be combined with |.
Bitwise operators
| combine, & test, ~ invert, ^ toggle bits.
Reference equality
Two references point to the same object (ReferenceEquals).
Value equality
Two objects hold equal data.
IEquatable<T>
Interface providing a strongly typed Equals(T other), avoiding boxing for structs.
Hash code
An int derived from an object's data, used by Dictionary and HashSet to pick a bucket.
HashCode.Combine
Helper that produces a good hash code from several fields.
Boxing
Copying a value type into a new heap object so it can be treated as object or an interface.
Unboxing
Copying the value back out of the box; requires a cast to the exact type.
System.Object
Root of all types; defines Equals, GetHashCode, ToString, GetType, MemberwiseClone.
Quick notes
  • Store enums by name in JSON/APIs where possible; numbers break when members are reordered.
  • Give [Flags] members powers of two and include None = 0.
  • Override Equals and GetHashCode together, always.
  • Equal objects must have equal hash codes; unequal objects may share one.
  • Never use mutable fields in GetHashCode for objects stored in a dictionary or set.
  • Boxing hides in non-generic APIs, interface calls on structs and object parameters.

4. Implementing equality properly

Decide what makes two objects "the same". For a product it's the SKU, not the name.

Product.cs
public sealed class Product : IEquatable<Product>
{
    public string Sku { get; }
    public string Name { get; set; }      // mutable, so NOT part of equality

    public Product(string sku, string name)
    {
        Sku = sku.Trim().ToUpperInvariant();
        Name = name;

The equality contract

  • Reflexive: x.Equals(x) is true.
  • Symmetric: x.Equals(y) equals y.Equals(x).
  • Transitive: if x = y and y = z, then x = z.
  • Consistent with GetHashCode: equal objects return equal hash codes.
  • x.Equals(null) is false and never throws.
Danger. If an object's hash code changes while it's inside a Dictionary key or HashSet, you can no longer find or remove it. Base hash codes on immutable fields.
Tip. Records do all of this for you, including IEquatable<T>, == and !=. Hand-write equality only when the identity rule differs from 'all fields'.

Exceptions: try/catch/finally, custom exceptions, throw vs throw ex

GoalHandle errors at the right level, preserve stack traces, write meaningful custom exceptions, and know when not to use exceptions at all.

Key definitions

Exception
An object describing an error that interrupts normal flow and propagates up the call stack until caught.
Throw
Raising an exception: throw new InvalidOperationException("…").
try / catch / finally
try runs code; catch handles matching exceptions; finally always runs for cleanup.
Exception filter
catch (HttpRequestException ex) when (ex.StatusCode == 404) — catches only when the condition is true, without unwinding the stack first.

The list of method calls active when the exception was thrown; vital for debugging.

Re-raises the current exception preserving its original stack trace.

Re-raises the exception but resets the stack trace to the current line. Avoid.

The original exception wrapped inside a new, higher-level one (new XException("…", ex)).

  • Throw for things that shouldn't happen; return a result for expected outcomes.
  • Catch only what you can handle, at the level where you can do something useful.

  • Wrap low-level exceptions in domain ones and pass the original as the inner exception.

static decimal ReadPriceFromFile(string path)

        return 0m;

    catch (FormatException)

    }
}

6. Pitfalls

  • Memory leaks: the publisher holds references to subscribers. If a long-lived publisher (a static service) has a short-lived subscriber (a form, a view model), the subscriber never gets collected unless it unsubscribes.
  • Exceptions in handlers: if one handler throws, later handlers don't run and the exception reaches the code that raised the event.
  • Synchronous: handlers run on the raiser's thread, one after another. A slow handler slows the publisher.
  • Can't unsubscribe an anonymous lambda unless you stored it in a variable first.
Tip. In ASP.NET Core you'll mostly use other patterns for this (MediatR notifications, domain events, message queues), but they all build on the same publisher/subscriber idea.

Common mistakes

  • Raising events without the null-conditional ?. → NullReferenceException when nobody subscribed.
  • Using a public delegate field instead of an event.
  • Forgetting to unsubscribe from long-lived publishers.
  • Doing slow work (I/O, network) directly inside an event handler.
  • Expecting multicast Func to return all results.

namespace Bank.Core;

public abstract class Account
{
    public const decimal LargeTransactionLimit = 50_000m;
    private static int _sequence = 1000;
    private readonly List<Transaction> _ledger = [];

    public string Number { get; }
    public string Holder { get; }
    public decimal Balance { get; private set; }
    public decimal LowBalanceThreshold { get; set; }
    public IReadOnlyList<Transaction> Ledger => _ledger.AsReadOnly();

    public event EventHandler<LowBalanceEventArgs>? LowBalance;
    public event EventHandler<LargeTransactionEventArgs>? LargeTransaction;

    protected Account(string prefix, string holder, decimal lowBalanceThreshold)
    {
        ArgumentException.ThrowIfNullOrWhiteSpace(holder);
        Number = $"{prefix}{++_sequence}";
        Holder = holder.Trim();
        LowBalanceThreshold = lowBalanceThreshold;
    }

    public abstract string Kind { get; }

    /// <summary>The most this account allows to be withdrawn right now.</summary>
    public abstract decimal AvailableToWithdraw { get; }

    public void Deposit(decimal amount, string? note = null) =>
        Credit(TransactionType.Deposit, amount, note);

    public void Withdraw(decimal amount, string? note = null) =>
        Debit(TransactionType.Withdrawal, amount, note);

    internal void Credit(TransactionType type, decimal amount, string? note)
    {
        ArgumentOutOfRangeException.ThrowIfNegativeOrZero(amount);
        Balance += amount;
        Record(type, amount, note);
    }

    internal void Debit(TransactionType type, decimal amount, string? note)
    {
        ArgumentOutOfRangeException.ThrowIfNegativeOrZero(amount);
        if (amount > AvailableToWithdraw)
            throw new InvalidOperationException(
                $"{Number}: can't withdraw {amount:N2}; available {AvailableToWithdraw:N2}");   // replaced tomorrow

        Balance -= amount;
        Record(type, amount, note);

        if (Balance < LowBalanceThreshold)
            OnLowBalance(new LowBalanceEventArgs(Number, Balance, LowBalanceThreshold));
    }

    private void Record(TransactionType type, decimal amount, string? note)
    {
        var tx = new Transaction(Guid.NewGuid(), DateTime.Now, type, amount, Balance, note);
        _ledger.Add(tx);
        if (amount >= LargeTransactionLimit)
            OnLargeTransaction(new LargeTransactionEventArgs(Number, tx));
    }

    protected virtual void OnLowBalance(LowBalanceEventArgs e) => LowBalance?.Invoke(this, e);
    protected virtual void OnLargeTransaction(LargeTransactionEventArgs e) => LargeTransaction?.Invoke(this, e);

    public override string ToString() => $"{Number}  {Kind,-8} {Holder,-12} {Balance,14:N2}";
}

Step 5 — BankService

namespace Bank.Core;

public class BankService
{
    private readonly Dictionary<string, Account> _accounts = new(StringComparer.OrdinalIgnoreCase);

    public IReadOnlyCollection<Account> Accounts => _accounts.Values;

    // Forward every account's events through the bank so the app subscribes once
    public event EventHandler<LowBalanceEventArgs>? LowBalance;
    public event EventHandler<LargeTransactionEventArgs>? LargeTransaction;

    public T Open<T>(T account) where T : Account
    {
        account.LowBalance += (s, e) => LowBalance?.Invoke(s, e);
        account.LargeTransaction += (s, e) => LargeTransaction?.Invoke(s, e);
        _accounts.Add(account.Number, account);
        return account;
    }

    public Account Get(string number) =>
        _accounts.TryGetValue(number, out var acc)
            ? acc
            : throw new KeyNotFoundException($"No account {number}");   // replaced tomorrow

    public void Transfer(string fromNumber, string toNumber, decimal amount)
    {
        if (string.Equals(fromNumber, toNumber, StringComparison.OrdinalIgnoreCase))
            throw new InvalidOperationException("Can't transfer to the same account");

        Account from = Get(fromNumber), to = Get(toNumber);
        from.Debit(TransactionType.TransferOut, amount, $"to {to.Number}");   // throws first if not enough
        to.Credit(TransactionType.TransferIn, amount, $"from {from.Number}");
    }
}

BasicWhy is Transaction a readonly record struct?
Transactions are small, immutable facts that never change once recorded. A readonly record struct gives value equality and a readable ToString without heap allocation per transaction.
BasicWhy does Account use events instead of printing alerts itself?
Separation of concerns: the domain only announces that something happened. The console app, an email service or a fraud check can subscribe without the account knowing about them.
IntermediateWhy does Transfer debit before crediting?
Debit validates funds and throws if insufficient. Doing it first means a failed transfer never credits the receiver, keeping both accounts consistent. Real systems use database transactions for this (Week 13).
IntermediateHow does polymorphism decide how much can be withdrawn?
AvailableToWithdraw is abstract: savings returns balance minus the minimum, current returns balance plus the overdraft. Debit only calls the abstract property, so new account types plug in without changing it.

Key definitions

Exception hierarchy
A family of exceptions sharing a base class, so callers can catch broadly or narrowly.
Domain exception
An exception expressing a business rule violation, e.g. insufficient funds.
Frozen account
An account blocked from debits, e.g. after suspected fraud.
Daily limit
The maximum total amount that may be withdrawn per day.
Quick notes
  • One abstract base (BankException) lets the app catch all business errors in one place.
  • Each subtype carries the data a handler needs (shortfall, limit, account number).
  • The app catches specific types for specific messages, then the base type as a fallback.
  • Programming bugs (ArgumentException from wrong code) are separate from business failures.

1. Exception hierarchy

namespace Bank.Core.Exceptions;

public abstract class BankException : Exception
{
    public string? AccountNumber { get; }
    protected BankException(string message, string? accountNumber = null, Exception? inner = null)
        : base(message, inner) => AccountNumber = accountNumber;
}

public sealed class AccountNotFoundException(string accountNumber)
    : BankException($"Account {accountNumber} doesn't exist", accountNumber);

public sealed class InsufficientFundsException(string accountNumber, decimal requested, decimal available)
    : BankException($"{accountNumber}: requested {requested:N2}, available {available:N2}", accountNumber)
{
    public decimal Requested { get; } = requested;
    public decimal Available { get; } = available;
    public decimal Shortfall => Requested - Available;
}

public sealed class AccountFrozenException(string accountNumber, string reason)
    : BankException($"{accountNumber} is frozen: {reason}", accountNumber)
{
    public string Reason { get; } = reason;
}

public sealed class DailyLimitExceededException(string accountNumber, decimal limit, decimal usedToday)
    : BankException($"{accountNumber}: daily limit {limit:N2} reached (used {usedToday:N2})", accountNumber)
{
    public decimal Limit { get; } = limit;
    public decimal UsedToday { get; } = usedToday;
}

// Account.cs — new members
public const decimal DailyWithdrawalLimit = 100_000m;
public bool IsFrozen { get; private set; }
public string? FrozenReason { get; private set; }

public void Freeze(string reason) { IsFrozen = true; FrozenReason = reason; }
public void Unfreeze() { IsFrozen = false; FrozenReason = null; }

private decimal WithdrawnToday() =>
    Ledger.Where(t => t.At.Date == DateTime.Today &&
                      t.Type is TransactionType.Withdrawal or TransactionType.TransferOut)
          .Sum(t => t.Amount);

internal void Debit(TransactionType type, decimal amount, string? note)
{
    ArgumentOutOfRangeException.ThrowIfNegativeOrZero(amount);       // caller bug → ArgumentException

    if (IsFrozen)
        throw new AccountFrozenException(Number, FrozenReason ?? "no reason given");

    decimal used = WithdrawnToday();
    if (used + amount > DailyWithdrawalLimit)
        throw new DailyLimitExceededException(Number, DailyWithdrawalLimit, used);

    if (amount > AvailableToWithdraw)
        throw new InsufficientFundsException(Number, amount, AvailableToWithdraw);

    Balance -= amount;
    Record(type, amount, note);
    if (Balance < LowBalanceThreshold)
        OnLowBalance(new LowBalanceEventArgs(Number, Balance, LowBalanceThreshold));
}

public Account Get(string number) =>
    _accounts.TryGetValue(number, out var acc) ? acc : throw new AccountNotFoundException(number);

BasicWhy give custom exceptions a common base class?
Callers can catch the whole family with one catch (BankException) for generic handling, while still catching specific subtypes when they need special behaviour.
BasicShould 'insufficient funds' be an exception or a result object?
Both are defensible. If callers usually check availability first, an attempted overdraw is a contract violation and an exception fits. If it's a common, expected outcome (e.g. API validation), a Result is cheaper and clearer. Be consistent within a layer.
IntermediateHow do you keep a stack trace when translating a low-level exception into a domain exception?
Pass the original as the inner exception: throw new AccountNotFoundException(id, ex). Logs then show both the domain message and the original stack trace.
IntermediateWhy separate ArgumentException from BankException in the catch blocks?
ArgumentException signals a programming or input-validation bug (negative amount); BankException signals a legitimate business rule. Treating them differently helps users get the right message and helps developers spot real bugs.
