DAY 1 · MON

Classes, objects, constructors, properties and fields

GoalModel a real business entity as a class with validated properties, sensible constructors and a useful ToString().

Key definitions

Class
A blueprint that defines the data (state) and behaviour (methods) of a type. A reference type.
Object / instance
A concrete value created from a class with new; each object has its own copy of instance data.
Field
A variable declared directly in a class that stores the object's data. Private by convention, named _camelCase.
Property
A member that looks like a field to callers but runs get/set accessors, so you can validate or compute.
Backing field
The private field a full property reads and writes.
Auto-property
{ get; set; } — the compiler generates a hidden backing field.
Init-only setter
{ get; init; } — the property can be set only in a constructor or object initializer (C# 9).
required member
C# 11 modifier forcing callers to set a property in the object initializer.
Computed property
A property with no storage that calculates its value: public decimal Annual => Monthly * 12;
Constructor
A special method with the class's name and no return type that initialises a new object.
Constructor chaining
Calling another constructor of the same class with : this(...) to avoid duplicate code.
Primary constructor
C# 12 syntax that declares constructor parameters on the class line: class Invoice(string number).
Object initializer
new Employee { Name = "Asha" } — sets accessible properties right after construction.
this
A reference to the current object inside its own members.
Member
Anything declared inside a class: fields, properties, methods, constructors, events, nested types.
Quick notes
  • A class is the design; an object is one thing built from it. You can create many objects from one class.
  • Keep fields private; expose data through properties.
  • Validate in the constructor and in property setters so an object can never be in an invalid state.
  • Use init / private set for values that shouldn't change after creation.
  • Chain constructors with : this(...) instead of copying code.
  • Override ToString() so objects print something useful in logs and the debugger.

1. Classes and objects

A class describes what a thing has (data) and what it does (behaviour). An object is one instance of that class living on the heap. The variable holds a reference to it, which is why classes behave as reference types (Week 1, Day 2).

Product.cs
public class Product
{
    // Fields: the object's data (private by convention)
    private string _name;
    private decimal _price;

    // Constructor: runs when you call `new`
    public Product(string name, decimal price)
    {
        _name = name;
        _price = price;
    }

    // Method: behaviour that uses the object's data
    public string Describe() => $"{_name} costs {_price:C}";
}
Program.cs
var laptop = new Product("Laptop", 65000m);   // object #1
var mouse  = new Product("Mouse", 799m);      // object #2 — its own separate data

Console.WriteLine(laptop.Describe());   // Laptop costs ₹65,000.00   (en-IN culture)
Console.WriteLine(mouse.Describe());    // Mouse costs ₹799.00

var sameLaptop = laptop;                // copies the REFERENCE, not the object
Console.WriteLine(ReferenceEquals(laptop, sameLaptop)); // True
Tip. :C and :N format using the current culture: the ₹ output above assumes en-IN, while other :N outputs in these notes show en-US-style grouping (150,000); under en-IN you'd see lakh grouping (1,50,000). Also, when a sample shows a class and the code that uses it together, put the usage in Program.cs or above the class: top-level statements must come before type declarations in a file (error CS8803).

2. Fields

Fields hold state. Unassigned fields get default values (0, false, null). Mark a field readonly when it is assigned once in the constructor and never again.

public class Counter
{
    private int _count;                          // defaults to 0
    private readonly DateTime _createdAt = DateTime.UtcNow;   // field initializer
    private readonly List<string> _log = new();  // the reference is readonly, the list contents are not

    public void Increment()
    {
        _count++;
        _log.Add($"Incremented to {_count}");
    }
}
Avoid. Public fields like public decimal Price;. Anyone can set a negative price and you can never add validation later without breaking callers. Use a property.

3. Properties

Properties are the public face of an object's data. They look like fields to the caller, but they are really methods, so you can validate, compute or restrict access.

Employee.cs
public class Employee
{
    private decimal _monthlySalary;                 // backing field

    // 1. Full property with validation
    public decimal MonthlySalary
    {
        get => _monthlySalary;
        set
        {
            if (value < 0)
                throw new ArgumentOutOfRangeException(nameof(value), "Salary can't be negative");
            _monthlySalary = value;
        }
    }

    // 2. Auto-property with a default value
    public string Name { get; set; } = "";

    // 3. Read-only from outside the class
    public int Id { get; private set; }

    // 4. Init-only: settable only while the object is being created
    public string Department { get; init; } = "General";

    // 5. Required (C# 11): the caller MUST set it in the initializer
    public required string Email { get; init; }

    // 6. Computed: no storage, calculated on every read
    public decimal AnnualSalary => MonthlySalary * 12;
}

{
    Name = "Asha",
    Email = "asha@example.com",      // leave this out → compile error CS9035
    MonthlySalary = 85_000m,
    Department = "IT"

4. Constructors

A constructor guarantees an object starts life valid. If you declare no constructor, C# gives you a public parameterless one. As soon as you write any constructor, that free one disappears.

Order.cs
public class Order
{
    public int Id { get; }
    public string Customer { get; }
    public DateTime CreatedAt { get; }
    public decimal Total { get; private set; }

    // Chains to the main constructor — no duplicated logic
    public Order() : this(0, "Walk-in") { }

    // Main constructor: validate everything here
    public Order(int id, string customer)
    {
        if (string.IsNullOrWhiteSpace(customer))
            throw new ArgumentException("Customer is required", nameof(customer));

        Id = id;
        Customer = customer.Trim();
        CreatedAt = DateTime.UtcNow;
    }

    public void AddLine(decimal unitPrice, int quantity)
    {
        if (quantity <= 0) throw new ArgumentOutOfRangeException(nameof(quantity));
        Total += unitPrice * quantity;
    }

    public override string ToString() => $"Order #{Id} for {Customer}: {Total:N2}";
}
var order = new Order(101, "Ravi Traders");
order.AddLine(250m, 4);
order.AddLine(99.5m, 2);
Console.WriteLine(order);          // Order #101 for Ravi Traders: 1,199.00

var walkIn = new Order();
Console.WriteLine(walkIn.Customer); // Walk-in

Primary constructors (C# 12)

For simple classes, declare parameters on the class itself. The parameters are in scope across the whole class body.

Invoice.cs
public class Invoice(string number, decimal amount)
{
    public string Number { get; } = number;
    public decimal Amount { get; } = amount;
    public decimal Gst => Amount * 0.18m;        // use the property, not the parameter

    public override string ToString() => $"{Number}: {Amount:N2} + GST {Gst:N2}";
}

var inv = new Invoice("INV-2026-001", 10_000m);
Console.WriteLine(inv);   // INV-2026-001: 10,000.00 + GST 1,800.00
Tip. Primary-constructor parameters are not properties and are mutable. If callers need the value, copy it into a property like Number above. Using the parameter in both a property initializer and a method triggers warning CS9124.

5. this, methods and ToString()

public class Rectangle
{
    public double Width { get; }
    public double Height { get; }

    public Rectangle(double width, double height)
    {
        this.Width = width;        // `this.` is optional here, required only when names clash
        this.Height = height;
    }

    public double Area() => Width * Height;

    // Returns a NEW object instead of changing this one
    public Rectangle Scale(double factor) => new(Width * factor, Height * factor);

    public bool IsLargerThan(Rectangle other) => this.Area() > other.Area();

    public override string ToString() => $"{Width} × {Height}";
}

6. Object lifetime

  • new allocates the object on the managed heap and runs the constructor.
  • Variables hold references. When no reference reaches an object, the garbage collector can reclaim it. You never free memory yourself.
  • A reference that points to nothing is null; using it throws NullReferenceException.
Order? current = new Order(1, "Meena");
current = null;               // the Order object is now unreachable → eligible for GC
// current.AddLine(10, 1);    // NullReferenceException at runtime (and a compiler warning)

Common mistakes

  • Exposing public fields instead of properties.
  • Forgetting that adding any constructor removes the default parameterless one.
  • Doing validation in the UI instead of in the class, so invalid objects can still be created elsewhere.
  • Setters on values that should never change after creation (IDs, created dates).
  • Huge constructors with 8+ parameters. Group related values into their own class.

Why use a property instead of a public field?Properties let you add validation, make setters private or init-only, compute values and change the implementation later without breaking callers. Data binding and serializers also work with properties.

BasicWhat is the difference between a class and an object?
A class is a type definition: a blueprint describing data and behaviour. An object is a runtime instance of that class with its own state, allocated on the heap. One class can produce many objects.
BasicWhat is the difference between a field and a property?
A field is a variable that stores data directly. A property is a pair of accessor methods (get/set/init) that controls access to data, usually wrapping a private backing field. Properties support validation, computed values, access restrictions and are what frameworks like EF Core and JSON serializers bind to.
BasicWhat is constructor chaining?
Calling one constructor from another of the same class using : this(args), or the base class using : base(args). It keeps initialisation logic in one place.
IntermediateWhat are init-only setters and required members?
init (C# 9) allows a property to be set during construction or in an object initializer, then makes it immutable. required (C# 11) makes the compiler enforce that callers set the member in the initializer, unless a constructor marked [SetsRequiredMembers] does it.
IntermediateWhat are primary constructors in C# 12 and what is a pitfall?
They declare constructor parameters on the type declaration, available throughout the class body. The pitfall: the parameters are captured as hidden mutable fields, not properties. Using a parameter both to initialise a property and elsewhere creates two copies of the state, which is why the compiler warns (CS9124).
IntermediateCan a constructor be private? Why would you do that?
Yes. Private constructors prevent outside instantiation. They're used for static-only classes, the Singleton pattern, and factory methods like Order.Create(...) that validate or choose a subtype before constructing.
DAY 2 · TUE

Encapsulation, access modifiers and static members

GoalHide an object's internals behind a small, safe public surface, choose the right access modifier, and know when something belongs to the type instead of an instance.

Key definitions

Encapsulation
Bundling data with the methods that operate on it and hiding internal state so it can only change through valid operations.
Invariant
A rule that must always hold for an object, e.g. a bank balance is never negative.
Access modifier
A keyword that controls where a type or member can be used: public, private, protected, internal, protected internal, private protected, file.
public
Accessible from any code.
private
Accessible only inside the same class (the default for members).
protected
Accessible inside the class and classes that derive from it.
internal
Accessible anywhere in the same assembly (project). The default for top-level types.
protected internal
Same assembly OR derived classes in any assembly.
private protected
Derived classes in the same assembly only (C# 7.2).
file
Type visible only within its source file (C# 11), used mostly by source generators.
Static member
Belongs to the type itself, shared by all instances; accessed as TypeName.Member.
Static constructor
Parameterless constructor that runs once, automatically, before the type is first used.
Static class
A class that can't be instantiated or inherited and contains only static members.
static readonly
A field set once at runtime and shared by all instances; unlike const it can hold any type.
Namespace
A logical grouping of types that prevents name clashes, e.g. Library.Core.Models.
Quick notes
  • Make everything private first, then open up only what callers truly need.
  • Expose behaviour (Deposit, Withdraw) instead of raw setters (Balance = ...).
  • Return IReadOnlyList<T>, never your internal List<T>.
  • Static = one copy per type; instance = one copy per object.
  • Use static classes for stateless helpers; avoid static mutable state (hard to test, not thread-safe).
  • const for compile-time literals, static readonly for values computed at startup.

1. Encapsulation by example

Start with what goes wrong without it. With public fields, any caller can break the account's rules:

public class BadAccount
{
    public decimal Balance;            // anyone can write anything
}

var acc = new BadAccount();
acc.Balance = -50_000;                 // invariant broken, nobody stopped it

An encapsulated version exposes operations and keeps state private. Every change goes through code that enforces the rules.

BankAccount.cs
public class BankAccount
{
    private readonly List<string> _transactions = new();

    public string AccountNumber { get; }
    public string Owner { get; }
    public decimal Balance { get; private set; }               // read publicly, write privately
    public IReadOnlyList<string> Transactions => _transactions; // read-only view

    public BankAccount(string accountNumber, string owner, decimal openingBalance = 0)
    {
        ArgumentException.ThrowIfNullOrWhiteSpace(accountNumber);
        ArgumentException.ThrowIfNullOrWhiteSpace(owner);
        if (openingBalance < 0)
            throw new ArgumentOutOfRangeException(nameof(openingBalance));

        AccountNumber = accountNumber;
        Owner = owner;
        Balance = openingBalance;
        Log($"Opened with {openingBalance:N2}");
    }

    public void Deposit(decimal amount)
    {
        if (amount <= 0)
            throw new ArgumentOutOfRangeException(nameof(amount), "Deposit must be positive");
        Balance += amount;
        Log($"Deposit {amount:N2}");
    }

    public bool TryWithdraw(decimal amount)
    {
        if (amount <= 0 || amount > Balance) return false;   // invariant: never negative
        Balance -= amount;
        Log($"Withdraw {amount:N2}");
        return true;
    }

    private void Log(string message) => _transactions.Add($"{DateTime.Now:g}  {message}");
}
var account = new BankAccount("SB-00123", "Samrath", 5_000m);
account.Deposit(2_500m);
bool ok = account.TryWithdraw(10_000m);    // false — insufficient funds

Console.WriteLine($"{account.Balance:N2}"); // 7,500.00
foreach (var t in account.Transactions) Console.WriteLine(t);

// account.Balance = 1_000_000;            // ❌ setter is private
// account.Transactions.Add("hack");       // ❌ IReadOnlyList has no Add
Tip. Returning IReadOnlyList<T> stops casual mutation, but a determined caller could cast it back to List<T>. For a hard guarantee return _transactions.AsReadOnly() or a copy.

3. Static members

Instance members belong to each object. Static members belong to the type and exist once, no matter how many objects you create.

Customer.cs
public class Customer
{
    private static int _nextId = 1;           // shared counter
    public static int Count { get; private set; }

    public int Id { get; }                    // per-object
    public string Name { get; }

    public Customer(string name)
    {
        Id = _nextId++;
        Name = name;
        Count++;
    }

    // Static factory method: a named way to create objects
    public static Customer CreateGuest() => new("Guest");
}

var a = new Customer("Priya");
var b = new Customer("Karan");
var g = Customer.CreateGuest();

Console.WriteLine($"{a.Id} {b.Id} {g.Id}");   // 1 2 3
Console.WriteLine(Customer.Count);            // 3 — accessed through the TYPE
// a.Count                                    // ❌ can't access static via instance
Watch out. The _nextId++ counter above isn't thread-safe. Two threads could get the same id. You'll fix this with Interlocked.Increment in Week 7; in real apps the database generates ids.

Static constructors and static classes

public class AppInfo
{
    public static readonly string Environment;
    public static readonly DateTime StartedAt;

    // Runs exactly once, before the first access to AppInfo
    static AppInfo()
    {
        Environment = System.Environment.GetEnvironmentVariable("APP_ENV") ?? "Development";
        StartedAt = DateTime.UtcNow;
    }
}

public static class Gst                      // cannot be instantiated or inherited
{
    public const decimal StandardRate = 0.18m;
    public static decimal Add(decimal amount, decimal rate = StandardRate) => amount + amount * rate;
    public static decimal Extract(decimal grossAmount, decimal rate = StandardRate) => grossAmount - grossAmount / (1 + rate);
}

Console.WriteLine(Gst.Add(1000m));           // 1180.00
Console.WriteLine(AppInfo.Environment);      // Development

Common mistakes

  • Making everything public because it's easier right now.
  • Returning a mutable internal collection from a getter.
  • Storing per-user or per-request data in static fields — every user shares it.
  • Using public const in a shared library for values that may change.
  • Static classes that hold state; they can't be mocked in tests.

BasicWhat is encapsulation and why does it matter?
Encapsulation hides an object's internal state and exposes only controlled operations, so invariants can't be broken from outside. It reduces coupling: you can change the internals without changing callers, and bugs are localised to the class that owns the data.

DAY 3 · WED

Inheritance, base, virtual/override and sealed

GoalBuild a small class hierarchy, reuse and extend base behaviour correctly, and know when inheritance is the wrong tool.

Key definitions

Inheritance
A mechanism where a derived class acquires the members of a base class, modelling an "is-a" relationship.
Base class (parent)
The class being inherited from, e.g. Employee.
Derived class (child)
The class that inherits, e.g. Manager : Employee.
Single inheritance
C# classes can inherit from only one base class (but implement many interfaces).
base
Keyword to call the base class's constructor (: base(...)) or members (base.CalculatePay()).
virtual
Marks a base member that derived classes are allowed to override.
override
Replaces a virtual/abstract member's implementation in a derived class; resolved at runtime.
new (modifier)
Hides a base member with a new one; the call is resolved by the variable's compile-time type.
sealed class
A class that can't be inherited.
sealed override
An override that further-derived classes can't override again.
System.Object
The ultimate base of every type; provides ToString, Equals, GetHashCode, GetType.
Composition
Building a class from other objects it holds ("has-a") instead of inheriting from them.
Method resolution
Choosing which implementation runs: virtual calls use the object's runtime type.
Quick notes
  • Inherit only for genuine "is-a" relationships: a Manager is an Employee.
  • Base constructor runs before the derived constructor's body; pass arguments with : base(...).
  • A method must be virtual (or abstract) in the base before it can be overridden.
  • override = polymorphic; new = hiding, usually a smell.
  • Seal classes you didn't design for inheritance.
  • Prefer composition when you just want to reuse code.

1. A simple hierarchy

Employees.cs
public class Employee
{
    public string Name { get; }
    public decimal BaseSalary { get; }

    public Employee(string name, decimal baseSalary)
    {
        Name = name;
        BaseSalary = baseSalary;
        Console.WriteLine("  Employee constructor");
    }

    // virtual: derived classes MAY replace this
    public virtual decimal CalculatePay() => BaseSalary;

    public override string ToString() => $"{GetType().Name,-8} {Name,-8} pays {CalculatePay(),10:N0}";
}

public class Manager : Employee
{
    public decimal Bonus { get; }

    public Manager(string name, decimal baseSalary, decimal bonus)
        : base(name, baseSalary)                    // base constructor first
    {
        Bonus = bonus;
        Console.WriteLine("  Manager constructor");
    }

    // Extend the base behaviour instead of rewriting it
    public override decimal CalculatePay() => base.CalculatePay() + Bonus;
}

public sealed class Intern : Employee               // nobody can derive from Intern
{
    public Intern(string name) : base(name, 20_000m) { }
}
Console.WriteLine("Creating manager:");
var m = new Manager("Divya", 120_000m, 30_000m);
// Creating manager:
//   Employee constructor     ← base runs first
//   Manager constructor

Employee[] staff = [ new Employee("Arjun", 60_000m), m, new Intern("Zoya") ];
foreach (var e in staff) Console.WriteLine(e);
// Employee Arjun    pays     60,000
// Manager  Divya    pays    150,000   ← Manager's override ran via an Employee reference
// Intern   Zoya     pays     20,000

2. What a derived class gets

  • All public, protected and internal members of the base (private members exist in the object but aren't accessible).
  • Constructors are not inherited; each class declares its own and chains with : base(...).
  • If the base has no parameterless constructor, every derived constructor must call base(...) explicitly.
public class Vehicle
{
    protected int Wheels { get; }                 // visible to derived classes only
    private string _secret = "VIN-123";           // not accessible in Car

    protected Vehicle(int wheels) => Wheels = wheels;
}

public class Car : Vehicle
{
    public Car() : base(4) { }
    public string Describe() => $"Car with {Wheels} wheels";   // ✓ protected
    // public string Vin => _secret;                             // ❌ private in Vehicle
}

BasicWhat is inheritance and what are its benefits and drawbacks?
Inheritance lets a derived class reuse and specialise a base class (an is-a relationship). Benefits: code reuse and polymorphism. Drawbacks: tight coupling, fragile base class problem (base changes break children), and rigid hierarchies that are hard to refactor.
BasicWhat is the difference between virtual and abstract?

public abstract class Shape
{
    public string Name { get; }

    protected Shape(string name) => Name = name;    // protected: only subclasses call it

    public abstract double Area();                  // no body — must be overridden
    public abstract double Perimeter();

    public virtual string Describe() => $"{Name,-9} area {Area(),8:F2}  perimeter {Perimeter(),7:F2}";
}

public class Circle(double radius) : Shape("Circle")
{
    public double Radius => radius;
    public override double Area() => Math.PI * radius * radius;
    public override double Perimeter() => 2 * Math.PI * radius;
}

public class Rectangle(double width, double height) : Shape("Rectangle")
{
    public double Width => width;
    public double Height => height;
    public override double Area() => width * height;
    public override double Perimeter() => 2 * (width + height);
}

public class Triangle(double a, double b, double c) : Shape("Triangle")
{
    public override double Perimeter() => a + b + c;
    public override double Area()
    {
        double s = Perimeter() / 2;                               // Heron's formula
        return Math.Sqrt(s * (s - a) * (s - b) * (s - c));
    }
}

3. Template Method: a real-world abstract class

Payment flows share the same steps (validate amount, run checks, charge, add fees) but each method does the specifics differently. The base class owns the algorithm; subclasses fill in the blanks.

Payments.cs
public record PaymentResult(bool Success, string? Reference, decimal Charged, string? Error)
{
    public static PaymentResult Ok(string reference, decimal charged) => new(true, reference, charged, null);
    public static PaymentResult Fail(string error) => new(false, null, 0, error);
}

public abstract class PaymentProcessor
{
    // Template method: NOT virtual — the order of steps is fixed
    public PaymentResult Process(decimal amount)
    {
        if (amount <= 0) return PaymentResult.Fail("Amount must be positive");
        if (!Validate(amount)) return PaymentResult.Fail($"{Method} rejected {amount:N2}");

        string reference = Charge(amount);
        return PaymentResult.Ok(reference, amount + Fee(amount));
    }

    protected abstract string Method { get; }               // required
    protected abstract bool Validate(decimal amount);       // required
    protected abstract string Charge(decimal amount);       // required
    protected virtual decimal Fee(decimal amount) => 0m;    // optional hook
}

public class UpiProcessor : PaymentProcessor
{
    protected override string Method => "UPI";
    protected override bool Validate(decimal amount) => amount <= 100_000m;     // typical per-transaction cap
    protected override string Charge(decimal amount) => "UPI-" + Guid.NewGuid().ToString("N")[..10];
}

public class CardProcessor : PaymentProcessor
{
    protected override string Method => "Card";
    protected override bool Validate(decimal amount) => true;
    protected override string Charge(decimal amount) => "CARD-" + Random.Shared.Next(100_000, 999_999);
    protected override decimal Fee(decimal amount) => Math.Round(amount * 0.02m, 2);   // 2% fee
}
PaymentProcessor[] processors = [ new UpiProcessor(), new CardProcessor() ];

foreach (var p in processors)
{
    var r = p.Process(150_000m);
    Console.WriteLine(r.Success ? $"✓ {r.Reference} charged {r.Charged:N2}" : $"✗ {r.Error}");
}
// ✗ UPI rejected 150,000.00
// ✓ CARD-482913 charged 153,000.00

4. Type checks and casting

Sometimes you genuinely need subtype-specific data. Use pattern matching, not blind casts.

Shape shape = new Circle(12);

// Upcast: implicit, always safe

// Downcast with a cast: throws InvalidCastException if wrong

// `as`: returns null instead of throwing (reference types only)

    Console.WriteLine($"Radius {c.Radius}");

{
    Circle { Radius: > 10 }                     => "Large circle",

public readonly struct Money(decimal amount, string currency)
{

using Library.Core.Interfaces;

namespace Library.Core.Models;

public abstract class LibraryItem : ISearchable
{
    private static int _nextId = 1;

    public int Id { get; }
    public string Title { get; }
    public int Year { get; }
    public bool IsAvailable { get; internal set; } = true;   // only Library.Core can change it

    protected LibraryItem(string title, int year)
    {
        ArgumentException.ThrowIfNullOrWhiteSpace(title);
        if (year < 1450 || year > DateTime.Today.Year)
            throw new ArgumentOutOfRangeException(nameof(year), $"Year must be between 1450 and {DateTime.Today.Year}");

        Id = _nextId++;
        Title = title.Trim();
        Year = year;
    }

    public abstract int LoanDays { get; }        // every type MUST decide
    public abstract string Kind { get; }
    public virtual decimal LateFeePerDay => 5m;  // sensible default, may override

    public virtual bool Matches(string term) =>
        Title.Contains(term, StringComparison.OrdinalIgnoreCase);

    public override string ToString() =>
        $"#{Id,-3} {Kind,-8} {Title} ({Year})  [{(IsAvailable ? "available" : "on loan")}]";
}

namespace Library.Core.Services;

public class InMemoryCatalog : ICatalog
{
    private readonly List<LibraryItem> _items = [];
    private readonly List<Member> _members = [];

    public IReadOnlyList<LibraryItem> Items => _items.AsReadOnly();
    public IReadOnlyList<Member> Members => _members.AsReadOnly();

    public void AddItem(LibraryItem item)
    {
        ArgumentNullException.ThrowIfNull(item);
        if (item is Book book && _items.OfType<Book>().Any(b => b.Isbn == book.Isbn))
            throw new InvalidOperationException($"A book with ISBN {book.Isbn} already exists");
        _items.Add(item);
    }

    public void AddMember(Member member)
    {
        ArgumentNullException.ThrowIfNull(member);
        if (_members.Any(m => m.Email == member.Email))
            throw new InvalidOperationException($"{member.Email} is already registered");
        _members.Add(member);
    }

    public LibraryItem? FindItem(int id) => _items.FirstOrDefault(i => i.Id == id);
    public Member? FindMember(int id) => _members.FirstOrDefault(m => m.Id == id);
}

BasicWhy is LibraryItem abstract rather than concrete?
No real item is just a 'library item'; every one is a book, magazine or DVD. Making it abstract prevents meaningless instances and forces each subtype to define LoanDays and Kind.
BasicWhy does Program.cs declare ICatalog instead of InMemoryCatalog?
So the app depends on the contract only. Replacing storage with a database later (Week 15) means writing a new ICatalog implementation and changing one line, not the whole app.
IntermediateWhy is IsAvailable's setter internal?
Only the domain/service layer in Library.Core should change availability, through borrow/return rules. internal blocks the console app or any other assembly from flipping it directly and bypassing those rules.
IntermediateHow would you add a new item type without modifying existing code?
Create a new class deriving from LibraryItem and override the abstract members. Listing, searching and (tomorrow) borrowing all work through the base type, so nothing else changes. That's the Open/Closed Principle.

2. Loan and Result

Library.Core/Models/Loan.cs
namespace Library.Core.Models;

public class Loan
{
    public LibraryItem Item { get; }
    public Member Member { get; }
    public DateOnly BorrowedOn { get; }
    public DateOnly DueOn { get; }
    public DateOnly? ReturnedOn { get; private set; }
    public bool IsOpen => ReturnedOn is null;

    public Loan(LibraryItem item, Member member, DateOnly borrowedOn)
    {
        Item = item;
        Member = member;
        BorrowedOn = borrowedOn;
        DueOn = borrowedOn.AddDays(item.LoanDays);     // polymorphic: 14, 7 or 3 days
    }

    public int DaysOverdue(DateOnly today) => Math.Max(0, today.DayNumber - DueOn.DayNumber);

    // Closes the loan and returns the late fee
    public decimal Close(DateOnly returnedOn)
    {
        if (!IsOpen) throw new InvalidOperationException("Loan is already closed");
        ReturnedOn = returnedOn;
        return DaysOverdue(returnedOn) * Item.LateFeePerDay;   // polymorphic fee
    }

    public override string ToString() =>
        $"{Item.Title} → {Member.Name}, due {DueOn:dd MMM}" + (IsOpen ? "" : $", returned {ReturnedOn:dd MMM}");
}

3. LibraryService — the business rules

Library.Core/Services/LibraryService.cs
using Library.Core.Interfaces;
using Library.Core.Models;

namespace Library.Core.Services;

public class LibraryService(ICatalog catalog, IClock clock)
{
    private readonly List<Loan> _loans = [];

    public IReadOnlyList<Loan> OpenLoans => _loans.Where(l => l.IsOpen).ToList();

    public IReadOnlyList<Loan> Overdue => _loans.Where(l => l.IsOpen && l.DaysOverdue(clock.Today) > 0).ToList();

    public Result<Loan> Borrow(int memberId, int itemId)
    {
        Member? member = catalog.FindMember(memberId);
        if (member is null) return Result<Loan>.Fail($"No member with id {memberId}");

        LibraryItem? item = catalog.FindItem(itemId);
        if (item is null) return Result<Loan>.Fail($"No item with id {itemId}");
        if (!item.IsAvailable) return Result<Loan>.Fail($"'{item.Title}' is already on loan");

        int active = _loans.Count(l => l.IsOpen && l.Member.Id == member.Id);
        if (active >= Member.MaxLoans)
            return Result<Loan>.Fail($"{member.Name} already has {Member.MaxLoans} items out");

        if (_loans.Any(l => l.IsOpen && l.Member.Id == member.Id && l.DaysOverdue(clock.Today) > 0))
            return Result<Loan>.Fail($"{member.Name} has an overdue item; return it first");

        var loan = new Loan(item, member, clock.Today);
        item.IsAvailable = false;                 // allowed: same assembly (internal set)
        _loans.Add(loan);
        return Result<Loan>.Ok(loan);
    }

    public Result<decimal> Return(int itemId)
    {
        Loan? loan = _loans.FirstOrDefault(l => l.IsOpen && l.Item.Id == itemId);
        if (loan is null) return Result<decimal>.Fail($"Item {itemId} isn't on loan");

        decimal fee = loan.Close(clock.Today);
        loan.Item.IsAvailable = true;
        return Result<decimal>.Ok(fee);
    }

    // One search over everything that implements ISearchable
    public IReadOnlyList<ISearchable> Search(string term)
    {
        if (string.IsNullOrWhiteSpace(term)) return [];
        var results = new List<ISearchable>();
        foreach (LibraryItem item in catalog.Items) if (item.Matches(term)) results.Add(item);
        foreach (Member member in catalog.Members) if (member.Matches(term)) results.Add(member);
        return results;
    }
}

Interview questions

Answer out loud first, then open each one to compare.

BasicWhy return a Result object instead of throwing an exception when an item is already on loan?
An item being on loan is an expected business outcome, not an error in the program. Exceptions are slower, hide control flow and are meant for exceptional situations. A Result makes the failure explicit in the method signature and forces callers to handle it.
BasicWhy inject IClock instead of calling DateTime.Today?
Direct calls to static time make code non-deterministic and hard to test. With IClock, tests and demos can control the date (ManualClock) to verify due dates and late fees instantly.
IntermediateWhere should business rules like 'max 3 loans' live, and why?
In the domain/service layer (LibraryService, Member.MaxLoans), not the UI. Then every client — console today, Web API later — enforces the same rules, and the rules can be unit-tested in isolation.
IntermediateHow does polymorphism show up in the late-fee calculation?
Loan.Close multiplies days overdue by Item.LateFeePerDay, and DueOn uses Item.LoanDays. Both are virtual/abstract members, so a Book, Magazine or DVD each supply their own values with no if/else on type.
