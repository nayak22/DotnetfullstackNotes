DAY 1 · MON

Background Services and Channels

GoalWire up IHostedService and BackgroundService for long-running work inside an ASP.NET Core app, guard workers against crashes, and pass work items between threads with System.Threading.Channels.

Key definitions

IHostedService
Interface with StartAsync and StopAsync; called by the host at application start and shutdown.
BackgroundService
Abstract base class implementing IHostedService; you override ExecuteAsync(CancellationToken).
PeriodicTimer
A .NET 6+ timer designed for loops: await timer.WaitForNextTickAsync(ct) skips ticks that were missed instead of piling them up.
IServiceScopeFactory
Factory that creates a DI scope; workers are singletons, so they must resolve scoped services (DbContext, repositories) through a fresh scope per unit of work.
Channel<T>
A thread-safe, async-first pipe for producer/consumer messaging. Channel.CreateBounded<T> limits backpressure.
ChannelWriter<T>
The producer side: TryWrite (non-blocking) or WriteAsync (back-pressure-aware).
ChannelReader<T>
The consumer side: await reader.ReadAsync(ct) or await foreach (var item in reader.ReadAllAsync(ct)).
CancellationToken
Propagated from the host's StoppingToken; every async call in a worker should accept and honour it.
StoppingToken
The BackgroundService property that is cancelled when the host begins graceful shutdown.
IServiceScope
Short-lived DI container child; always disposed in a using block to free scoped resources like DbContext.
Never-die error handling
A try/catch around the inner loop so an unexpected exception is logged but the worker restarts rather than crashing the whole app.
AddHostedService<T>
Registers a hosted service with the DI container; works for both IHostedService and BackgroundService implementations.
Quick notes
  • The host calls StartAsync on all hosted services before accepting HTTP requests.
  • ExecuteAsync blocks startup if it doesn't return quickly; await your first real async op immediately.
  • Never inject a DbContext directly into a singleton worker — always create a scope.
  • PeriodicTimer fires one tick at a time; it cannot queue up multiple ticks, so a slow handler doesn't pile up work.
  • Channels replace BlockingCollection<T> (synchronous, thread-blocking); they are async-native and compose well with await.
  • Always call channel.Writer.Complete() when the producer is done so the consumer's ReadAllAsync exits cleanly.

2. BackgroundService with PeriodicTimer

A common pattern: poll a database table or external API on a schedule without a heavy scheduler library.

StockAlertWorker.cs
using Microsoft.Extensions.DependencyInjection;
using Microsoft.Extensions.Hosting;
using Microsoft.Extensions.Logging;

public sealed class StockAlertWorker : BackgroundService
{
    private readonly IServiceScopeFactory _scopes;
    private readonly ILogger<StockAlertWorker> _log;

    public StockAlertWorker(IServiceScopeFactory scopes, ILogger<StockAlertWorker> log)
        => (_scopes, _log) = (scopes, log);

    protected override async Task ExecuteAsync(CancellationToken ct)
    {
        // Yield immediately so the host finishes starting other services
        await Task.Yield();

        using var timer = new PeriodicTimer(TimeSpan.FromMinutes(5));

        while (await timer.WaitForNextTickAsync(ct))   // returns false when ct is cancelled
        {
            try
            {
                await CheckLowStockAsync(ct);
            }
            catch (OperationCanceledException) when (ct.IsCancellationRequested)
            {
                break;   // graceful shutdown
            }
            catch (Exception ex)
            {
                _log.LogError(ex, "StockAlertWorker iteration failed; will retry on next tick");
                // ✓ do NOT rethrow — let the loop continue
            }
        }
    }

    private async Task CheckLowStockAsync(CancellationToken ct)
    {
        await using var scope = _scopes.CreateAsyncScope();
        var db = scope.ServiceProvider.GetRequiredService<AppDbContext>();

        var low = await db.Products
            .Where(p => p.StockQty < p.ReorderLevel)
            .ToListAsync(ct);

        foreach (var p in low)
            _log.LogWarning("Low stock: {Sku} — {Qty} units left", p.Sku, p.StockQty);
    }
}
Avoid. Injecting DbContext (or any scoped service) directly into a background worker throws at startup because the worker is a singleton. Always use IServiceScopeFactory.

3. Never-die error handling pattern

NeverDiePattern.cs
protected override async Task ExecuteAsync(CancellationToken ct)
{
    while (!ct.IsCancellationRequested)
    {
        try
        {
            await DoWorkLoopAsync(ct);
            // If DoWorkLoopAsync returns normally (should not under normal ops), restart it
        }
        catch (OperationCanceledException) when (ct.IsCancellationRequested)
        {
            break;   // expected during shutdown
        }
        catch (Exception ex)
        {
            _log.LogError(ex, "Worker crashed; restarting in 10 s");
            try { await Task.Delay(TimeSpan.FromSeconds(10), ct); }
            catch (OperationCanceledException) { break; }
        }
    }

    async Task DoWorkLoopAsync(CancellationToken innerCt)
    {
        // actual work; may throw any exception
        while (!innerCt.IsCancellationRequested)
        {
            await ProcessNextBatch(innerCt);
        }
    }
}
Tip. Log the exception before sleeping, not after. If shutdown happens during the sleep the second log never fires.

4. Channels: producer/consumer queue

An order import endpoint receives CSV rows; a background worker saves them to SQL Server. The Channel decouples ingestion speed from database write speed.

OrderImportQueue.cs
// Shared abstraction — register as a singleton
public sealed class OrderImportQueue
{
    private readonly Channel<ImportRow> _channel;
    public ChannelWriter<ImportRow> Writer => _channel.Writer;
    public ChannelReader<ImportRow> Reader => _channel.Reader;

    public OrderImportQueue()
    {
        // BoundedChannelOptions: when full, Writer.WriteAsync waits (backpressure)
        _channel = Channel.CreateBounded<ImportRow>(new BoundedChannelOptions(500)
        {
            FullMode = BoundedChannelFullMode.Wait,
            SingleReader = true
        });
    }
}
ImportEndpoint.cs
// Producer: minimal API endpoint
app.MapPost("/orders/import", async (IFormFile csv, OrderImportQueue queue, CancellationToken ct) =>
{
    using var reader = new StreamReader(csv.OpenReadStream());
    int lineNo = 0;
    while (await reader.ReadLineAsync(ct) is { } line)
    {
        lineNo++;
        if (lineNo == 1) continue;   // skip header
        var parts = line.Split(',');
        if (parts.Length < 3) continue;
        await queue.Writer.WriteAsync(new ImportRow(parts[0], decimal.Parse(parts[1]), int.Parse(parts[2])), ct);
    }
    return Results.Accepted("/orders/import/status");
});
OrderImportWorker.cs
// Consumer: background service
public sealed class OrderImportWorker : BackgroundService
{
    private readonly OrderImportQueue _queue;
    private readonly IServiceScopeFactory _scopes;
    private readonly ILogger<OrderImportWorker> _log;

    public OrderImportWorker(OrderImportQueue queue, IServiceScopeFactory scopes,
        ILogger<OrderImportWorker> log)
        => (_queue, _scopes, _log) = (queue, scopes, log);

    protected override async Task ExecuteAsync(CancellationToken ct)
    {
        await foreach (var row in _queue.Reader.ReadAllAsync(ct))
        {
            try
            {
                await using var scope = _scopes.CreateAsyncScope();
                var db = scope.ServiceProvider.GetRequiredService<AppDbContext>();
                db.OrderRows.Add(new OrderRow { Sku = row.Sku, UnitPrice = row.UnitPrice, Qty = row.Qty });
                await db.SaveChangesAsync(ct);
            }
            catch (Exception ex)
            {
                _log.LogError(ex, "Failed to persist row {Sku}", row.Sku);
            }
        }
    }
}

public record ImportRow(string Sku, decimal UnitPrice, int Qty);

Common mistakes

  • Injecting a scoped service (DbContext) directly into the worker singleton.
  • Letting an unhandled exception in ExecuteAsync bubble up — the host crashes (pre-.NET 6) or the worker silently stops.
  • Not propagating the CancellationToken into every async call; app shutdown hangs for 5 s waiting.
  • Creating a scope in the constructor instead of per work-unit; the scope lives forever and leaks connections.
  • Using Thread.Sleep inside a hosted service instead of await Task.Delay.

Self-check questions

What is the difference between IHostedService and BackgroundService?IHostedService is the two-method interface. BackgroundService is an abstract implementation that runs ExecuteAsync in the background and wires CancellationToken, StoppingToken and disposal for you.
Why use IServiceScopeFactory in a worker?Workers are singletons; DbContext and other scoped services must not be injected directly (lifetime mismatch). IServiceScopeFactory creates a fresh child container per unit of work, then disposes it.
What advantage does PeriodicTimer have over Timer?It fires one tick at a time and skips missed ticks, so a slow iteration doesn't queue up N pending callbacks. It also integrates naturally with async/await and CancellationToken.

Interview questions

Answer out loud first, then open each one to compare.

BasicWhat is a background service in ASP.NET Core?
A class that runs alongside the web server in the same process. It implements IHostedService (or BackgroundService). The host starts it before serving HTTP and stops it gracefully on shutdown.
BasicHow do you schedule repeated work inside a BackgroundService?
Use PeriodicTimer: create it with the interval, then loop with await timer.WaitForNextTickAsync(ct). When ct is cancelled the method returns false and the loop exits cleanly.
IntermediateWhat is System.Threading.Channels and when is it better than a ConcurrentQueue?
Channels add async producer/consumer semantics, back-pressure (bounded) and cooperative cancellation. ConcurrentQueue is sync-only; consuming it requires spinning or blocking. Channels compose naturally with async workflows.
IntermediateHow do you gracefully stop a BackgroundService?
The host cancels the BackgroundService.StoppingToken. Any await that accepts it throws OperationCanceledException, which you catch to exit the loop. The host then calls StopAsync and waits (default 5 s) for ExecuteAsync to finish.
IntermediateWhat is back-pressure and how does BoundedChannel enforce it?
Back-pressure slows the producer when the consumer falls behind. A BoundedChannel with FullMode.Wait makes WriteAsync pause until a slot is free, preventing unlimited memory growth.
AdvancedA background worker crashes repeatedly. How do you prevent cascading restarts from flooding the log?
Implement exponential back-off: catch the exception, multiply the delay by 2 each crash up to a maximum (e.g. 60 s), log a warning not an error after the first crash. Reset the delay to minimum after a successful iteration.
DAY 2 · TUE

Hangfire: Reliable Background Jobs

GoalReplace fire-and-forget background threads with Hangfire — durable, retriable, dashboard-visible jobs backed by SQL Server, covering fire-and-forget, delayed, recurring (IST cron), continuations and security.

Key definitions

Hangfire
An open-source library for persistent background job processing in .NET; jobs survive app restarts because they are stored in SQL Server before execution.
Storage
Hangfire creates its own schema (HangFire.*) in SQL Server on first run; every job state transition is written there.
Fire-and-forget job
A job queued with BackgroundJob.Enqueue; executed once as soon as a worker is free.
Delayed job
A job queued with BackgroundJob.Schedule; executed after a specified delay.
Recurring job
A job registered with RecurringJob.AddOrUpdate; runs on a cron expression, optionally in a specific timezone.
Continuation
A job queued with BackgroundJob.ContinueJobWith; runs after a parent job succeeds.
Hangfire Server
The in-process component that polls for due jobs and executes them. app.UseHangfireServer().
Hangfire Dashboard
A middleware-mounted web UI at /hangfire showing queues, jobs and retries. app.UseHangfireDashboard().
Idempotency
Designing a job so that running it twice produces the same result; important because Hangfire may retry on failure.
Retry policy
Hangfire retries a failed job up to 10 times by default, with exponential back-off. Configure globally with [AutomaticRetry].
IBackgroundJobClient
DI-injectable interface for enqueueing jobs; preferred over static BackgroundJob in testable code.
Quartz.NET
An alternative .NET scheduler with cron-first design, clustered execution and persistent triggers; heavier than Hangfire but more flexible for complex schedules.
Quick notes
  • Hangfire jobs must be idempotent: on retry the second run should not send two emails or charge twice.
  • Use method expressions (() => service.DoWork(id)), not lambdas with captured objects; Hangfire serialises the method name and arguments, not the closure.
  • The dashboard is public by default — always add an authorization filter in production.
  • Recurring jobs run in UTC internally; convert to IST using TimeZoneInfo in the cron registration.
  • Continuations let you model a pipeline: generate report → send email → archive.
  • Use IBackgroundJobClient and IRecurringJobManager for DI-friendly, testable code.

Self-check questions

What makes a Hangfire job durable?It is serialised to SQL Server before the worker picks it up. If the app crashes after enqueueing but before execution, the job is still in the database and will run when the app restarts.
What is the default retry behaviour?Hangfire retries up to 10 times with exponential back-off (around 1 min, 4 min, 10 min…). Override with [AutomaticRetry(Attempts = 3)].
BackgroundService vs Hangfire?BackgroundService is built-in and good for continuous workers (polling, channels). Hangfire adds persistence, retries, cron scheduling, a dashboard and distributed execution across multiple app instances.

BasicWhat is Hangfire and what problem does it solve?
Hangfire is a persistent background job library. It solves the problem of tasks lost on app crash: every job is written to SQL Server before execution, so it survives restarts.
BasicWhat is a recurring job in Hangfire?
A job registered with RecurringJob.AddOrUpdate that fires on a cron schedule. Hangfire stores the last run time and next due time in SQL Server and handles timezone conversion.
IntermediateHow does Hangfire differ from Quartz.NET?
Hangfire is simpler to set up, has a built-in dashboard and suits most apps. Quartz.NET is more powerful for complex schedules (misfire policies, clustered triggers, job stores) and suits enterprise scheduling needs.
IntermediateHow do you make a Hangfire job idempotent?
Before doing the real work, check a durable log (a database flag, a Redis key) to see if this exact operation was already completed; if so, return early. The check-and-mark must be in the same transaction or use compare-and-swap.
IntermediateExplain Hangfire continuations.
A continuation is a job that is enqueued only after its parent job succeeds. Chain them with BackgroundJob.ContinueJobWith(parentJobId, ...). If the parent fails, the continuation is never started.
AdvancedHow would you run Hangfire workers in a separate microservice?
Install Hangfire.SqlServer in both the web app (storage only, no server) and a dedicated worker process (server only). Both share the same SQL Server database. The web app enqueues; the worker processes. Scale the worker independently.

Sending Email with MailKit

GoalSend plain-text and HTML emails using MailKit, test locally with Mailpit in Docker, build a reusable IEmailSender service, and keep credentials in user-secrets.

Key definitions

MailKit
A cross-platform .NET library for SMTP, IMAP and POP3; the recommended replacement for System.Net.Mail.SmtpClient which is deprecated for async use.
MimeMessage
MailKit's message class. Set From, To, Subject and Body (via BodyBuilder).
BodyBuilder
A helper inside MailKit for building multipart messages: HtmlBody and TextBody together create a multipart/alternative body so plain-text clients get readable text.
SmtpClient (MailKit)
MailKit.Net.Smtp.SmtpClient — not the same as System.Net.Mail.SmtpClient. Always use the MailKit one.
STARTTLS
A protocol upgrade that starts on the plain port (587) and upgrades to TLS. MailKit uses SecureSocketOptions.StartTls.
Mailpit
A local SMTP fake server with a web UI at port 8025; catches emails instead of sending them. Replaces smtp4dev; both work fine.
smtp4dev
Another popular local SMTP trap. Docker image: rnwood/smtp4dev.
User-secrets
dotnet user-secrets set stores credentials outside source control in %APPDATA%/Microsoft/UserSecrets.
IEmailSender
A custom interface (or ASP.NET Core Identity's built-in one) that abstracts sending; lets you swap MailKit for SendGrid in tests or staging.
EmailOptions
A strongly typed options class for SMTP host, port, sender address and credentials — bound via builder.Services.Configure<EmailOptions>.
Quick notes
  • System.Net.Mail.SmtpClient lacks a proper async implementation; it blocks a thread pool thread. Always use MailKit.
  • Always build a multipart/alternative body (BodyBuilder.HtmlBody + BodyBuilder.TextBody) so email clients that don't render HTML still show something.
  • Use a using block for MailKit.Net.Smtp.SmtpClient; it owns a socket.
  • Keep SMTP passwords in user-secrets or Azure Key Vault, never in appsettings.json checked into Git.
  • Test locally with Mailpit (port 1025 SMTP, 8025 web UI) before connecting to a real relay.
  • For production in India common choices are AWS SES (cheapest), SendGrid, or Brevo (formerly Sendinblue).

// A thread-safe connection map (in-memory, single server)
public sealed class ConnectionMap
{
    private readonly ConcurrentDictionary<string, HashSet<string>> _userToConnections = new();
    private readonly object _lock = new();

    public void Add(string userId, string connectionId)
    {
        lock (_lock)
        {
            if (!_userToConnections.TryGetValue(userId, out var set))
                _userToConnections[userId] = set = new HashSet<string>();
            set.Add(connectionId);
        }
    }

    public void Remove(string userId, string connectionId)
    {
        lock (_lock)
        {
            if (_userToConnections.TryGetValue(userId, out var set))
            {
                set.Remove(connectionId);
                if (set.Count == 0) _userToConnections.TryRemove(userId, out _);
            }
        }
    }

    public IReadOnlySet<string> GetConnections(string userId) =>
        _userToConnections.TryGetValue(userId, out var set) ? set : new HashSet<string>();

    public IReadOnlyCollection<string> OnlineUsers => _userToConnections.Keys.ToList();
}

using Dapper;
using Microsoft.Data.SqlClient;

namespace ReportMailer.Data;

public sealed record SaleRow(string City, int Orders, decimal Total);

public sealed class SalesQuery(string connString)
{
    public async Task<IReadOnlyList<SaleRow>> GetDailySummaryAsync(DateOnly date,
        CancellationToken ct = default)
    {
        await using var conn = new SqlConnection(connString);
        const string sql =
            "SELECT CityName AS City, COUNT(*) AS Orders, SUM(TotalAmount) AS Total " +
            "FROM Orders WHERE OrderDate = @Date " +
            "GROUP BY CityName ORDER BY Total DESC;";

        var rows = await conn.QueryAsync<SaleRow>(
            new CommandDefinition(sql, new { Date = date.ToDateTime(TimeOnly.MinValue) },
                cancellationToken: ct));
        return rows.ToList();
    }
}

namespace ReportMailer.Jobs;

public sealed class DailySalesReportJob(
    SalesQuery query,
    IEmailSender mailer,
    IConfiguration config,
    ILogger<DailySalesReportJob> log)
{
    [AutomaticRetry(Attempts = 3)]
    public async Task RunAsync(CancellationToken ct = default)
    {
        var date = DateOnly.FromDateTime(DateTime.Today);
        log.LogInformation("Running daily sales report for {Date}", date);

        var rows = await query.GetDailySummaryAsync(date, ct);

        if (rows.Count == 0)
        {
            log.LogWarning("No sales data for {Date} — skipping email", date);
            return;
        }

        string html = SalesReportTemplate.Build(date, rows);
        string to   = config["ReportEmail:To"] ?? "cfo@acme.in";

        await mailer.SendAsync(
            to, "CFO",
            subject: $"Daily Sales Report — {date:dd MMM yyyy}",
            htmlBody: html,
            textBody: $"Sales report for {date:dd MMM yyyy}. Total: Rs. {rows.Sum(r => r.Total):N2}",
            ct);

        log.LogInformation("Sales report emailed to {To}", to);
    }
}

Hubs/ChatHub.cs
using Microsoft.AspNetCore.Authorization;
using Microsoft.AspNetCore.SignalR;

[Authorize]
public sealed class ChatHub : Hub<IChatClient>
{
    private readonly ConnectionMap _map;
    private readonly IServiceScopeFactory _scopes;
    private readonly ILogger<ChatHub> _log;

    public ChatHub(ConnectionMap map, IServiceScopeFactory scopes, ILogger<ChatHub> log)
        => (_map, _scopes, _log) = (map, scopes, log);

    // ── Connection lifecycle ──────────────────────────────────────────────
    public override async Task OnConnectedAsync()
    {
        _map.Add(Context.UserIdentifier!, Context.ConnectionId);
        await Clients.Others.UserOnline(Context.UserIdentifier!);
        await base.OnConnectedAsync();
    }

    public override async Task OnDisconnectedAsync(Exception? e)
    {
        _map.Remove(Context.UserIdentifier!, Context.ConnectionId);
        await Clients.Others.UserOffline(Context.UserIdentifier!);
        await base.OnDisconnectedAsync(e);
    }

    // ── Rooms ─────────────────────────────────────────────────────────────
    public async Task JoinRoom(string room)
    {
        await Groups.AddToGroupAsync(Context.ConnectionId, room);

        // Load last 50 messages for this room from DB
        await using var scope = _scopes.CreateAsyncScope();
        var db = scope.ServiceProvider.GetRequiredService<ChatDbContext>();
        var history = await db.Messages
            .Where(m => m.Room == room)
            .OrderByDescending(m => m.SentAt)
            .Take(50)
            .OrderBy(m => m.SentAt)
            .Select(m => new MessageDto(m.SenderId, m.SenderName, m.Body, m.SentAt))
            .ToListAsync();

        await Clients.Caller.RoomHistory(room, history);
        await Clients.OthersInGroup(room).UserJoinedRoom(Context.UserIdentifier!, room);
    }

    public async Task LeaveRoom(string room)
    {
        await Groups.RemoveFromGroupAsync(Context.ConnectionId, room);
        await Clients.Group(room).UserLeftRoom(Context.UserIdentifier!, room);
    }

    // ── Messages ──────────────────────────────────────────────────────────
    public async Task SendToRoom(string room, string body)
    {
        var msg = new ChatMessage
        {
            Room       = room,
            SenderId   = Context.UserIdentifier!,
            SenderName = Context.User!.Identity!.Name!,
            Body       = body,
            SentAt     = DateTime.UtcNow
        };

        await using var scope = _scopes.CreateAsyncScope();
        var db = scope.ServiceProvider.GetRequiredService<ChatDbContext>();
        db.Messages.Add(msg);
        await db.SaveChangesAsync();

        await Clients.Group(room).ReceiveMessage(
            new MessageDto(msg.SenderId, msg.SenderName, body, msg.SentAt));
    }

    public async Task SendDirect(string targetUserId, string body)
    {
        // Clients.User uses IUserIdProvider → all tabs of that user
        await Clients.User(targetUserId).ReceiveDm(
            Context.UserIdentifier!, Context.User!.Identity!.Name!, body, DateTime.UtcNow);
    }

    public async Task Typing(string room) =>
        await Clients.OthersInGroup(room).UserTyping(Context.UserIdentifier!);
}

// Client-side method contract
public interface IChatClient
{
    Task ReceiveMessage(MessageDto msg);
    Task ReceiveDm(string fromId, string fromName, string body, DateTime at);
    Task RoomHistory(string room, List<MessageDto> history);
    Task UserJoinedRoom(string userId, string room);
    Task UserLeftRoom(string userId, string room);
    Task UserTyping(string userId);
    Task UserOnline(string userId);
    Task UserOffline(string userId);
}
