DAY 1 · MON

CLR, IL, JIT, assemblies and NuGet packages

GoalExplain what happens between writing C# and the CPU running it, read a little IL, know your JIT and AOT options, and manage NuGet dependencies safely.

Key definitions

CLR
Common Language Runtime: the virtual machine that loads assemblies, JIT-compiles IL, manages memory with the GC, enforces type safety and handles exceptions and threads.
IL / CIL
Intermediate Language: the CPU-independent, stack-based instruction set the C# compiler (Roslyn) emits into a .dll.
JIT compiler
Just-In-Time compiler (RyuJIT) that turns a method's IL into native machine code the first time the method is called.
Tiered compilation
On by default since .NET Core 3.0: methods first get a quick, unoptimised Tier 0 compile; hot methods (called ~30 times) are recompiled in the background at optimised Tier 1.
Dynamic PGO
Profile-Guided Optimisation at runtime: Tier 0 code records which types and branches are actually used, and Tier 1 optimises for them. On by default in .NET 8.
OSR
On-Stack Replacement (.NET 7+): lets a long-running loop inside a Tier 0 method jump into optimised code without waiting for the method to be called again.
ReadyToRun (R2R)
Ahead-of-time pre-compiled native code stored inside the assembly alongside IL, to cut startup JIT time. The JIT can still re-optimise hot methods.
Native AOT
Publishing the whole app as one native executable with no JIT and no IL at runtime (.NET 7+ for console apps, .NET 8 adds ASP.NET Core minimal APIs). Fast startup, small memory, but limited reflection and no dynamic code.
Assembly
The unit of deployment and versioning in .NET: a .dll or .exe containing IL, metadata and a manifest.
Metadata
Tables inside an assembly describing every type, method, field, attribute and reference. Reflection and IntelliSense read it.
Manifest
Part of the metadata describing the assembly itself: name, version, culture and the assemblies it references.
NuGet package
A .nupkg (zip) containing compiled assemblies per target framework plus a .nuspec describing its dependencies.
PackageReference
The csproj item that declares a NuGet dependency: <PackageReference Include="Serilog" Version="4.0.0" />.
Transitive dependency
A package you get indirectly because a package you referenced depends on it.
Central Package Management
Declaring all package versions once in Directory.Packages.props so every project in a solution uses the same version.
Quick notes
  • C# → (Roslyn) → IL in a .dll → (CLR loads it) → JIT → native code. Only the last step is CPU-specific.
  • The same .dll runs on Windows, Linux and macOS because it contains IL, not machine code.
  • Every .NET language (C#, F#, VB) compiles to the same IL, which is why they can call each other.
  • Tier 0 → Tier 1 is why the first few calls of a method are slower; always warm up before measuring.
  • Version="8.0.0" in a PackageReference means 8.0.0 or higher (minimum), and NuGet picks the lowest version that satisfies it.
  • Run dotnet list package --vulnerable --include-transitive regularly; the .NET 8 SDK also audits on restore and warns (NU1901–NU1904).

1. From C# to running code

Common mistakes

  • Benchmarking a Debug build, or timing the first call that includes JIT compilation.
  • Thinking a .NET .dll contains machine code; it contains IL (unless published R2R, and even then IL is still there).
  • Using floating versions (*) in production projects, making builds non-repeatable.
  • Ignoring restore warnings NU1901–NU1904 about vulnerable packages.
  • Turning on Native AOT for an app full of reflection and ignoring the trim warnings.

DAY 2 · TUE

Stack vs heap, the managed heap and the garbage collector

GoalDescribe precisely where data lives, how the GC finds and frees garbage, how generations and the Large Object Heap work, and why finalizers are expensive.

Key definitions

Stack
Per-thread memory holding method frames: parameters, locals and return addresses. Freed automatically when a method returns.
Managed heap
Memory the GC manages, holding every object (class instance, array, string, boxed value).
Reference
A pointer-sized value that refers to an object on the heap.
GC root
A starting point the GC trusts is alive: live locals and parameters, static fields, GC handles, the f-reachable (ready-to-finalize) queue, CPU registers.
Reachable
An object that can be reached by following references from some root. Unreachable objects are garbage.
Mark / sweep / compact
The GC marks reachable objects, frees the rest, and usually slides survivors together to remove gaps.
Generation
Age bucket for objects: gen 0 (new), gen 1 (survived one GC), gen 2 (long-lived).
Promotion
Moving a surviving object to the next generation after a collection.
Large Object Heap (LOH)
Separate heap for objects of 85,000 bytes or more. Logically part of gen 2, collected only in gen 2 GCs, not compacted by default.
Pinned Object Heap (POH)
.NET 5+ heap for objects that must never move (e.g. buffers passed to native code).
Workstation vs Server GC
Workstation: one heap, tuned for low latency on client apps. Server: one heap and GC thread per core, tuned for throughput.
Background GC
The default concurrent mode: gen 2 collections run mostly alongside your threads; gen 0/1 still pause briefly.
Finalizer
A ~ClassName() method the GC calls on a dedicated thread before reclaiming an object. A last-resort safety net for unmanaged resources.
Dispose
Deterministic cleanup via IDisposable, called by you or a using statement — the normal way to release resources.
Quick notes
  • "Value types live on the stack" is a myth. Value types live where their container lives.
  • Allocation on the managed heap is very cheap (bump a pointer). Collection is the expensive part.
  • Most objects die young, so gen 0 collections are frequent and fast; gen 2 collections are rare and expensive.
  • Objects ≥ 85,000 bytes go straight to the LOH; repeatedly allocating them causes gen 2 GCs and fragmentation.
  • Don't call GC.Collect() in application code. The GC tunes itself far better than you can.
  • A finalizer makes every instance survive at least one extra GC. Implement IDisposable and call GC.SuppressFinalize.

1. Stack vs heap, precisely

The interview-safe statement: reference-type objects always live on the heap. Value types live wherever their container is — in a method's stack frame if they're a plain local or parameter, inside the object if they're a field, inside the array if they're array elements. Captured or hoisted locals move to the heap too.

Where.cs
public struct Money                 // value type
{
    public decimal Amount;
    public string Currency;         // a reference: the string object itself is on the heap
}

public class Order                  // reference type
{
    public int Id;                  // inside the Order object → heap
    public Money Total;             // struct field → stored INLINE inside the Order object → heap
}

public static class Where
{
    public static void Process()
    {
        int qty = 3;                                   // local → this method's stack frame (or a CPU register)
        Money price = new() { Amount = 499m, Currency = "INR" };   // whole struct in the frame; "INR" is a heap string
        Order order = new() { Id = 1 };                // the REFERENCE is in the frame; the Order object is on the heap
        int[] lines = [1, 2, 3];                       // one heap array object holding the ints inline
        object boxed = qty;                            // boxing: a new heap object holding a copy of 3

        int discount = 10;
        Func<int> getDiscount = () => discount;        // captured: `discount` becomes a field of a heap closure object
        Console.WriteLine(getDiscount() + price.Amount + order.Id + lines.Length + (int)boxed);
    }
}

2. How the GC decides what to free

  1. Allocation: the heap keeps a pointer to the next free byte. new just bumps it, which is why allocation is almost as cheap as a stack push.
  2. Trigger: when gen 0's budget is used up (or memory is low, or you call GC.Collect), a collection starts.
  3. Mark: starting from roots, follow every reference and mark what's reachable.
  4. Sweep / compact: everything unmarked is garbage. Survivors are usually slid together and references updated, so the free space is one contiguous block again.
  5. Promote: survivors of a gen 0 GC become gen 1; survivors of a gen 1 GC become gen 2.

Circular references are not a problem: two objects pointing at each other but unreachable from any root are both garbage. .NET's GC is a tracing GC, not reference counting.

static void BuildReport()
{
    var customer = new Customer("Asha");          // reachable via the local `customer`
    customer.Orders.Add(new CustomerOrder(1, customer));   // the order points back: a cycle
    Console.WriteLine(customer.Orders.Count);
}   // after this returns nothing roots either object → both are collectable, cycle or not

3. Generations and measuring them

The generational hypothesis: most objects die young (request DTOs, LINQ iterators, temporary strings), and objects that survive a while tend to live a long time (caches, singletons). So the GC collects gen 0 often and cheaply, and touches gen 2 rarely.

Generations.cs
var invoice = new byte[1_000];
Console.WriteLine(GC.GetGeneration(invoice));   // 0 — brand new

GC.Collect();                                   // learning only!
Console.WriteLine(GC.GetGeneration(invoice));   // 1 — survived, promoted
GC.Collect();
Console.WriteLine(GC.GetGeneration(invoice));   // 2 — long-lived now
GC.KeepAlive(invoice);

Console.WriteLine($"gen0={GC.CollectionCount(0)} gen1={GC.CollectionCount(1)} gen2={GC.CollectionCount(2)}");

// Measuring memory
long heapNow     = GC.GetTotalMemory(forceFullCollection: false);  // approx bytes currently in use on the heap
long allocThread = GC.GetAllocatedBytesForCurrentThread();         // total ever allocated by THIS thread
long allocTotal  = GC.GetTotalAllocatedBytes(precise: false);      // total ever allocated by the process

GCMemoryInfo info = GC.GetGCMemoryInfo();
Console.WriteLine($"Heap {info.HeapSizeBytes / 1024 / 1024} MB, fragmented {info.FragmentedBytes / 1024} KB, " +
                  $"time paused in GC {info.PauseTimePercentage}%");

4. The Large Object Heap

var small = new byte[84_000];
var large = new byte[85_000];
Console.WriteLine(GC.GetGeneration(small));   // 0
Console.WriteLine(GC.GetGeneration(large));   // 2 — LOH objects are reported as gen 2 from birth

// The threshold is the OBJECT size, header included (24 bytes for an array on 64-bit):
// new byte[84_975] → 84,999 bytes → small object heap
// new byte[84_976] → 85,000 bytes → LOH
// new double[10_700] → 85,624 bytes → LOH ; a List<int> grown to 25,000 ints by Add has capacity 32,768 → a 131,072-byte internal array → LOH
  • LOH objects are only collected in gen 2 collections, so churning them (e.g. a new 1 MB buffer per request) forces expensive full GCs.
  • The LOH isn't compacted by default (copying big blocks is expensive), so it can fragment. You can request a one-off compaction with GCSettings.LargeObjectHeapCompactionMode = GCLargeObjectHeapCompactionMode.CompactOnce.
  • Fixes: reuse buffers with ArrayPool<T> (Wednesday), stream data instead of loading it all, and pre-size collections sensibly.

Why not GC.Collect()?

  • It forces a full, blocking gen 2 collection: the most expensive kind.
  • It promotes everything still alive into older generations, making later collections more expensive.
  • It throws away the GC's own tuning, which is based on actual allocation rates.
  • Acceptable: tests and experiments (like this week's lab), benchmarks between iterations, and very rare cases like right after loading a huge one-time dataset in a desktop app, after measuring.

6. Finalizers and why they're costly

Finalizers.cs
using System.Runtime.InteropServices;

// Only needed when YOU own an unmanaged resource directly (rare; prefer SafeHandle)
public class NativeReportBuffer : IDisposable
{
    private IntPtr _memory = Marshal.AllocHGlobal(64 * 1024);   // unmanaged: the GC knows nothing about it

    public void Dispose()
    {
        Dispose(disposing: true);

    }

    protected virtual void Dispose(bool disposing)
    {
        if (_disposed) return;
        if (disposing)
        {
            // dispose other managed IDisposables here (only when called from Dispose)
        }
        Marshal.FreeHGlobal(_memory);       // always release the unmanaged resource
        _memory = IntPtr.Zero;
        _disposed = true;
    }

    ~NativeReportBuffer() => Dispose(disposing: false);   // safety net if someone forgets Dispose
}

// Typical class: wraps managed IDisposables only → NO finalizer needed
public sealed class InvoiceWriter(string path) : IDisposable
{
    private readonly StreamWriter _writer = new(path);    // FileStream's SafeFileHandle has its own finalizer
    public void WriteLine(string line) => _writer.WriteLine(line);
    public void Dispose() => _writer.Dispose();
}

What a finalizer costs:

  1. At allocation, the object is registered on the finalization queue (slower allocation).
  2. When it becomes unreachable, the GC can't free it. It moves it to the f-reachable queue — which is a root — so the object and everything it references survive and get promoted.
  3. A single finalizer thread runs finalizers one by one, in no guaranteed order.
  4. Only a later GC (often gen 1 or 2 by now) actually frees the memory.
  5. In .NET Core / .NET 5+, finalizers are not run on process exit, so they can't be relied on for flushing data.

On a 2-core cloud VM with .NET 8, allocating and collecting 1,000,000 tiny objects took around 1 ms without a finalizer and roughly 150–300 ms with an empty one (approximate; varies by machine, but the gap is always large).

Common mistakes

  • Repeating "value types go on the stack, reference types go on the heap" without the caveats.
  • Calling GC.Collect() to "fix" memory usage instead of finding what keeps objects alive.
  • Allocating large temporary buffers (≥ 85 KB) in a loop or per request.
  • Adding a finalizer to a class that only holds managed objects.
  • Forgetting GC.SuppressFinalize(this) in Dispose when the class does have a finalizer.

BasicWhere are value types and reference types stored?
Reference-type objects are always on the managed heap; variables hold references to them. Value types are stored inline where they're declared: in the stack frame for non-captured locals and parameters, inside the object for fields, inside the array for elements. Captured locals and async/iterator locals are hoisted to heap objects.
BasicHow does the .NET garbage collector work?
It's a generational, tracing, compacting GC. When gen 0's budget is used it marks objects reachable from roots (locals, statics, handles), frees the rest, compacts survivors and promotes them to the next generation. Gen 0 is collected often and cheaply, gen 2 rarely.
BasicWhat is the Large Object Heap?
A separate area for objects of 85,000 bytes or more. It's logically part of gen 2, so those objects are only collected during full GCs, and it isn't compacted by default to avoid copying large blocks.
IntermediateWhy shouldn't you call GC.Collect()?
It forces an expensive blocking full collection, promotes still-live objects to older generations (making future GCs costlier) and overrides the GC's self-tuning. It's acceptable in tests, benchmarks and rare measured scenarios.
IntermediateWorkstation vs Server GC?
Workstation GC uses one heap and collects on the triggering thread, minimising memory and pause times for client apps. Server GC creates one heap and GC thread per logical core and collects in parallel, maximising throughput for servers at the cost of more memory. Dispose is deterministic: called by your code or a using statement as soon as you're done. Quick notes
  • A span is a pointer + a length. Slicing just changes those two numbers.
  • Substring allocates a new string; AsSpan(start, length) doesn't.

2. Parsing without allocations

A GSTIN has 15 characters: a 2-digit state code, the 10-character PAN, an entity number, the letter Z and a check character. Validating thousands of them per second (e.g. an invoice import) with Substring creates several strings each. With spans it creates none until you decide to keep something.

Gstin.cs
Console.WriteLine(Gstin.TryParse("  29ABCDE1234F1Z5 ", out var g));   // True
Console.WriteLine(g);                                                // GstinInfo { StateCode = 29, Pan = ABCDE1234F, EntityNumber = 1 }
Console.WriteLine(Gstin.TryParse("29ABCDE12X4F1Z5", out _));         // False

public readonly record struct GstinInfo(int StateCode, string Pan, char EntityNumber);

public static class Gstin
{
    // e.g. 29ABCDE1234F1Z5 → state 29 (Karnataka), PAN ABCDE1234F, entity 1
    public static bool TryParse(ReadOnlySpan<char> input, out GstinInfo info)
    {
        info = default;
        ReadOnlySpan<char> s = input.Trim();                     // span Trim: no new string
        if (s.Length != 15 || s[13] != 'Z') return false;

        if (!int.TryParse(s[..2], out int state) || state is < 1 or > 38) return false;   // simplified range

        ReadOnlySpan<char> pan = s.Slice(2, 10);
        if (!IsPan(pan)) return false;

        info = new GstinInfo(state, pan.ToString(), s[12]);     // the only allocation, and only on success
        return true;
    }

    private static bool IsPan(ReadOnlySpan<char> p)
    {
        foreach (char c in p[..5]) if (!char.IsAsciiLetterUpper(c)) return false;   // .NET 7+
        foreach (char c in p[5..9]) if (!char.IsAsciiDigit(c)) return false;
        return char.IsAsciiLetterUpper(p[9]);
    }
}

using System.Buffers;

// Size not known in advance: stack for small inputs, pool for big ones
static int CountVowels(string text)
{
    const int MaxStack = 256;
    char[]? rented = null;
    Span<char> lower = text.Length <= MaxStack
        ? stackalloc char[MaxStack]
        : (rented = ArrayPool<char>.Shared.Rent(text.Length));

    {

    }
}

public ref struct LineReader(ReadOnlySpan<char> text)
{

    public bool TryReadLine(out ReadOnlySpan<char> line)
    {
        if (_rest.IsEmpty) { line = default; return false; }
        int nl = _rest.IndexOf('\n');
        line = nl < 0 ? _rest : _rest[..nl];
        _rest = nl < 0 ? default : _rest[(nl + 1)..];
        return true;
    }
}

        string s => !string.IsNullOrWhiteSpace(s),
        _ => true
    };
    public override string FormatError(string property) => Message ?? $"{property} is required";
}

public sealed class RangeAttribute(double min, double max) : ValidationAttribute   // ctor args: constants only
{
    public double Min { get; } = min;
    public double Max { get; } = max;

    public override bool IsValid(object? value) =>
        value is null || (Convert.ToDouble(value) is var d && d >= Min && d <= Max);   // null is Required's job
    public override string FormatError(string property) => Message ?? $"{property} must be between {Min} and {Max}";
}

public sealed class MaxLengthAttribute(int length) : ValidationAttribute
{
    public int Length { get; } = length;
    public override bool IsValid(object? value) => value is not string s || s.Length <= Length;
    public override string FormatError(string property) => Message ?? $"{property} must be at most {Length} characters";
}
Gotcha. You can't write [Range(10_000m, 5_00_000m)]: decimal isn't a valid attribute argument type. That's why RangeAttribute here (and the real DataAnnotations one) takes double, or takes a Type plus strings.

5. Reading attributes: a tiny validation framework

Mini.Validation/Validator.cs
using System.Collections.Concurrent;
using System.Reflection;

namespace Mini.Validation;

public static class Validator
{
    // Reflection lookups are slow; do them once per type and cache the result
    private static readonly ConcurrentDictionary<Type, (PropertyInfo Prop, ValidationAttribute[] Rules)[]> Cache = new();

    public static IReadOnlyList<string> Validate(object model)
    {
        ArgumentNullException.ThrowIfNull(model);
        var rules = Cache.GetOrAdd(model.GetType(), static type =>
            type.GetProperties(BindingFlags.Public | BindingFlags.Instance)
                .Select(p => (p, p.GetCustomAttributes<ValidationAttribute>(inherit: true).ToArray()))
                .Where(x => x.Item2.Length > 0)
                .ToArray());

        var errors = new List<string>();
        foreach (var (prop, attributes) in rules)
        {
            object? value = prop.GetValue(model);
            foreach (var attribute in attributes)
                if (!attribute.IsValid(value))
                    errors.Add(attribute.FormatError(prop.Name));
        }
        return errors;
    }
}

What's the difference between typeof(X) and x.GetType()?typeof is resolved at compile time for a named type. GetType() returns the actual runtime type of an instance, which may be a derived class.

BasicWhat is reflection and where is it used?
The ability to inspect metadata and work with types and members at runtime: list properties, read/write values, create instances, invoke methods, read attributes. Used by serializers, ORMs (EF Core), DI containers, model binding and validation, test frameworks and plugin systems.
BasicWhat are attributes and how do you create a custom one?
Declarative metadata attached to code elements. Create a class deriving from System.Attribute (name ending in Attribute), mark it with [AttributeUsage] to control targets, AllowMultiple and Inherited, and read it with GetCustomAttribute(s).

IntermediateWhy is reflection slow and how do you make it faster?
Member lookups search metadata by string, and Invoke/GetValue box arguments and results, check types and access, and can't be inlined. Cache MemberInfo objects, convert hot paths into strongly typed delegates (CreateDelegate) or compiled expression trees, or move the work to compile time with source generators.
IntermediateHow do reflection and Native AOT/trimming interact?
The trimmer removes code it can't see being used. Members accessed only by string names via reflection may be removed, causing runtime failures. IntermediateWhat are source generators?
Roslyn components that run during compilation, inspect your code (often attributes) and add new C# source. They replace runtime reflection with ordinary generated code: faster startup, no reflection cost, and AOT-safe. Examples: [GeneratedRegex], System.Text.Json source generation, [LoggerMessage].
DAY 5 · FRI

Async and GC pitfalls, memory leaks and diagnostics

GoalRecognise the async and memory mistakes that cause crashes, hangs and leaks in real systems, fix them, and know which tool to reach for when production misbehaves.

Key definitions

async void
An async method that returns nothing awaitable. Exceptions go straight to the SynchronizationContext and usually crash the process.
Sync-over-async
Blocking on async code with .Result, .Wait() or GetAwaiter().GetResult().
SynchronizationContext
Decides where an await continues: the UI thread in WinForms/WPF, the request context in legacy ASP.NET. ASP.NET Core and console apps have none.
ConfigureAwait(false)
Tells an await not to resume on the captured context; any thread-pool thread will do.
Deadlock
Two parties each waiting for the other forever, e.g. a blocked UI thread waiting for a continuation that needs the UI thread.
Thread-pool starvation
All pool threads are blocked waiting, so queued work (including the continuations they're waiting for) can't run; latency explodes.
Fire-and-forget
Starting a task without awaiting or observing it. Its exceptions are lost and its lifetime is unmanaged.
Managed memory leak
Objects that are no longer needed but are still reachable from a root, so the GC can't free them.
Event leak
A long-lived publisher's event holds a reference to a short-lived subscriber's handler, keeping the subscriber alive.
WeakReference
A reference that doesn't keep its target alive; used to test whether an object was collected.
dotnet-counters
CLI tool showing live runtime metrics: GC heap size, GC counts, allocation rate, thread-pool queue, exceptions.
dotnet-dump
CLI tool to capture and analyse a process memory dump: which objects exist and what roots them.
dotnet-gcdump
Lighter dump of just the GC heap, viewable in Visual Studio or PerfView.
dotnet-trace
CLI tool that records an event trace (CPU samples, GC events, allocations) for later analysis.
Quick notes
  • Use async void only for event handlers, and wrap their bodies in try/catch.
  • Async all the way: if you call an async method, your method should be async and await it.
  • In library code, ConfigureAwait(false) avoids capturing a context you don't need.
  • A memory leak in .NET is always "something still references it". Find the root.
  • Classic roots of leaks: events, static collections, caches without limits, timers, closures.
  • Watch a counter first (is the heap growing?), then take a dump to see what and why.

1. async void

AsyncVoid.cs (fragment)
// ❌ async void: the caller can't await it or catch its exceptions
public async void SendInvoiceEmail(int invoiceId)
{
    await Task.Delay(100);
    throw new InvalidOperationException($"SMTP down for invoice {invoiceId}");   // crashes the process
}

try
{
    SendInvoiceEmail(42);              // returns at the first await; the exception happens later
}
catch (Exception) { /* never reached */ }

// ✓ async Task: awaitable and catchable

{
    await Task.Delay(100);
    throw new InvalidOperationException($"SMTP down for invoice {invoiceId}");
}
try { await SendInvoiceEmailAsync(42); }
catch (InvalidOperationException ex) { Console.WriteLine($"Logged: {ex.Message}"); }

// The one valid use: event handlers (their signature must return void)
private async void SaveButton_Click(object? sender, EventArgs e)
{
    try { await SaveAsync(); }
    catch (Exception ex) { ShowError(ex.Message); }   // never let it escape

2. Sync-over-async deadlocks

In a WinForms/WPF app (or classic ASP.NET on .NET Framework), awaits resume on the captured context, which only has one thread. Block that thread and the continuation can never run:

  1. The UI thread calls LoadCustomerAsync().Result and blocks, waiting for the task.
  2. Inside, await httpClient.GetStringAsync(...) completes on an I/O thread.
  3. The rest of LoadCustomerAsync must run on the UI thread (context captured), so it's posted there.
  4. The UI thread is blocked in step 1 forever. Deadlock.
Deadlock.cs (WinForms fragment)
// WinForms button handler — ❌ freezes forever
private void LoadButton_Click(object sender, EventArgs e)
{
    string name = LoadCustomerAsync(101).Result;     // blocks the UI thread
    nameLabel.Text = name;
}

private async Task<string> LoadCustomerAsync(int id)
{
    string json = await _http.GetStringAsync($"https://api.example.com/customers/{id}");
    return ParseName(json);                          // needs the UI thread to run → never gets it
}

// ✓ Fix 1 (the real fix): async all the way
private async void LoadButton_Click2(object sender, EventArgs e)
{
    try { nameLabel.Text = await LoadCustomerAsync(101); }
    catch (HttpRequestException ex) { MessageBox.Show(ex.Message); }
}

// ✓ Fix 2 (library code): don't capture the context you don't need
public async Task<string> LoadCustomerLibAsync(int id)
{
    string json = await _http.GetStringAsync($"https://api.example.com/customers/{id}").ConfigureAwait(false);
    return ParseName(json);                          // runs on a thread-pool thread
}

public sealed class GoldRateWorker(ILogger<GoldRateWorker> logger) : IAsyncDisposable
{
    private readonly CancellationTokenSource _cts = new();
    private Task? _loop;

    public void Start() => _loop = RunAsync(_cts.Token);

    private async Task RunAsync(CancellationToken ct)
    {
        using var timer = new PeriodicTimer(TimeSpan.FromSeconds(5));
        try
        {
            while (await timer.WaitForNextTickAsync(ct))
                logger.LogInformation("Polling gold rate at {Time}", DateTime.Now);
        }
        catch (OperationCanceledException) { /* stopping */ }
    }

    {
        _cts.Cancel();
        if (_loop is not null) await _loop;
        _cts.Dispose();
    }

BasicWhat causes the classic .Result deadlock?

BasicCan a .NET application have memory leaks if it has a garbage collector?

When pool threads are blocked (often by sync-over-async), new work and continuations wait in the queue while the pool injects threads slowly. namespace Internals.Lab.Core;

public readonly record struct Measurement<T>(T Result, long AllocatedBytes, TimeSpan Elapsed);

public static class Measure
{
    /// <summary>Runs the action once and reports bytes allocated on this thread and time taken.</summary>
    public static Measurement<T> Run<T>(Func<T> action)
    {
        long before = GC.GetAllocatedBytesForCurrentThread();
        long start = Stopwatch.GetTimestamp();             // a long, not a Stopwatch object: measuring must not allocate
        T result = action();
        TimeSpan elapsed = Stopwatch.GetElapsedTime(start); // .NET 7+
        long allocated = GC.GetAllocatedBytesForCurrentThread() - before;
        return new Measurement<T>(result, allocated, elapsed);
    }

    /// <summary>Warm up (JIT, static init), then measure the best of several runs.</summary>
    public static Measurement<T> Best<T>(Func<T> action, int runs = 5)
    {
        action();                                         // warm-up: not measured
        Measurement<T> best = Run(action);
        for (int i = 1; i < runs; i++)
        {
            var m = Run(action);
            if (m.Elapsed < best.Elapsed) best = m;
        }
        return best;
    }

    public static string Bytes(long bytes) => bytes switch
    {
        < 0 => "-" + Bytes(-bytes),
        < 1024 => $"{bytes} B",
        < 1024 * 1024 => $"{bytes / 1024.0:N1} KB",
        _ => $"{bytes / (1024.0 * 1024):N1} MB"
    };
}
Tip. The first version of this helper used Stopwatch.StartNew(), and every "zero-allocation" case reported 40 bytes: the Stopwatch object itself. Measuring tools must not disturb what they measure.

public sealed class LohExperiment : IExperiment
{
    public string Id => "loh";
    public string Title => "3. Finding the Large Object Heap threshold";
    public string Question => "At what array length does a byte[] land on the LOH (reported as gen 2 straight away)?";

    public void Run(TextWriter output)
    {
        int[] lengths = [1_000, 80_000, 84_975, 84_976, 85_000, 1_000_000];
        output.WriteLine($"{"byte[] length",14} {"Generation",11}  Heap");
        foreach (int length in lengths)
        {
            var buffer = new byte[length];
            int gen = GC.GetGeneration(buffer);
            output.WriteLine($"{length,14:N0} {gen,11}  {(gen == 2 ? "LOH" : "SOH")}");
        }
        output.WriteLine("(On 64-bit an array has a 24-byte header, so 84,976 + 24 = 85,000 bytes.)");

        // Cost: renting large buffers vs allocating them
        output.WriteLine();
        int g2Before = GC.CollectionCount(2);
        long sum = 0;
        for (int i = 0; i < 2_000; i++)
        {
            var report = new byte[200_000];          // new LOH object every time
            report[i % report.Length] = 1;
            sum += report.Length;
        }
        output.WriteLine($"new byte[200_000] x 2,000:       gen2 GCs = {GC.CollectionCount(2) - g2Before}");

        g2Before = GC.CollectionCount(2);
        for (int i = 0; i < 2_000; i++)
        {
            byte[] report = ArrayPool<byte>.Shared.Rent(200_000);   // reused, may be larger than asked
            try { report[i % 200_000] = 1; sum += report.Length; }
            finally { ArrayPool<byte>.Shared.Return(report); }
        }
        output.WriteLine($"ArrayPool.Rent(200_000) x 2,000: gen2 GCs = {GC.CollectionCount(2) - g2Before}");
        GC.KeepAlive(sum);
    }
}

Step 6 — Experiment 4: Split/Substring vs Span

Internals.Lab.Core/Experiments/SpanParsingExperiment.cs
using System.Globalization;

namespace Internals.Lab.Core.Experiments;

public sealed class SpanParsingExperiment : IExperiment
{
    public string Id => "span";
    public string Title => "4. Split/Substring vs ReadOnlySpan<char> parsing";
    public string Question => "How much less does span-based parsing allocate, and is it faster?";

    // Each line: orderId|pinCode|amount|state, e.g. ORD-100042|560001|1499.50|KA
    private readonly string[] _lines = BuildLines(100_000);

    public void Run(TextWriter output)
    {
        var classic = Measure.Best(() => TotalForPinPrefixClassic(_lines, "56"));
        var span    = Measure.Best(() => TotalForPinPrefixSpan(_lines, "56"));

        output.WriteLine($"{"Approach",-22} {"Total (INR)",16} {"Allocated",12} {"Time",10}");
        output.WriteLine($"{"Split + Substring",-22} {classic.Result,16:N2} {Measure.Bytes(classic.AllocatedBytes),12} {classic.Elapsed.TotalMilliseconds,8:N1}ms");
        output.WriteLine($"{"ReadOnlySpan<char>",-22} {span.Result,16:N2} {Measure.Bytes(span.AllocatedBytes),12} {span.Elapsed.TotalMilliseconds,8:N1}ms");
        output.WriteLine(classic.Result == span.Result ? "Totals match ✓" : "Totals DIFFER ✗ — check your parser");
    }

    public static decimal TotalForPinPrefixClassic(string[] lines, string pinPrefix)
    {
        decimal total = 0;
        foreach (string line in lines)
        {
            string[] parts = line.Split('|');                       // new array + 4 new strings per line
            if (parts[1].StartsWith(pinPrefix, StringComparison.Ordinal))
                total += decimal.Parse(parts[2], CultureInfo.InvariantCulture);
        }
        return total;
    }

    public static decimal TotalForPinPrefixSpan(string[] lines, string pinPrefix)
    {
        decimal total = 0;
        foreach (string line in lines)
        {
            ReadOnlySpan<char> rest = line;                         // a view, no copy
            rest = rest[(rest.IndexOf('|') + 1)..];                 // skip orderId
            int bar = rest.IndexOf('|');
            ReadOnlySpan<char> pin = rest[..bar];
            if (!pin.StartsWith(pinPrefix, StringComparison.Ordinal)) continue;

            rest = rest[(bar + 1)..];
            ReadOnlySpan<char> amount = rest[..rest.IndexOf('|')];
            total += decimal.Parse(amount, CultureInfo.InvariantCulture);   // span overload: no string
        }
        return total;
    }

    private static string[] BuildLines(int count)
    {
        string[] pins = ["560001", "400001", "110001", "600028", "560078", "700019"];
        string[] states = ["KA", "MH", "DL", "TN", "KA", "WB"];
        var rng = new Random(42);                                   // fixed seed: same data every run
        var lines = new string[count];
        for (int i = 0; i < count; i++)
        {
            int p = rng.Next(pins.Length);
            decimal amount = rng.Next(100, 500_000) / 100m;
            lines[i] = string.Create(CultureInfo.InvariantCulture, $"ORD-{100_000 + i}|{pins[p]}|{amount:F2}|{states[p]}");
        }
        return lines;
    }
}
Note. The span parser trusts the input format (it assumes four fields). In production, check every IndexOf result for -1 and use decimal.TryParse. Robustness first, then speed.

Internals.Lab.Core/Experiments/EventLeakExperiment.cs
using System.Runtime.CompilerServices;

namespace Internals.Lab.Core.Experiments;

public sealed class PriceTicker                       // long-lived publisher (think: a singleton service)
{
    public event EventHandler<decimal>? PriceChanged;
    public void Publish(decimal price) => PriceChanged?.Invoke(this, price);
    public int SubscriberCount => PriceChanged?.GetInvocationList().Length ?? 0;
}

public sealed class LeakyQuoteScreen                  // ❌ subscribes, never unsubscribes
{
    private readonly byte[] _chartCache = new byte[1_000_000];   // ~1 MB per screen
    public LeakyQuoteScreen(PriceTicker ticker) => ticker.PriceChanged += OnPrice;
    private void OnPrice(object? sender, decimal price) => _chartCache[0] = (byte)price;
}

public sealed class QuoteScreen : IDisposable         // ✓ unsubscribes in Dispose
{
    private readonly byte[] _chartCache = new byte[1_000_000];
    private readonly PriceTicker _ticker;
    public QuoteScreen(PriceTicker ticker) { _ticker = ticker; _ticker.PriceChanged += OnPrice; }
    private void OnPrice(object? sender, decimal price) => _chartCache[0] = (byte)price;
    public void Dispose() => _ticker.PriceChanged -= OnPrice;
}

public sealed class EventLeakExperiment : IExperiment
{
    public string Id => "leak";
    public string Title => "5. A memory leak through an event — and the fix";
    public string Question => "After we drop every reference to 50 screens and force a GC, how many are still alive?";

    private const int Screens = 50;

    public void Run(TextWriter output)
    {
        var ticker = new PriceTicker();

        long baseline = GC.GetTotalMemory(forceFullCollection: true);
        WeakReference[] leaky = OpenAndCloseLeakyScreens(ticker);
        ForceFullGc();
        output.WriteLine("Leaky screens (no unsubscribe):");
        output.WriteLine($"  still alive:   {leaky.Count(w => w.IsAlive)} of {Screens}");
        output.WriteLine($"  subscribers:   {ticker.SubscriberCount}");
        output.WriteLine($"  memory growth: {Measure.Bytes(GC.GetTotalMemory(true) - baseline)}");

        var ticker2 = new PriceTicker();
        baseline = GC.GetTotalMemory(forceFullCollection: true);
        WeakReference[] fixedOnes = OpenAndCloseDisposableScreens(ticker2);
        ForceFullGc();
        output.WriteLine("Disposable screens (unsubscribe in Dispose):");
        output.WriteLine($"  still alive:   {fixedOnes.Count(w => w.IsAlive)} of {Screens}");
        output.WriteLine($"  subscribers:   {ticker2.SubscriberCount}");
        output.WriteLine($"  memory growth: {Measure.Bytes(GC.GetTotalMemory(true) - baseline)}");

        GC.KeepAlive(ticker);
        GC.KeepAlive(ticker2);
    }

    // NoInlining keeps the screens' local variables out of Run, so only the event can keep them alive
    [MethodImpl(MethodImplOptions.NoInlining)]
    private static WeakReference[] OpenAndCloseLeakyScreens(PriceTicker ticker)
    {
        var refs = new WeakReference[Screens];
        for (int i = 0; i < Screens; i++)
            refs[i] = new WeakReference(new LeakyQuoteScreen(ticker));   // "user closes the screen" = we drop it
        return refs;
    }

    [MethodImpl(MethodImplOptions.NoInlining)]
    private static WeakReference[] OpenAndCloseDisposableScreens(PriceTicker ticker)
    {
        var refs = new WeakReference[Screens];
        for (int i = 0; i < Screens; i++)
        {
            using var screen = new QuoteScreen(ticker);
            refs[i] = new WeakReference(screen);
        }
        return refs;
    }

    private static void ForceFullGc()
    {
        GC.Collect();
        GC.WaitForPendingFinalizers();
        GC.Collect();
    }
}

Step 8 — Experiment 6: a real sync-over-async deadlock

Console apps have no SynchronizationContext, so .Result can't deadlock there. To see the UI-thread deadlock for real, we install a tiny single-threaded context that queues continuations and never runs them while its thread is blocked — exactly what a frozen WinForms thread does.

Internals.Lab.Core/Experiments/DeadlockExperiment.cs
using System.Diagnostics;

namespace Internals.Lab.Core.Experiments;

/// <summary>
/// A context like WinForms/WPF/legacy ASP.NET: continuations are queued to ONE thread.
/// We never pump the queue while blocked — exactly what a UI thread stuck in .Result does.
/// </summary>
public sealed class SingleThreadContext : SynchronizationContext
{
    private readonly Queue<(SendOrPostCallback Callback, object? State)> _queue = new();
    public int Pending { get { lock (_queue) return _queue.Count; } }

    public override void Post(SendOrPostCallback d, object? state)
    {
        lock (_queue) _queue.Enqueue((d, state));     // "please run this on my thread later"
    }
}

public sealed class DeadlockExperiment : IExperiment
{
    public string Id => "deadlock";
    public string Title => "6. Sync-over-async deadlock (and why ConfigureAwait(false) avoids it)";
    public string Question => "Blocking with .Wait() on a single-threaded context: does the task ever finish?";

    public void Run(TextWriter output)
    {
        output.WriteLine(Attempt(useConfigureAwaitFalse: false));
        output.WriteLine(Attempt(useConfigureAwaitFalse: true));
        output.WriteLine("Console apps and ASP.NET Core have no such context, so the same code would not deadlock there —");
        output.WriteLine("but it would still block a thread-pool thread. The real fix is async all the way down.");
    }

    private static string Attempt(bool useConfigureAwaitFalse)
    {
        string result = "";
        var uiThread = new Thread(() =>
        {
            var context = new SingleThreadContext();
            SynchronizationContext.SetSynchronizationContext(context);

            var sw = Stopwatch.StartNew();
            Task<decimal> task = GetGstRateAsync(useConfigureAwaitFalse);
            bool finished = task.Wait(TimeSpan.FromSeconds(2));       // ❌ blocking, like .Result
            sw.Stop();

            string label = useConfigureAwaitFalse ? "ConfigureAwait(false)" : "default await";
            result = finished
                ? $"{label,-22}: finished in {sw.ElapsedMilliseconds} ms, rate = {task.Result:P0}"
                : $"{label,-22}: DEADLOCK — gave up after {sw.ElapsedMilliseconds} ms; {context.Pending} continuation(s) stuck in the queue";
        });
        uiThread.Start();
        uiThread.Join();
        return result;
    }

    private static async Task<decimal> GetGstRateAsync(bool configureAwaitFalse)
    {
        await Task.Delay(100).ConfigureAwait(!configureAwaitFalse);   // true = capture the context (default)
        return 0.18m;                                                  // needs the context to run this line
    }
}
Tip. We use Wait(TimeSpan) with a timeout so the lab reports the deadlock instead of hanging forever. A real .Result has no timeout.

BasicWhy must you run benchmarks in Release and warm up first?
Debug builds disable JIT optimisations, and the first call includes JIT compilation and static initialisation. Release plus warm-up (or BenchmarkDotNet, which does it for you with statistics) measures the steady-state code your users actually run.
BasicHow did you prove the event caused the leak?
By holding only WeakReferences to the screens, forcing a full GC and checking IsAlive: all 50 leaky screens survived and the ticker reported 50 subscribers. The disposable version that unsubscribes had 0 survivors. In production, dotnet-dump's gcroot would show the path ticker → delegate → screen.
IntermediateWhy does the span parser allocate nothing while Split allocates ~20 MB?
Split creates a string[] plus one new string per field for every line. The span version only moves a pointer and length over the existing string, and decimal.Parse has a ReadOnlySpan<char> overload, so no intermediate strings are ever created.
IntermediateYour deadlock demo needed a custom SynchronizationContext. What does that tell you about where .Result deadlocks occur?
Only where a single-threaded context captures continuations: UI frameworks and legacy ASP.NET. Console apps and ASP.NET Core have no context, so continuations run on the thread pool. There, blocking doesn't deadlock but wastes threads and can starve the pool under load.

Q4. (Week 7) What prints? 
static async Task Fail(string name, int delayMs)
{
    await Task.Delay(delayMs);
    throw new InvalidOperationException(name);
}

try
{
    await Task.WhenAll(Fail("GST", 100), Fail("TDS", 10));
}
catch (Exception ex)
{
    Console.WriteLine(ex.Message);
}
TDS (verified on .NET 8). await on WhenAll rethrows only the first exception in the combined task's Exception.InnerExceptions; on .NET 8 those are collected as the tasks complete, so TDS (failing after 10 ms) comes first. Don't rely on which one you get: inspect the WhenAll task's Exception.InnerExceptions to see all of them.

BasicWhat is the difference between deferred and immediate execution in LINQ?
Deferred operators (Where, Select, OrderBy, GroupBy…) build a query that runs only when enumerated, every time it's enumerated, against the source's current contents. Immediate operators (ToList, ToArray, Count, Sum, First, Any…) enumerate right away and return a result. Materialise once with ToList when you need the results more than once.
IntermediateHow does await relate to threads?
await doesn't create a thread. It registers a continuation and returns an incomplete task to the caller, freeing the current thread. When the awaited operation (often I/O with no thread at all) completes, the continuation runs on the captured context or a thread-pool thread. Async improves scalability; parallelism comes from running multiple tasks concurrently.
IntermediateHow would you reduce allocations in a hot JSON or CSV processing path?
Measure first (BenchmarkDotNet MemoryDiagnoser, dotnet-counters alloc rate). Then stream instead of loading whole files, parse with spans and span-based Parse overloads, reuse buffers with ArrayPool, use System.Text.Json source generation or Utf8JsonReader, avoid LINQ and closures in the innermost loop, and only create strings for values you keep.
IntermediateA colleague says "we have a GC, so we can't have memory leaks." How do you respond?
The GC frees unreachable objects, but leaks in .NET are reachable objects you no longer need: event subscriptions to long-lived publishers, static or unbounded caches, timers whose callbacks capture objects, closures held by long-lived lists, and undisposed resources holding native memory and handles. You find them with dumps and gcroot, and fix them by removing the reference.
