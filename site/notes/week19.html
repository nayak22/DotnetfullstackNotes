DAY 1 · MON

Global Exception Handling with IExceptionHandler

GoalHandle every unhandled exception in one place: map domain errors to HTTP status codes, return RFC 7807 ProblemDetails, and keep production safe while development stays informative.

Key definitions

IExceptionHandler
ASP.NET Core 8 interface with a single TryHandleAsync method; replaces UseExceptionHandler lambda with a testable, injectable class.
ProblemDetails
RFC 7807 JSON error body with type, title, status, detail and extensions; returned by Problem() or typed as ValidationProblemDetails.
traceId
A unique string per request (from Activity.Current?.Id) added to ProblemDetails so you can correlate logs with errors reported by users.
Chained handlers
Multiple IExceptionHandler implementations registered in order; the first one to return true from TryHandleAsync wins.
UseExceptionHandler("/error")
Built-in middleware that invokes the handler chain and falls back to the /error endpoint if nothing handles the exception.
AddProblemDetails()
Registers the default ProblemDetails factory and writes Content-Type: application/problem+json.
IProblemDetailsService
Injected by AddProblemDetails(); call WriteAsync to serialize and send the response.
Domain exception
A business-rule violation that should map to a known HTTP status (e.g. NotFoundException → 404, ConflictException → 409).
Development vs Production
In development, include exception.ToString() in the detail field. In production, log it and return a generic message.
ExceptionHandlerMiddleware
The ASP.NET Core middleware that catches unhandled exceptions and invokes IExceptionHandler implementations.
StatusCodes.Status422UnprocessableEntity
Returned for domain-rule violations where the payload was valid JSON but breaks a business constraint.
Quick notes
  • Register IExceptionHandler implementations with services.AddExceptionHandler<T>() in dependency-injection order.
  • Call app.UseExceptionHandler() (no path) in .NET 8 to activate the IExceptionHandler chain.
  • Always add app.UseExceptionHandler() before app.UseRouting() so it catches routing errors too.
  • Return false from TryHandleAsync to let the next handler try; return true to short-circuit.
  • Enrich ProblemDetails with a traceId extension so your support team can find the log entry.
  • Test exception handling with integration tests that deliberately trigger each exception type.

1. Why IExceptionHandler?

Before .NET 8 teams registered a UseExceptionHandler("/error") endpoint and scattered try/catch blocks across controllers. IExceptionHandler centralises the mapping, keeps it out of business logic, and is properly injectable and testable.

// Before .NET 8 — scattered catch blocks
[HttpGet("{id}")]
public IActionResult Get(int id)
{
    try { return Ok(_service.FindPost(id)); }
    catch (NotFoundException ex) { return NotFound(ex.Message); }  // repeated everywhere
}

// .NET 8 — declare once in a handler class, controllers throw freely
[HttpGet("{id}")]
public IActionResult Get(int id) => Ok(_service.FindPost(id));  // exceptions flow up

3. Mapping domain exceptions to ProblemDetails

Blog.Api/Exceptions/DomainExceptionHandler.cs
// Blog.Api/Exceptions/DomainExceptionHandler.cs
using Blog.Core.Exceptions;
using Microsoft.AspNetCore.Diagnostics;
using Microsoft.AspNetCore.Mvc;

namespace Blog.Api.Exceptions;

public sealed class DomainExceptionHandler(
    IProblemDetailsService problemDetailsService,
    ILogger<DomainExceptionHandler> logger) : IExceptionHandler
{
    private static readonly Dictionary<Type, int> StatusMap = new()
    {
        [typeof(NotFoundException)]      = StatusCodes.Status404NotFound,
        [typeof(ConflictException)]      = StatusCodes.Status409Conflict,
        [typeof(UnprocessableException)] = StatusCodes.Status422UnprocessableEntity,
    };

    public async ValueTask<bool> TryHandleAsync(
        HttpContext ctx,
        Exception exception,
        CancellationToken ct)
    {
        if (exception is not DomainException domain) return false;  // let the next handler try

        var status = StatusMap.GetValueOrDefault(exception.GetType(), StatusCodes.Status400BadRequest);
        logger.LogWarning(exception, "Domain exception: {Message}", domain.Message);

        ctx.Response.StatusCode = status;

        await problemDetailsService.WriteAsync(new()
        {
            HttpContext = ctx,
            ProblemDetails = new ProblemDetails
            {
                Status  = status,
                Title   = exception.GetType().Name.Replace("Exception", ""),
                Detail  = domain.Message,
                Extensions = { ["traceId"] = System.Diagnostics.Activity.Current?.Id ?? ctx.TraceIdentifier }
            }
        });

        return true;    // handled
    }
}

4. Catch-all handler for unexpected exceptions

Blog.Api/Exceptions/GlobalExceptionHandler.cs
// Blog.Api/Exceptions/GlobalExceptionHandler.cs
using Microsoft.AspNetCore.Diagnostics;
using Microsoft.AspNetCore.Mvc;

namespace Blog.Api.Exceptions;

public sealed class GlobalExceptionHandler(
    IProblemDetailsService problemDetailsService,
    ILogger<GlobalExceptionHandler> logger,
    IHostEnvironment env) : IExceptionHandler
{
    public async ValueTask<bool> TryHandleAsync(
        HttpContext ctx,
        Exception exception,
        CancellationToken ct)
    {
        logger.LogError(exception, "Unhandled exception on {Method} {Path}",
            ctx.Request.Method, ctx.Request.Path);

        ctx.Response.StatusCode = StatusCodes.Status500InternalServerError;

        // Show full stack trace only in Development
        string detail = env.IsDevelopment()
            ? exception.ToString()
            : "An unexpected error occurred. Contact support with the traceId below.";

        await problemDetailsService.WriteAsync(new()
        {
            HttpContext = ctx,
            ProblemDetails = new ProblemDetails
            {
                Status  = 500,
                Title   = "InternalServerError",
                Detail  = detail,
                Extensions = { ["traceId"] = System.Diagnostics.Activity.Current?.Id ?? ctx.TraceIdentifier }
            }
        });

        return true;
    }
}

Common mistakes

  • Registering UseExceptionHandler() after MapControllers() — it must be first in the pipeline.
  • Forgetting AddProblemDetails() — IProblemDetailsService won't be available.
  • Returning true from TryHandleAsync without writing a response — the client receives 500 with no body.
  • Leaking stack traces in production — always check IHostEnvironment.IsProduction().
  • Throwing raw Exception from service layer — define a domain hierarchy so handlers can distinguish causes.

BasicWhat is IExceptionHandler in ASP.NET Core 8?
An interface with TryHandleAsync that lets you map exceptions to HTTP responses in a testable, DI-friendly class. Multiple handlers are chained; the first to return true wins.
BasicWhat HTTP status should a NotFoundException return and why?
404 Not Found, because the requested resource genuinely does not exist. Using 500 for a missing record makes it impossible for callers to distinguish application bugs from missing data.
BasicWhat is ProblemDetails?
An RFC 7807 JSON object with type, title, status and detail fields that standardises error responses across HTTP APIs. ASP.NET Core's AddProblemDetails() wires it up automatically.
IntermediateHow do you chain exception handlers in .NET 8?
Register them in DI order with services.AddExceptionHandler<T>(). Call app.UseExceptionHandler() (no path). The middleware invokes each in registration order until one returns true.
IntermediateHow do you correlate an error report from a user to a log entry?
Add Activity.Current?.Id (the distributed trace ID) to ProblemDetails.Extensions["traceId"]. The same ID appears in Serilog's structured logs via the enricher, so a support engineer can filter by it in Seq or Application Insights.
IntermediateWhat is the difference between UseExceptionHandler("/error") and UseExceptionHandler() (no path) in .NET 8?
The path variant re-executes the pipeline to an error endpoint, requiring a controller action. The no-path variant (new in .NET 8) calls the IExceptionHandler chain directly without a re-execution, which is simpler and doesn't expose an extra route.
DAY 2 · TUE

Structured Logging with Serilog

GoalReplace the default ILogger with Serilog's structured pipeline: two-stage bootstrap, appsettings-driven sinks, enrichers, and request logging middleware for every HTTP call.

Key definitions

Serilog
A structured logging library for .NET; writes log events as key-value property bags rather than interpolated strings.
Sink
A destination for log events: Console, File, Seq, Application Insights, Elasticsearch, etc.
Two-stage bootstrap
Starting Serilog from code (Log.Logger) before the host is built, so startup errors are caught; then reconfiguring from appsettings.json once DI is ready.
Message template
A string with named holes like {UserId} that Serilog captures as structured properties, not raw string interpolation.
Enricher
A component that attaches extra properties to every log event: machine name, environment, thread ID, correlation ID.
Seq
A self-hosted log server that understands Serilog's structured format; great for development because you can filter by any property.
UseSerilogRequestLogging
Serilog middleware that logs one structured line per HTTP request, replacing the noisy built-in Microsoft HTTP logs.
Level override
Silencing verbose Microsoft.* or EF Core SQL logs by setting their minimum level higher than the global minimum.
Destructuring
@ prefix in a template: {@User} captures all object properties, not just ToString()
Log.Fatal + Log.CloseAndFlush
Flush sinks synchronously before the process exits so the last log entries reach sinks, especially async file sinks.
LogContext.PushProperty
Pushes a property into all subsequent log events within a using block (e.g. the request's tenant ID).
Quick notes
  • Use message templates with named holes, never string interpolation — it destroys the structure that makes filtering fast.
  • Always call Log.CloseAndFlush() in a try/catch/finally around host.Run() so final entries reach sinks on crashes.
  • Level overrides in appsettings.json silence Microsoft.EntityFrameworkCore.* and Microsoft.AspNetCore.* without changing the global level.
  • UseSerilogRequestLogging must come before UseRouting and UseAuthorization to capture the status code.
  • {:l} after a hole logs without quotes; use it for single-word string properties in concise output templates.
  • Seq binds to localhost:5341 by default; run it with Docker for local development.

1. Install and two-stage bootstrap

Blog.Api/Program.cs
// Blog.Api/Program.cs
using Serilog;

// Stage 1: minimal bootstrap logger to catch startup errors
Log.Logger = new LoggerConfiguration()
    .MinimumLevel.Warning()                // quiet for startup
    .WriteTo.Console(outputTemplate:
        "[{Timestamp:HH:mm:ss} {Level:u3}] {Message:lj}{NewLine}{Exception}")
    .CreateBootstrapLogger();

try
{
    var builder = WebApplication.CreateBuilder(args);

    // Stage 2: replace with the full configuration from appsettings.json + DI
    builder.Host.UseSerilog((ctx, services, cfg) =>
        cfg.ReadFrom.Configuration(ctx.Configuration)
           .ReadFrom.Services(services)         // allows enrichers registered as services
           .Enrich.FromLogContext()              // picks up LogContext.PushProperty
           .Enrich.WithMachineName()
           .Enrich.WithEnvironmentName());

    // ... services and middleware

    var app = builder.Build();
    app.UseSerilogRequestLogging(opts =>         // ONE structured line per request
    {
        opts.MessageTemplate =
            "HTTP {RequestMethod} {RequestPath} → {StatusCode} in {Elapsed:0.0}ms";
        opts.EnrichDiagnosticContext = (diag, ctx) =>
        {
            diag.Set("ClientIp", ctx.Connection.RemoteIpAddress);
            diag.Set("UserAgent", ctx.Request.Headers.UserAgent.FirstOrDefault());
        };
    });
    app.UseExceptionHandler();
    app.UseRouting();
    app.MapControllers();
    app.Run();
}
catch (Exception ex) when (ex is not HostAbortedException)
{
    Log.Fatal(ex, "Application startup failed");
}
finally
{
    Log.CloseAndFlush();    // ensures async sinks (File, Seq) write their buffers
}

DAY 3 · WED

Health Checks and CORS

GoalExpose liveness and readiness endpoints that orchestrators can poll, write a custom DbContext health check, and configure CORS policies that allow the right origins without opening the API to everyone.

Key definitions

Health check
An endpoint that reports whether the application is Healthy, Degraded or Unhealthy, used by Kubernetes, Azure Load Balancer, or a monitoring dashboard.
Liveness
Probe: is the process alive? Return Healthy unless the app is deadlocked or needs a restart.
Readiness
Probe: can the app serve traffic? Return Unhealthy while warming up, running migrations or when a dependency (DB, Redis) is unreachable.
IHealthCheck
Interface with a single CheckHealthAsync method; return HealthCheckResult.Healthy/Degraded/Unhealthy.
HealthCheckContext
Passed to CheckHealthAsync; holds the registration (name, tags, failure status).
AddDbContextCheck<T>
Extension from Microsoft.Extensions.Diagnostics.HealthChecks.EntityFrameworkCore; pings the DB with a lightweight query.
HealthCheckOptions
Configures the /health response: response writer, predicate to filter by tag, result status codes.
CORS
Cross-Origin Resource Sharing: browser policy that blocks JS on origin A from calling an API on origin B unless B sends the right headers.
AllowedOrigins
The specific scheme+host+port combos a policy permits, e.g. https://blogfront.example.com.
Preflight
An HTTP OPTIONS request the browser sends before a cross-origin non-simple request; the API must reply with Access-Control headers.
Named policy
A CORS policy registered with AddCors and applied by name, allowing different rules for different endpoint groups.
Credentials pitfall
You cannot combine AllowAnyOrigin() with AllowCredentials() — the browser refuses; always specify exact origins for credentialled requests.
Quick notes
  • Use tags ("live", "ready") to route Kubernetes liveness and readiness probes to separate endpoints.
  • Return Degraded (not Unhealthy) when a non-critical dependency is slow; orchestrators restart the pod on Unhealthy.
  • Never call AllowAnyOrigin().AllowCredentials() — it throws at startup since .NET 5.
  • Put CORS before UseRouting (or at minimum before UseAuthorization) to ensure preflight OPTIONS requests are handled.
  • Use RequireCors("policy") per endpoint, or app.MapControllers().RequireCors("policy") globally.
  • Return health check results within 10 seconds; set a timeout on slow DB checks with cts.CancelAfter().

2. Custom IHealthCheck — checking the EF Core DB

Blog.Api/HealthChecks/DatabaseHealthCheck.cs
// Blog.Api/HealthChecks/DatabaseHealthCheck.cs
using Microsoft.EntityFrameworkCore;
using Microsoft.Extensions.Diagnostics.HealthChecks;

namespace Blog.Api.HealthChecks;

public sealed class DatabaseHealthCheck(BlogDbContext db) : IHealthCheck
{
    public async Task<HealthCheckResult> CheckHealthAsync(
        HealthCheckContext context,
        CancellationToken ct = default)
    {
        try
        {
            // Lightweight: just runs "SELECT 1" via CanConnectAsync
            bool canConnect = await db.Database.CanConnectAsync(ct);

            if (!canConnect)
                return HealthCheckResult.Unhealthy("Cannot connect to SQL Server.");

            // Check post count as a quick sanity test
            int count = await db.Posts.CountAsync(ct);
            return HealthCheckResult.Healthy($"DB reachable. Posts: {count}.");
        }
        catch (Exception ex)
        {
            return HealthCheckResult.Unhealthy("DB check threw.", ex);
        }
    }
}

Rate Limiting and Output Caching

GoalProtect your API from abuse with .NET 8's built-in rate limiters and speed it up with OutputCache policies that support tag-based eviction — no extra infrastructure required.

Key definitions

AddRateLimiter
ASP.NET Core 8 service registration that enables the rate-limiting middleware and policies.
FixedWindowLimiter
Allows N requests per fixed time window (e.g. 10 req / 60 sec); resets at the window boundary.
SlidingWindowLimiter
Allows N requests per rolling window divided into segments; smoother than fixed window.
TokenBucketLimiter
Tokens replenish at a fixed rate; allows bursts up to the bucket size.
ConcurrencyLimiter
Caps the number of requests processed at the same time regardless of time.
PartitionedRateLimiter
A rate limiter keyed by a partition (e.g. user ID, IP address) so each user gets their own bucket.
429 Too Many Requests
The HTTP status code returned when a request is rejected by the rate limiter.
Retry-After
Response header telling the client how many seconds to wait before retrying.

ASP.NET Core 7+ middleware that caches full HTTP responses in-process (or Redis in .NET 8+).

Named configuration for OutputCache: duration, vary-by headers/query, tags.

Quick notes
  • Use PartitionedRateLimiter keyed by user ID in authenticated APIs to give each user their own quota.
  • On rejection, write Retry-After in OnRejected so clients back off correctly.
  • OutputCache stores the full response body; only cache idempotent GET/HEAD endpoints.
  • Add a tag to every cached endpoint in a resource group; on write, evict by that tag to invalidate the whole group.
  • ResponseCaching is controlled by Cache-Control headers from the client — OutputCache is controlled by the server, making it more secure.
  • Set a short base duration (e.g. 60 s) and vary by query string or user claim for personalised content.

// Blog.Api/Program.cs
using System.Threading.RateLimiting;
using Microsoft.AspNetCore.RateLimiting;

builder.Services.AddRateLimiter(opts =>
{
    // --- Global fixed-window policy ---
    opts.AddFixedWindowLimiter("global", o =>
    {
        o.PermitLimit         = 100;
        o.Window              = TimeSpan.FromMinutes(1);
        o.QueueProcessingOrder = QueueProcessingOrder.OldestFirst;
        o.QueueLimit          = 10;
    });

    // --- Per-user sliding window (authenticated endpoint) ---
    opts.AddPolicy("perUser", httpCtx =>
        RateLimitPartition.GetSlidingWindowLimiter(
            partitionKey: httpCtx.User.FindFirst("sub")?.Value ?? "anon",
            factory: _ => new SlidingWindowRateLimiterOptions
            {
                PermitLimit    = 20,
                Window         = TimeSpan.FromMinutes(1),
                SegmentsPerWindow = 4,
                QueueLimit     = 0,
            }));

    // --- Token bucket for comment creation ---
    opts.AddTokenBucketLimiter("commentCreate", o =>
    {
        o.TokenLimit           = 5;
        o.QueueProcessingOrder = QueueProcessingOrder.OldestFirst;
        o.QueueLimit           = 0;
        o.ReplenishmentPeriod  = TimeSpan.FromMinutes(1);
        o.TokensPerPeriod      = 2;
        o.AutoReplenishment    = true;
    });

    // 429 response with Retry-After header
    opts.OnRejected = async (ctx, ct) =>
    {
        ctx.HttpContext.Response.StatusCode = StatusCodes.Status429TooManyRequests;

        if (ctx.Lease.TryGetMetadata(MetadataName.RetryAfter, out var retryAfter))
            ctx.HttpContext.Response.Headers.RetryAfter =
                ((int)retryAfter.TotalSeconds).ToString();

        await ctx.HttpContext.Response.WriteAsync(
            "Too many requests. Please try again later.", ct);
    };
});

File Upload and Download

GoalAccept IFormFile uploads safely (size limits, content-type whitelist, magic bytes), store files outside wwwroot, and serve them with range-request support.

Key definitions

IFormFile
ASP.NET Core's abstraction for an uploaded file; exposes FileName, ContentType, Length, OpenReadStream().
ContentType whitelist
Checking IFormFile.ContentType against allowed MIME types; necessary but not sufficient — always verify magic bytes too.
Magic bytes
The first few bytes of a file that identify its real format, regardless of the file name or declared Content-Type.
Safe file name
A server-generated GUID (or slug + GUID) used as the stored name; never trust IFormFile.FileName from the client.
wwwroot
The static-file root served directly by the web server; uploaded files should NOT be stored here to prevent direct execution.
PhysicalFile
An ActionResult that streams a file from a physical path, setting Content-Type and Content-Disposition headers.
VirtualFileResult
Streams from the web root; not suitable for files outside wwwroot.
Range request
HTTP Range header support for resumable downloads; FileStreamResult and PhysicalFile handle this automatically.
IFormFile.OpenReadStream
Returns a stream you can read and copy without loading the whole file into memory.
Antiforgery
For browser form uploads, include a CSRF token; pure JSON/REST APIs use the Authorization header instead, so antiforgery is typically skipped.
MaxRequestBodySize
Kestrel and IIS limit the HTTP request body; set it per endpoint to override the default 30 MB.
Quick notes
  • Never trust IFormFile.FileName or IFormFile.ContentType from the client — they're user-controlled strings.
  • Check magic bytes by opening the stream and reading the first 4–16 bytes before saving.
  • Store uploaded files in a folder outside the content root (e.g. /data/uploads) and serve via a controller, not static files.
  • Use Path.GetRandomFileName() or Guid.NewGuid() for the stored file name; keep the original name in a database column.
  • Stream large files directly to disk with CopyToAsync; don't buffer them in memory with IFormFile.OpenReadStream().ToArray().
  • Set [RequestSizeLimit] and [RequestFormLimits] at the action level, not globally, so only upload endpoints bear the larger limit.

1. Accepting a file upload

Blog.Api/Controllers/UploadsController.cs
// Blog.Api/Controllers/UploadsController.cs
[ApiController]
[Route("api/[controller]")]
public class UploadsController(IFileStorage storage, ILogger<UploadsController> logger) : ControllerBase
{
    private static readonly string[] AllowedContentTypes =
        ["image/jpeg", "image/png", "image/webp"];

    private static readonly Dictionary<string, byte[]> MagicBytes = new()
    {
        ["image/jpeg"] = [0xFF, 0xD8, 0xFF],
        ["image/png"]  = [0x89, 0x50, 0x4E, 0x47],
        ["image/webp"] = [0x52, 0x49, 0x46, 0x46],   // "RIFF"
    };

    [HttpPost("cover")]
    [RequestSizeLimit(2 * 1024 * 1024)]                // 2 MB max
    [RequestFormLimits(MultipartBodyLengthLimit = 2 * 1024 * 1024)]
    public async Task<IActionResult> UploadCoverImage(
        IFormFile file,
        CancellationToken ct)
    {
        // 1. Content-type whitelist
        if (!AllowedContentTypes.Contains(file.ContentType))
            return BadRequest($"Only JPEG, PNG and WebP are allowed.");

        // 2. File size guard (belt + suspenders alongside the attribute)
        if (file.Length == 0 || file.Length > 2 * 1024 * 1024)
            return BadRequest("File must be 1 byte – 2 MB.");

        // 3. Magic-byte check
        if (!await HasValidMagicBytesAsync(file))
            return BadRequest("File content does not match its declared type.");

        // 4. Store with a safe, server-generated name
        string stored = await storage.SaveAsync(file, ct);

        logger.LogInformation("Cover image uploaded: {FileName} → {StoredPath}",
            file.FileName, stored);

        return Ok(new { url = $"/api/uploads/{stored}" });
    }

    private static async Task<bool> HasValidMagicBytesAsync(IFormFile file)
    {
        if (!MagicBytes.TryGetValue(file.ContentType, out byte[]? magic)) return false;

        byte[] header = new byte[magic.Length];
        await using var stream = file.OpenReadStream();
        int read = await stream.ReadAsync(header.AsMemory(0, magic.Length));
        return read == magic.Length && header.SequenceEqual(magic);
    }
}

public sealed class LocalFileStorage : IFileStorage
{
    private readonly string _root;

    public LocalFileStorage(IConfiguration cfg)
    {
        // Stored outside wwwroot: "StoragePath": "/data/blog-uploads" in appsettings
        _root = cfg["StoragePath"] ?? Path.Combine(Directory.GetCurrentDirectory(), "uploads");
        Directory.CreateDirectory(_root);
    }

    public async Task<string> SaveAsync(IFormFile file, CancellationToken ct)
    {
        // Server-generated safe name; keep original extension only after re-checking content
        string ext = file.ContentType switch
        {
            "image/jpeg" => ".jpg",
            "image/png"  => ".png",
            "image/webp" => ".webp",
            _            => throw new InvalidOperationException("Unsupported type")
        };

        string stored = $"{Guid.NewGuid():N}{ext}";
        string full   = Path.Combine(_root, stored);

        await using var dest = new FileStream(full, FileMode.CreateNew, FileAccess.Write,
            FileShare.None, bufferSize: 81920, useAsync: true);
        await file.CopyToAsync(dest, ct);         // streaming: doesn't buffer in RAM

        return stored;
    }

    public string GetPhysicalPath(string storedName) =>
        Path.GetFullPath(Path.Combine(_root, storedName));  // GetFullPath prevents path traversal

    public async Task DeleteAsync(string storedName, CancellationToken ct)
    {
        string path = GetPhysicalPath(storedName);
        if (File.Exists(path))
            await Task.Run(() => File.Delete(path), ct);
    }
}

3. Downloading a file (range requests)

// Blog.Api/Controllers/UploadsController.cs (download action)
[HttpGet("{storedName}")]
public IActionResult Download(string storedName)
{
    // Prevent path traversal: only allow simple file names
    if (storedName.Contains('/') || storedName.Contains('\\') || storedName.Contains(".."))
        return BadRequest("Invalid file name.");

    string path = _storage.GetPhysicalPath(storedName);
    if (!System.IO.File.Exists(path))
        return NotFound();

    // PhysicalFile automatically handles Range requests (resumable downloads)
    string contentType = Path.GetExtension(storedName).ToLowerInvariant() switch
    {
        ".jpg" or ".jpeg" => "image/jpeg",
        ".png"  => "image/png",
        ".webp" => "image/webp",
        _       => "application/octet-stream"
    };

    return PhysicalFile(path, contentType, enableRangeProcessing: true);
}
Tip. Set enableRangeProcessing: true in PhysicalFile so browsers and download managers can resume partial downloads with the HTTP Range header.

Blog.Api/Controllers/PostsController.cs
// Blog.Api/Controllers/PostsController.cs
using Blog.Core.Exceptions;
using Blog.Core.Models;
using Blog.Infrastructure.Data;
using Microsoft.AspNetCore.Mvc;
using Microsoft.AspNetCore.OutputCaching;
using Microsoft.EntityFrameworkCore;

namespace Blog.Api.Controllers;

[ApiController]
[Route("api/[controller]")]
public class PostsController(BlogDbContext db, IOutputCacheStore cacheStore, ILogger<PostsController> logger)
    : ControllerBase
{
    [HttpGet]
    [OutputCache(PolicyName = "postList")]
    public async Task<IActionResult> List(
        [FromQuery] int page = 1,
        [FromQuery] int pageSize = 10,
        [FromQuery] string? tag = null,
        CancellationToken ct = default)
    {
        var query = db.Posts
            .Include(p => p.Tags)
            .Where(p => p.Status == PostStatus.Published);

        if (!string.IsNullOrWhiteSpace(tag))
            query = query.Where(p => p.Tags.Any(t => t.Slug == tag));

        int total = await query.CountAsync(ct);
        var items = await query
            .OrderByDescending(p => p.PublishedAt)
            .Skip((page - 1) * pageSize)
            .Take(pageSize)
            .Select(p => new { p.Id, p.Title, p.Slug, p.AuthorName, p.PublishedAt,
                               Tags = p.Tags.Select(t => t.Name) })
            .ToListAsync(ct);

        return Ok(new { page, pageSize, total, items });
    }

    [HttpGet("{slug}")]
    [OutputCache(PolicyName = "singlePost")]
    public async Task<IActionResult> Get(string slug, CancellationToken ct)
    {
        var post = await db.Posts
            .Include(p => p.Tags)
            .Include(p => p.Comments.Where(c => c.ParentCommentId == null))
                .ThenInclude(c => c.Replies)
            .FirstOrDefaultAsync(p => p.Slug == slug && p.Status == PostStatus.Published, ct);

        if (post is null) throw new NotFoundException("Post", slug);

        return Ok(post);
    }

    [HttpPost]
    public async Task<IActionResult> Create(CreatePostRequest req, CancellationToken ct)
    {
        string slug = Slugify(req.Title);

        if (await db.Posts.AnyAsync(p => p.Slug == slug, ct))
            throw new ConflictException($"A post with slug '{slug}' already exists.");

        var post = new Post
        {
            Title      = req.Title,
            Slug       = slug,
            Content    = req.Content,
            AuthorName = req.AuthorName,
            Status     = PostStatus.Draft
        };
        db.Posts.Add(post);
        await db.SaveChangesAsync(ct);
        await cacheStore.EvictByTagAsync("posts", ct);
        logger.LogInformation("Post {Slug} created by {Author}", slug, req.AuthorName);
        return CreatedAtAction(nameof(Get), new { slug = post.Slug }, new { post.Id, post.Slug });
    }

    [HttpPost("{id:int}/publish")]
    public async Task<IActionResult> Publish(int id, CancellationToken ct)
    {
        var post = await db.Posts.FindAsync([id], ct)
            ?? throw new NotFoundException("Post", id);

        if (post.Status == PostStatus.Published)
            throw new ConflictException($"Post '{post.Slug}' is already published.");

        post.Status      = PostStatus.Published;
        post.PublishedAt = DateTime.UtcNow;
        await db.SaveChangesAsync(ct);
        await cacheStore.EvictByTagAsync("posts", ct);
        return NoContent();
    }

    private static string Slugify(string title) =>
        System.Text.RegularExpressions.Regex.Replace(
            title.Trim().ToLowerInvariant(), @"[^a-z0-9]+", "-")
        .Trim('-');

    public record CreatePostRequest(string Title, string Content, string AuthorName);
}

using Blog.Core.Exceptions;

using Blog.Infrastructure.Data;
using Microsoft.AspNetCore.Mvc;
using Microsoft.AspNetCore.RateLimiting;
using Microsoft.EntityFrameworkCore;

namespace Blog.Api.Controllers;

[ApiController]
[Route("api/posts/{{postId}}/comments")]
public class CommentsController(BlogDbContext db) : ControllerBase
{
    [HttpGet]
    public async Task<IActionResult> List(int postId, CancellationToken ct)
    {
        bool exists = await db.Posts.AnyAsync(p => p.Id == postId, ct);
        if (!exists) throw new NotFoundException("Post", postId);

        var comments = await db.Comments
            .Where(c => c.PostId == postId && c.ParentCommentId == null)
            .Include(c => c.Replies)
            .OrderByDescending(c => c.CreatedAt)
            .ToListAsync(ct);

        return Ok(comments);
    }

    [HttpPost]
    [EnableRateLimiting("commentCreate")]   // token-bucket from Program.cs
    public async Task<IActionResult> Create(int postId, CreateCommentRequest req, CancellationToken ct)
    {
        var post = await db.Posts.FindAsync([postId], ct)
            ?? throw new NotFoundException("Post", postId);

        if (post.Status != PostStatus.Published)
            throw new UnprocessableException("Cannot comment on a draft post.");

        if (req.ParentCommentId.HasValue)
        {
            bool parentExists = await db.Comments
                .AnyAsync(c => c.Id == req.ParentCommentId && c.PostId == postId, ct);
            if (!parentExists)
                throw new NotFoundException("Comment", req.ParentCommentId);
        }

        var comment = new Comment
        {
            PostId          = postId,
            Body            = req.Body,
            AuthorName      = req.AuthorName,
            ParentCommentId = req.ParentCommentId
        };
        db.Comments.Add(comment);
        await db.SaveChangesAsync(ct);
        return CreatedAtAction(nameof(List), new { postId }, new { comment.Id });
    }

    public record CreateCommentRequest(string Body, string AuthorName, int? ParentCommentId);
}

Blog.Api/Program.cs
// Blog.Api/Program.cs
using System.Threading.RateLimiting;
using Blog.Api.Exceptions;
using Blog.Api.HealthChecks;
using Blog.Core.Interfaces;
using Blog.Infrastructure.Data;
using Blog.Infrastructure.Storage;
using Microsoft.AspNetCore.RateLimiting;
using Microsoft.EntityFrameworkCore;
using Serilog;

Log.Logger = new LoggerConfiguration()
    .MinimumLevel.Warning()
    .WriteTo.Console()
    .CreateBootstrapLogger();

try
{
    var builder = WebApplication.CreateBuilder(args);

    builder.Host.UseSerilog((ctx, _, cfg) =>
        cfg.ReadFrom.Configuration(ctx.Configuration)
           .Enrich.FromLogContext()
           .Enrich.WithMachineName()
           .Enrich.WithEnvironmentName());

    builder.Services.AddDbContext<BlogDbContext>(opts =>
        opts.UseSqlServer(builder.Configuration.GetConnectionString("Blog")));

    builder.Services.AddSingleton<IFileStorage, LocalFileStorage>();

    builder.Services.AddProblemDetails();
    builder.Services.AddExceptionHandler<DomainExceptionHandler>();
    builder.Services.AddExceptionHandler<GlobalExceptionHandler>();

    builder.Services.AddHealthChecks()
        .AddCheck<DatabaseHealthCheck>("database", tags: ["ready"])
        .AddCheck<MemoryHealthCheck>("memory",    tags: ["live", "ready"]);

    builder.Services.AddCors(opts =>
        opts.AddPolicy("Frontend", p =>
            p.WithOrigins("http://localhost:3000", "https://blog.example.in")
             .AllowAnyHeader()
             .AllowAnyMethod()
             .AllowCredentials()));

    builder.Services.AddRateLimiter(opts =>
    {
        opts.AddTokenBucketLimiter("commentCreate", o =>
        {
            o.TokenLimit          = 5;
            o.ReplenishmentPeriod = TimeSpan.FromMinutes(1);
            o.TokensPerPeriod     = 2;
            o.AutoReplenishment   = true;
        });
        opts.OnRejected = async (ctx, ct) =>
        {
            ctx.HttpContext.Response.StatusCode = 429;
            if (ctx.Lease.TryGetMetadata(MetadataName.RetryAfter, out var wait))
                ctx.HttpContext.Response.Headers.RetryAfter = ((int)wait.TotalSeconds).ToString();
            await ctx.HttpContext.Response.WriteAsync("Too many requests.", ct);
        };
    });

    builder.Services.AddOutputCache(opts =>
    {
        opts.AddPolicy("postList",   b => b.Expire(TimeSpan.FromMinutes(2))
                                           .SetVaryByQuery("page", "pageSize", "tag")
                                           .Tag("posts"));
        opts.AddPolicy("singlePost", b => b.Expire(TimeSpan.FromMinutes(5))
                                           .SetVaryByRouteValue("slug")
                                           .Tag("posts"));
        opts.AddPolicy("noCache",    b => b.NoStore());
    });

    builder.Services.AddControllers();

    var app = builder.Build();

    app.UseExceptionHandler();
    app.UseSerilogRequestLogging();
    app.UseCors("Frontend");
    app.UseRateLimiter();
    app.UseOutputCache();
    app.MapControllers();
    app.MapHealthChecks("/health/live",  new() { Predicate = c => c.Tags.Contains("live")  });
    app.MapHealthChecks("/health/ready", new() { Predicate = c => c.Tags.Contains("ready") });

    app.Run();
}
catch (Exception ex) when (ex is not HostAbortedException)
{
    Log.Fatal(ex, "BlogApi startup failed");
}
finally
{
    Log.CloseAndFlush();
}

BasicWhy is the two-stage Serilog bootstrap necessary?
Without it, exceptions during host.Build() (e.g. a misconfigured connection string) would swallow silently. The bootstrap logger writes to Console before the host is ready, so startup failures are always visible.
BasicWhy is UseExceptionHandler() placed first in the pipeline?
Middleware runs in registration order. Placing UseExceptionHandler first ensures it wraps all subsequent middleware, catching exceptions from routing, authentication, controllers and output caching.
IntermediateHow do you prevent OutputCache from serving stale post data after a write?
Assign a tag to all post-list and single-post policies (e.g. 'posts'). After any create/update/delete call cacheStore.EvictByTagAsync('posts', ct). This removes all entries with that tag from the in-process store atomically.
IntermediateHow does the token-bucket rate limiter differ from a fixed-window limiter for comment spam prevention?
Token bucket replenishes at a smooth rate and allows short bursts up to the bucket size; a fixed window resets entirely and can be gamed by sending all requests at the boundary. For comment creation, token bucket distributes limits more fairly over time and is harder to abuse.

Key definitions

Cross-cutting concern
A behaviour that spans all layers and features — logging, error handling, security, caching, rate limiting — applied once, consistently, without polluting business logic.
Middleware pipeline order
The sequence in which ASP.NET Core middleware executes; order matters because each middleware wraps the next.
Defense in depth
Applying multiple independent checks (content-type + file size + magic bytes) so breaking one check alone is not sufficient.
Idempotent caching
Only caching GET/HEAD endpoints; write operations (POST/PUT/DELETE) must be NoStore so they never serve stale mutating responses.
Graceful degradation
Using HealthStatus.Degraded for non-critical checks so the pod isn't restarted for minor issues.
Quick notes
  • Health checks, CORS, rate limiting and output cache are configured in services, applied in middleware, and used in endpoints — always check all three layers.
  • Serilog's two-stage bootstrap + Log.CloseAndFlush() protects both startup and shutdown.
  • Magic-byte validation must rewind the stream to position 0 after reading — or use the approach of opening a fresh stream for validation.
  • Tag eviction from OutputCache is synchronous within the request; don't fire it in a background thread without a CancellationToken safety net.
  • The correct middleware order: ExceptionHandler → Serilog → CORS → RateLimit → OutputCache → Routing → Auth → Controllers.

// Blog.Api/Controllers/PostsController.cs — add upload action
[HttpPost("{id:int}/cover")]
[RequestSizeLimit(2 * 1024 * 1024)]
[RequestFormLimits(MultipartBodyLengthLimit = 2 * 1024 * 1024)]
public async Task<IActionResult> UploadCover(
    int id,
    IFormFile file,
    [FromServices] IFileStorage storage,
    CancellationToken ct)
{
    var post = await db.Posts.FindAsync([id], ct)
        ?? throw new NotFoundException("Post", id);

    // Validate content type
    string[] allowed = ["image/jpeg", "image/png", "image/webp"];
    if (!allowed.Contains(file.ContentType))
        throw new UnprocessableException("Only JPEG, PNG and WebP images are accepted.");

    if (file.Length > 2 * 1024 * 1024)
        throw new UnprocessableException("Cover image must be 2 MB or smaller.");

    // Magic-byte check
    byte[] buf = new byte[8];
    await using (var s = file.OpenReadStream()) await s.ReadAsync(buf.AsMemory(0, 8), ct);

    bool valid = file.ContentType switch
    {
        "image/jpeg" => buf[0] == 0xFF && buf[1] == 0xD8 && buf[2] == 0xFF,
        "image/png"  => buf[0] == 0x89 && buf[1] == 0x50 && buf[2] == 0x4E && buf[3] == 0x47,
        "image/webp" => buf[0] == 0x52 && buf[1] == 0x49 && buf[2] == 0x46 && buf[3] == 0x46,
        _            => false
    };
    if (!valid) throw new UnprocessableException("File content does not match declared type.");

    // Delete old cover if present
    if (post.CoverImage is not null)
        await storage.DeleteAsync(post.CoverImage, ct);

    string stored = await storage.SaveAsync(file, ct);
    post.CoverImage = stored;
    await db.SaveChangesAsync(ct);
    await cacheStore.EvictByTagAsync("posts", ct);

    return Ok(new { url = $"/api/uploads/{stored}" });
}

using Microsoft.Extensions.Diagnostics.HealthChecks;

namespace Blog.Api.HealthChecks;

public sealed class MemoryHealthCheck : IHealthCheck
{
    private const long DegradedThreshold = 200 * 1024 * 1024;  // 200 MB

    public Task<HealthCheckResult> CheckHealthAsync(
        HealthCheckContext context,
        CancellationToken ct = default)
    {
        long usedBytes = GC.GetTotalMemory(forceFullCollection: false);

        return Task.FromResult(usedBytes < DegradedThreshold
            ? HealthCheckResult.Healthy($"Memory: {usedBytes / 1024 / 1024} MB")
            : HealthCheckResult.Degraded($"Memory high: {usedBytes / 1024 / 1024} MB (> 200 MB)"));
    }

Q1. How many IExceptionHandler implementations are invoked for a NotFoundException? 
// DomainExceptionHandler is registered first; NotFoundException IS a DomainException.
// DomainExceptionHandler.TryHandleAsync returns true.

One — only DomainExceptionHandler. It matches the exception type and returns true, short-circuiting the chain.

string slug = "mastering-linq-in-india";

logger.LogInformation($"Post {slug} has {views} views");
A plain string: "Post mastering-linq-in-india has 1420 views". The $ makes this string interpolation; Serilog receives a pre-built string with no structured properties. Drop the $ to capture Slug and Views as filterable fields.
Q3. Does this compile and what does it do at startup? 
builder.Services.AddCors(opts =>
    opts.AddPolicy("Open", p =>
        p.AllowAnyOrigin().AllowCredentials()));
It compiles but throws InvalidOperationException at app.Build(). AllowAnyOrigin combined with AllowCredentials violates the CORS spec; ASP.NET Core 5+ rejects this combination at startup.
Q4. A GET /api/posts request comes in. What determines whether OutputCache serves a cached response or hits the DB? 
// The policy is: Expire(2 min), SetVaryByQuery("page","pageSize","tag"), Tag("posts")
// Request 1: GET /api/posts?page=1&pageSize=10 → DB hit, response cached under key (page=1,pageSize=10)
// Request 2: GET /api/posts?page=1&pageSize=10 within 2 min → cache hit
// Request 3: GET /api/posts?page=2&pageSize=10 → different vary-by key → DB hit
// After POST /api/posts and EvictByTagAsync("posts") → all entries removed → next request is DB hit
The vary-by query parameters and the tag eviction state. Each combination of page/pageSize/tag is a separate cache entry; eviction by tag removes them all.
Q5. A user sends 6 comment POST requests in 10 seconds. The token-bucket policy is: TokenLimit=5, ReplenishmentPeriod=1 min, TokensPerPeriod=2. What happens? 
// Bucket starts at 5. Each request costs 1 token.
// Requests 1–5: tokens 5→4→3→2→1→0, all succeed (HTTP 201)
// Request 6:    bucket is at 0, no token available → HTTP 429
// After 30 s:   1 token replenished (2 per 60 s = 1 per 30 s) → next request succeeds
Requests 1–5 get 201; request 6 gets 429 Too Many Requests with Retry-After ~30 s.

BasicWhat are magic bytes and why are they checked in addition to ContentType?
Magic bytes are file-format signatures at the start of a file, independent of its declared MIME type. An attacker can upload a PHP script as image.jpg with ContentType: image/jpeg; magic-byte verification catches this by reading the actual file header.
IntermediateHow does IExceptionHandler compose with the existing UseExceptionHandler middleware?
UseExceptionHandler() (no path) in .NET 8 wraps the pipeline and, on an unhandled exception, iterates the registered IExceptionHandler implementations in DI order, calling TryHandleAsync on each until one returns true. If none handles it, a default 500 response is generated.
IntermediateWhy should OutputCache policies on write endpoints use NoStore?
An endpoint that modifies data must never serve a cached response — it would return stale data to the client and might skip executing the mutation. NoStore tells the middleware to bypass the cache entirely for that endpoint, both for reading and writing.
