DAY 1 · MON

REST Principles and HTTP Semantics

GoalUnderstand URIs, verbs, idempotency, status codes, and RFC 9457 ProblemDetails so every endpoint you build speaks fluent HTTP.

Key definitions

REST
Representational State Transfer — an architectural style using resources, URIs, uniform verbs, stateless requests and self-descriptive messages.
Resource
A noun in your API — a Product, Order or Category — identified by a URI.
URI
Uniform Resource Identifier: the stable address of a resource, e.g. /api/v1/products/42.
Safe method
An HTTP method that does not modify server state: GET and HEAD.
Idempotent method
Calling it once or N times leaves the server in the same state: GET, PUT, DELETE, HEAD, OPTIONS.
POST
Creates a subordinate resource or triggers a command; neither safe nor idempotent.
PUT
Replaces a resource completely; idempotent.
PATCH
Partial update; not guaranteed idempotent — depends on the semantics.
204 No Content
Success with no response body — common for PUT, PATCH, DELETE.
201 Created
Resource was created; must include a Location header with the new resource URI.
409 Conflict
Request conflicts with current state: duplicate slug, optimistic-concurrency clash.
422 Unprocessable Content
Well-formed request that fails business/validation rules — the right code for validation errors.
ProblemDetails
RFC 9457 JSON structure for error responses: type, title, status, detail, instance.
HATEOAS
Hypermedia As The Engine Of Application State — responses include links to related actions; awareness is enough for most real-world APIs.
Quick notes
  • Use nouns for resource URIs, not verbs: /products not /getProducts.
  • Always return 201 + Location for POST creates so callers know where the new resource lives.
  • Use 422 (not 400) when input is structurally valid JSON but fails business validation.
  • ProblemDetails with errors extension lets FluentValidation field errors flow cleanly.
  • Keep URIs lowercase and hyphenated: /product-categories, not /ProductCategories.
  • Stateless means no session on the server — every request carries all it needs (auth token, etc.).

3. ProblemDetails — RFC 9457

ASP.NET Core produces this JSON by default when you throw or return a problem result. Register IExceptionHandler to convert unhandled exceptions into ProblemDetails and avoid leaking stack traces.

Program.cs (excerpt)
// Program.cs
builder.Services.AddProblemDetails();
builder.Services.AddExceptionHandler<GlobalExceptionHandler>();

app.UseExceptionHandler();   // must be early in the pipeline
GlobalExceptionHandler.cs
using Microsoft.AspNetCore.Diagnostics;
using Microsoft.AspNetCore.Mvc;

namespace Catalog.Api;

public sealed class GlobalExceptionHandler : IExceptionHandler
{
    private readonly ILogger<GlobalExceptionHandler> _log;

    public GlobalExceptionHandler(ILogger<GlobalExceptionHandler> log) => _log = log;

    public async ValueTask<bool> TryHandleAsync(
        HttpContext ctx, Exception ex, CancellationToken ct)
    {
        _log.LogError(ex, "Unhandled exception");

        var problem = new ProblemDetails
        {
            Type    = "https://tools.ietf.org/html/rfc9110#section-15.6.1",
            Title   = "An unexpected error occurred",
            Status  = StatusCodes.Status500InternalServerError,
            Detail  = ex.Message,       // sanitise in production — don't expose internals
            Instance = ctx.Request.Path
        };
        problem.Extensions["traceId"] = ctx.TraceIdentifier;

        ctx.Response.StatusCode = StatusCodes.Status500InternalServerError;
        await ctx.Response.WriteAsJsonAsync(problem, ct);
        return true;
    }
}

5. HATEOAS — awareness level

Full HATEOAS embeds links in every response so clients can discover transitions without hardcoded URIs. Most teams implement a lightweight subset — links to self, next-page, related resources — using plain JSON rather than a full media type like HAL or JSON:API. Knowing what it is matters for interviews; implementing the full RFC is overkill for most projects.

ProductResponse.cs (excerpt)
// Lightweight "links" extension on a response DTO
public record ProductResponse(int Id, string Name, decimal Price)
{{
    public Dictionary<string, string> Links {{ get; init; }} = [];
}}

// When building the response
var resp = new ProductResponse(p.Id, p.Name, p.Price)
{{
    Links = new Dictionary<string, string>
    {{
        ["self"]     = $"/api/v1/products/{{p.Id}}",
        ["category"] = $"/api/v1/categories/{{p.CategoryId}}"
    }}
}};

Common mistakes

  • Putting verbs in URIs: /getProduct/1 — use GET /products/1 instead.
  • Returning 200 with an error body — use the correct 4xx/5xx code.
  • Omitting the Location header on 201 responses.
  • Using 400 for validation failures — 422 is more precise and expected by clients.
  • Leaking exception details in ProblemDetails in production.

Self-check questions

What does idempotent mean for DELETE?Sending DELETE /products/42 multiple times returns 204 on the first call and 404 on subsequent calls, but the server state is the same after each — the item is gone.
When is 400 the right code versus 422?400 for requests that can't be parsed (malformed JSON, missing Content-Type). 422 for syntactically valid requests that fail semantic validation rules.
What fields does ProblemDetails require?status (HTTP status code) and title are the minimum. type, detail and instance are strongly recommended.

Interview questions

Answer out loud first, then open each one to compare.

BasicWhat does REST stand for and what are its key constraints?
Representational State Transfer. Key constraints: client–server, stateless (no server-side session), cacheable, uniform interface (URIs, verbs, ProblemDetails), layered system, code on demand (optional). Stateless and uniform interface are what most people mean day-to-day.
BasicWhat is the difference between PUT and PATCH?
PUT sends a complete replacement of the resource; the client must supply every field or risk clearing unset fields. PATCH sends only the changed fields. PATCH is not guaranteed idempotent; PUT is.
BasicWhy return 422 instead of 400 for validation errors?
400 means the request was malformed at the HTTP/syntax level (can't parse JSON, missing Content-Type). 422 means the request was syntactically correct but semantically invalid — the server understood it, but it failed business rules. RFC 9110 defines them separately.
BasicWhat must a 201 Created response include?
A Location header pointing to the URI of the newly created resource. Without it, the caller has no way to fetch or reference what was just created.
IntermediateWhat is IExceptionHandler in ASP.NET Core?
An interface (added in .NET 8) that centralises unhandled-exception handling. Implement TryHandleAsync to convert any thrown exception into a consistent ProblemDetails response. Register with AddExceptionHandler<T> and add app.UseExceptionHandler() to the pipeline.
IntermediateWhat is HATEOAS and do real APIs implement it?
Hypermedia As The Engine Of Application State: responses include hyperlinks to available next actions so clients don't need out-of-band documentation to navigate. Few real-world REST APIs implement full HATEOAS (HAL, JSON:API). Most implement a lightweight subset — a links dictionary with self, related, and pagination URLs.
DAY 2 · TUE

DTOs, Mapping and Records

GoalSeparate your API surface from your domain model with request/response DTOs, avoid over-posting and cycles, and choose a mapping strategy that fits your team.

Key definitions

DTO
Data Transfer Object — a plain class or record carrying only the fields needed for one use case, with no behaviour.
Over-posting
Client sends extra fields (e.g. IsAdmin=true) that get bound to a model property that shouldn't be settable via the API.
Circular reference
Two navigation properties pointing at each other; serialising naively causes infinite recursion.
Request DTO
Carries the caller's input for one operation: CreateProductRequest, UpdateProductRequest.
Response DTO
Shapes what the caller receives; may include computed fields or omit sensitive data.
Manual mapping
Writing a constructor or static factory method that explicitly copies fields — verbose but transparent.
Mapster
A source-generated or reflection-based mapping library. Fast; zero config for matching names; NuGet Mapster.
AutoMapper
Mature reflection-based mapper. Caution: in 2025 AutoMapper moved to a commercial license for large organisations — verify your situation before adopting it on a commercial project.
record
An immutable-by-default reference type with value equality; ideal for DTOs because accidental mutation is impossible.
init-only setter
A set accessor callable only during object construction or in object-initialisers — not after.
Primary constructor
C# 12 syntax: parameters declared on the class/record header, available throughout the class body.
Quick notes
  • Prefer one DTO per operation (CreateProductRequest, UpdateProductRequest) over one shared DTO.
  • Records for response DTOs; mutable classes (or records with init) for request DTOs that model binders must populate.
  • Map in a service or dedicated mapper class — never in the controller/endpoint.
  • Always whitelist properties a client may set via [Bind] or by using a dedicated request DTO.
  • Mapster can generate source code at build time (zero reflection, AOT-friendly): prefer Mapster.Tool for performance-critical paths.
  • AutoMapper's 2025 commercial licensing change: free for open-source / small teams, but verify your licence tier for commercial use.

namespace Catalog.Core.Mapping;

public static class ProductMapper
{{
    public static ProductResponse ToResponse(Product p) =>
        new(p.Id, p.Name, p.Slug, p.Price, p.Category.Name, p.StockCount > 0);

        new()

            Description = req.Description,

3. Mapster — fast zero-config mapping

Mapster maps by convention (matching names), is several times faster than AutoMapper on benchmarks, and can generate source code for AOT-safe builds. Add Mapster and optionally Mapster.DependencyInjection from NuGet.

MapsterSetup.cs
// No configuration needed when property names match
ProductResponse resp = product.Adapt<ProductResponse>();

// When names differ or you need custom logic, configure once at startup
TypeAdapterConfig<Product, ProductResponse>.NewConfig()
    .Map(dest => dest.CategoryName, src => src.Category.Name)
    .Map(dest => dest.InStock,      src => src.StockCount > 0);

// In Program.cs — scan assemblies for TypeAdapterConfig subclasses
var config = TypeAdapterConfig.GlobalSettings;
config.Scan(Assembly.GetExecutingAssembly());
builder.Services.AddSingleton(config);
builder.Services.AddScoped<IMapper, ServiceMapper>();

// Injected mapper (testable)
public class ProductService(IProductRepository repo, IMapper mapper)
{{
    public async Task<ProductResponse> GetByIdAsync(int id)
    {{
        var p = await repo.GetByIdAsync(id)
            ?? throw new NotFoundException($"Product {{id}} not found");
        return mapper.Map<ProductResponse>(p);
    }}
}}

5. Records as DTOs

DtoRecords.cs
// Positional record — constructor + deconstruct + value equality for free
public record CreateProductRequest(string Name, string Slug, decimal Price, int CategoryId);

// With optional and default values — requires { init; } syntax
public record UpdateProductRequest
{{
    public required string Name  {{ get; init; }}
    public required decimal Price {{ get; init; }}
    public string? Description   {{ get; init; }}
}}

// Response record — read-only after construction, safe to pass around
public record ProductResponse(int Id, string Name, decimal Price, bool InStock);

// Deserialization works with both positional and init-only records in System.Text.Json
// — System.Text.Json can deserialize positional records with matching constructor params
var req = JsonSerializer.Deserialize<CreateProductRequest>(json);
Tip. Use required properties (C# 11+) on request DTOs to get compile-time enforcement even when not using positional records. The model binder and JsonSerializer both respect them.
Design smell. Avoid putting [JsonIgnore] on entity navigation properties to fix serialisation cycles — use a response DTO instead. The [JsonIgnore] attribute silently drops data in ways callers don't expect.

Common mistakes

  • Sharing one DTO for create, update and response — each operation has different required fields.
  • Mapping inside a controller action — move it to a service or mapper class.
  • Returning the EF entity directly (causes cycle serialisation errors, exposes internal fields).
  • Using AutoMapper without checking your project's licence situation.
  • Mutable records with set instead of init — prefer init for response DTOs.

Self-check questions

Why is a request DTO better than [Bind] attribute for over-posting protection?A DTO is a whitelist by definition — only fields that exist on it can be populated. [Bind] is a list of exclusions on the entity itself that is easy to forget to update.

BasicWhat is a DTO and why use one?
A Data Transfer Object carries only the fields needed for a specific operation between layers or over the wire. Using DTOs decouples the API surface from the domain model, prevents over-posting, avoids serialisation issues with EF navigation properties and lets each operation define its own shape.
BasicWhat is over-posting and how do you prevent it?
Over-posting happens when a client sends extra fields (e.g. IsAdmin=true) that the server model-binds onto sensitive properties. Prevention: use a dedicated request DTO that only declares the fields the client may set. Never bind an EF entity directly.
BasicWhen would you use init vs set on a DTO property?
init (C# 9+) allows the property to be set only during object construction or in an object initialiser. Use it on response DTOs and value objects to enforce immutability. Use set on request DTOs only if something needs to mutate them post-construction (rare).
IntermediateHow does Mapster source generation work and why does it matter?
With Mapster.Tool, mapping code is generated at build time into plain C# extension methods, so at runtime there is no reflection, no expression compilation and no JIT warmup. It is compatible with AOT (Native AOT / Blazor WASM) and produces code you can read and debug.
IntermediateHow do you prevent circular reference errors when serialising EF entities?
Use response DTOs that only copy the flat fields you need — no navigation properties. Alternatively configure JsonSerializerOptions.ReferenceHandler = ReferenceHandler.IgnoreCycles in AddControllers(), but this is a band-aid; the real fix is to never serialise entities directly.
IntermediateAutoMapper vs manual mapping — when is each appropriate?
Manual mapping is best for small projects, teams that value explicitness, or when mappings are complex and bespoke. Mapster suits medium-to-large projects that want convention-based mapping with good performance. AutoMapper is acceptable if you have an existing codebase using it and have confirmed your licence. For new commercial projects in 2025, prefer Mapster or manual mapping.

FluentValidation

GoalWrite expressive, testable validation rules, wire them into ASP.NET Core's pipeline, and return 422 responses with per-field error details.

Key definitions

FluentValidation
A .NET library that uses a fluent builder API to define validation rules separate from the model class. NuGet: FluentValidation.AspNetCore.
AbstractValidator<T>
Base class for a validator; override or chain rules in the constructor with RuleFor.
RuleFor
Starts a rule chain for a specific property: RuleFor(x => x.Name).NotEmpty().MaximumLength(200).
Must / Custom
Escape hatch for logic too complex for built-in rules; Must(val => ...) or Custom((val, ctx) => ...).
MustAsync / CustomAsync
Same as above but accepts a cancellation token and returns Task<bool> — use for database uniqueness checks.
WithMessage
Overrides the default error message for a rule.
Cascade mode
CascadeMode.Stop stops validating a property after the first failure (default for a property in FV11+).
Endpoint filter
A minimal-API hook that runs before the endpoint delegate; used to auto-validate DTOs and short-circuit with 422.
Data annotations
[Required], [MaxLength], etc. — built into .NET. Simpler but mixed with the model, harder to test, less expressive.
ValidationProblemDetails
ASP.NET Core's subtype of ProblemDetails that adds an errors dictionary mapping field names to error arrays.
Quick notes
  • Register validators with builder.Services.AddValidatorsFromAssemblyContaining<CreateProductRequestValidator>().
  • Prefer FluentValidation over data annotations for complex rules, async checks and when rules live separately from the DTO.
  • Use data annotations only for truly simple structural constraints ([EmailAddress], [Range]) if your team prefers them.
  • Always return 422 (not 400) for FluentValidation failures — configure InvalidModelStateResponseFactory.
  • Test validators in isolation: instantiate the validator class and call TestValidateAsync.

1. A validator for Catalog API

CreateProductRequestValidator.cs
using FluentValidation;
using Catalog.Core.Dtos;

namespace Catalog.Core.Validators;

public class CreateProductRequestValidator : AbstractValidator<CreateProductRequest>
{{
    public CreateProductRequestValidator(IProductRepository repo)
    {{
        RuleFor(x => x.Name)
            .NotEmpty().WithMessage("Product name is required.")
            .MaximumLength(200).WithMessage("Name must be 200 characters or fewer.");

        RuleFor(x => x.Slug)
            .NotEmpty()
            .Matches(@"^[a-z0-9-]{{3,100}}$")
            .WithMessage("Slug must be 3–100 lowercase alphanumeric characters or hyphens.");

        RuleFor(x => x.Price)
            .GreaterThan(0).WithMessage("Price must be greater than ₹0.")
            .LessThanOrEqualTo(1_000_000m).WithMessage("Price cannot exceed ₹10,00,000.");

        RuleFor(x => x.CategoryId)
            .GreaterThan(0).WithMessage("A valid category is required.")
            .MustAsync(async (id, ct) => await repo.CategoryExistsAsync(id))
            .WithMessage("Category not found.");

        RuleFor(x => x.StockCount)
            .GreaterThanOrEqualTo(0).WithMessage("Stock cannot be negative.");

        // Conditional: description length only matters when provided
        When(x => x.Description is not null, () =>
        {{
            RuleFor(x => x.Description)
                .MaximumLength(2000).WithMessage("Description must be 2 000 characters or fewer.");
        }});
    }}
}}

2. Registering and auto-triggering in minimal APIs

Program.cs (validation wiring)
// Program.cs
builder.Services.AddValidatorsFromAssemblyContaining<CreateProductRequestValidator>();

// Endpoint filter that validates any T and short-circuits with 422
public static class ValidationFilter
{{
    public static async ValueTask<object?> HandleAsync<T>(
        EndpointFilterInvocationContext ctx,
        EndpointFilterDelegate next)
    {{
        var validator = ctx.HttpContext.RequestServices
            .GetService<IValidator<T>>();
        if (validator is null) return await next(ctx);

        var arg = ctx.Arguments.OfType<T>().First();
        var result = await validator.ValidateAsync(arg);
        if (!result.IsValid)
        {{
            return Results.ValidationProblem(
                result.ToDictionary(),       // field -> string[]
                statusCode: StatusCodes.Status422UnprocessableEntity);
        }}
        return await next(ctx);
    }}
}}

// Apply to an endpoint
app.MapPost("/api/v1/products", CreateProductHandler)
   .AddEndpointFilter(ValidationFilter.HandleAsync<CreateProductRequest>);

Pagination, Filtering, Sorting and Search

GoalBuild a production-quality list endpoint: offset and keyset paging, whitelisted filtering, safe dynamic sorting, full-text search, and a composable IQueryable pipeline.

Key definitions

Offset pagination
Skip N items and take M: OFFSET @skip ROWS FETCH NEXT @take ROWS ONLY. Simple but slow on large offsets.
Keyset pagination
Use the last seen key (e.g. last Id or Slug) to anchor the next page. O(log n) for any page; no skipped/duplicated rows during inserts.
Cursor
An opaque token (often base-64 encoded) returned by the server representing the position in a dataset; the client passes it back for the next page.
PagedResult<T>
A generic envelope: items, current page, page size, total count, total pages, has-next, has-previous.
Whitelist filter
Only allow filtering on fields you explicitly permit; prevents clients injecting arbitrary columns.
Safe dynamic sort
A Dictionary<string, Expression<Func<T, object>>> mapping allowed field names to LINQ expressions; unknown fields are ignored or return 400.
IQueryable composition
Building a LINQ query step-by-step, letting EF Core translate the whole thing to one SQL statement.
EF Core .AsSplitQuery()
Splits a query with multiple collection Includes into separate SQL queries to avoid a cartesian explosion.
Search
A LIKE %term% or full-text CONTAINS filter against one or more text columns.
Quick notes
  • Cap page size server-side (e.g. max 100) regardless of what the client asks.
  • Offset pagination is fine up to ~10 k rows; beyond that use keyset or cursor paging.
  • Always sort by a stable, unique column as the last sort key (usually Id) so keyset pages are deterministic.
  • Apply filters before OrderBy; apply OrderBy before Skip/Take — EF Core requires this order.
  • Use a whitelist dictionary for sortable fields — never pass a user string directly to EF's LINQ.

3. IQueryable composition pipeline

ProductRepository.cs
using System.Linq.Expressions;
using Catalog.Core.Models;
using Catalog.Infrastructure;
using Microsoft.EntityFrameworkCore;

namespace Catalog.Infrastructure.Repositories;

public class ProductRepository(CatalogDbContext db) : IProductRepository
{{
    // Safe sort whitelist: field name → EF expression
    private static readonly Dictionary<string, Expression<Func<Product, object>>> _sortMap = new()
    {{
        ["name"]       = p => p.Name,
        ["price"]      = p => (object)p.Price,
        ["created-at"] = p => p.CreatedAt
    }};

    public async Task<PagedResult<Product>> ListAsync(
        ProductListQuery q, CancellationToken ct = default)
    {{
        IQueryable<Product> query = db.Products
            .Include(p => p.Category)
            .Where(p => p.IsActive);               // base filter: only active

        // 1. Filter — whitelist only
        if (q.CategoryId.HasValue)
            query = query.Where(p => p.CategoryId == q.CategoryId.Value);

        if (q.InStock.HasValue)
            query = q.InStock.Value
                ? query.Where(p => p.StockCount > 0)
                : query.Where(p => p.StockCount == 0);

        // 2. Search (LIKE %term%)
        if (!string.IsNullOrWhiteSpace(q.Search))
        {{
            var term = q.Search.Trim();
            query = query.Where(p =>
                EF.Functions.Like(p.Name, $"%{{term}}%") ||
                EF.Functions.Like(p.Description ?? "", $"%{{term}}%"));
        }}

        // 3. Count BEFORE paging (EF translates to SELECT COUNT)
        long total = await query.LongCountAsync(ct);

        // 4. Sort — look up safe expression; fall back to Name
        var sortExpr = _sortMap.GetValueOrDefault(
            q.SortBy?.ToLowerInvariant() ?? "name", _sortMap["name"]);

        query = q.SortDir?.ToLowerInvariant() == "desc"
            ? query.OrderByDescending(sortExpr).ThenBy(p => p.Id)   // tie-break with Id
            : query.OrderBy(sortExpr).ThenBy(p => p.Id);

        // 5. Offset pagination — cap page size server-side
        int pageSize = Math.Min(q.PageSize, 100);
        int skip     = (q.Page - 1) * pageSize;

        var items = await query
            .Skip(skip)
            .Take(pageSize)
            .AsNoTracking()
            .ToListAsync(ct);

        return new PagedResult<Product>(items, q.Page, pageSize, total);
    }}
}}

4. Keyset / cursor paging

ProductRepository.cs (keyset)
// After getting page 1, the client sends the last seen slug as afterSlug.
// No OFFSET: EF translates this to WHERE Slug > @afterSlug ORDER BY Slug, Id
public async Task<List<Product>> ListKeysetAsync(
    string? afterSlug, int pageSize = 20, CancellationToken ct = default)
{{
    pageSize = Math.Min(pageSize, 100);
    IQueryable<Product> query = db.Products
        .Where(p => p.IsActive)
        .OrderBy(p => p.Name).ThenBy(p => p.Id);   // stable compound sort

    if (afterSlug is not null)
        query = query.Where(p => string.Compare(p.Slug, afterSlug) > 0);

    return await query.Take(pageSize).AsNoTracking().ToListAsync(ct);
}}

Why is a ThenBy(p => p.Id) needed after the main sort?Without a tiebreaker, two products with the same price (or name) could appear in different orders on different pages, causing items to be skipped or duplicated. Id is unique so it makes the sort deterministic.
How does EF Core translate IQueryable filter chains into SQL?EF Core builds an expression tree from each LINQ operation. Answer out loud first, then open each one to compare.

BasicWhat is offset pagination and what are its limits?
Offset pagination uses Skip/Take (SQL: OFFSET n ROWS FETCH NEXT m ROWS ONLY) to jump to a page. It is simple and supports random access to any page, but performance degrades with large offsets because the database reads and discards all preceding rows.
BasicWhy cap page size on the server?
A malicious or buggy client could request pageSize=1000000, returning millions of rows, exhausting memory and DB connections. The server must enforce a maximum (commonly 100–500) regardless of the client's request.
BasicWhat is a whitelist sort map and why use it?
A Dictionary mapping allowed field names to LINQ expressions. The user sends a sort field name; the server looks it up in the map. Unknown fields return 400. Never pass a user-supplied string directly to OrderBy — that is an injection risk.
IntermediateExplain keyset pagination and when to use it.
Keyset (cursor) paging anchors to the last seen value of the sort column: WHERE col > @lastSeen ORDER BY col TAKE n. The database uses an index seek (O(log n)) regardless of page depth, never reads skipped rows, and handles inserts/deletes between pages correctly. Use it for large tables, infinite scroll and real-time feeds.
IntermediateHow do you get the total count efficiently with EF Core?
Call query.LongCountAsync() on the filtered but un-paged IQueryable before applying Skip/Take. EF Core translates this to SELECT COUNT(*) using the same WHERE clause, so it runs in one extra DB round-trip.
IntermediateWhat is IQueryable composition and how does it help?
You build up a LINQ expression tree by chaining Where, OrderBy, Skip and Take without hitting the database. EF Core translates the entire tree into a single SQL statement when you call ToListAsync. This is more efficient than fetching all rows into memory and filtering in C#.

GoalVersion your API without breaking existing clients, polish your OpenAPI spec, and understand how to generate a typed HTTP client from it.

Key definitions

API versioning
Letting multiple versions of an endpoint coexist so old clients keep working while new clients use the latest.

using Catalog.Core.Dtos;
using Catalog.Infrastructure.Repositories;
using MapsterMapper;

namespace Catalog.Api.Endpoints;

public static class ProductEndpoints
{{
    public static void MapProductEndpoints(this WebApplication app)
    {{
        var v1 = app.NewVersionedApi("Products");
        var group = v1.MapGroup("/api/v1/products")
                      .HasApiVersion(1, 0)
                      .WithTags("Products");

        group.MapGet("/", ListProducts)
            .Produces<PagedResult<ProductResponse>>()
            .WithSummary("List products with paging, filtering, sorting and search");

        group.MapGet("/{{id:int}}", GetById)
            .Produces<ProductResponse>()
            .ProducesProblem(404)
            .WithName("GetProductById");

        group.MapGet("/by-slug/{{slug}}", GetBySlug)
            .Produces<ProductResponse>()
            .ProducesProblem(404);

        group.MapPost("/", CreateProduct)
            .Produces<ProductResponse>(StatusCodes.Status201Created)
            .ProducesProblem(StatusCodes.Status422UnprocessableEntity)
            .AddEndpointFilter(ValidationFilter.HandleAsync<CreateProductRequest>);

        group.MapPut("/{{id:int}}", UpdateProduct)
            .Produces<ProductResponse>()
            .ProducesProblem(404)
            .ProducesProblem(StatusCodes.Status422UnprocessableEntity)
            .AddEndpointFilter(ValidationFilter.HandleAsync<UpdateProductRequest>);

        group.MapDelete("/{{id:int}}", DeleteProduct)
            .Produces(StatusCodes.Status204NoContent)
            .ProducesProblem(404);
    }}

    // --- handlers (injected via parameter binding) ---

    static async Task<IResult> ListProducts(
        [AsParameters] ProductListQuery q,
        IProductRepository repo, IMapper mapper)
    {{
        var page = await repo.ListAsync(q);
        return Results.Ok(new
        {{
            items       = page.Items.Select(p => mapper.Map<ProductResponse>(p)),
            page        = page.Page,
            pageSize    = page.PageSize,
            totalCount  = page.TotalCount,
            totalPages  = page.TotalPages,
            hasNext     = page.HasNext,
            hasPrevious = page.HasPrevious
        }});
    }}

    static async Task<IResult> GetById(
        int id, IProductRepository repo, IMapper mapper)
    {{
        var p = await repo.GetByIdAsync(id);
        return p is null
            ? Results.Problem($"Product {{id}} was not found.", statusCode: 404)
            : Results.Ok(mapper.Map<ProductResponse>(p));
    }}

    static async Task<IResult> GetBySlug(
        string slug, IProductRepository repo, IMapper mapper)
    {{
        var p = await repo.GetBySlugAsync(slug);
        return p is null
            ? Results.Problem($"Product '{{slug}}' was not found.", statusCode: 404)
            : Results.Ok(mapper.Map<ProductResponse>(p));
    }}

    static async Task<IResult> CreateProduct(
        CreateProductRequest req, IProductRepository repo, IMapper mapper)
    {{
        if (await repo.SlugExistsAsync(req.Slug))
            return Results.Problem(
                detail: $"The slug '{{req.Slug}}' is already taken.",
                statusCode: StatusCodes.Status409Conflict);

        var product = mapper.Map<Product>(req);
        await repo.AddAsync(product);
        var resp = mapper.Map<ProductResponse>(product);
        return Results.Created($"/api/v1/products/{{product.Id}}", resp);
    }}

    static async Task<IResult> UpdateProduct(
        int id, UpdateProductRequest req,
        IProductRepository repo, IMapper mapper)
    {{
        var product = await repo.GetByIdAsync(id);
        if (product is null)
            return Results.Problem($"Product {{id}} was not found.", statusCode: 404);

        mapper.Map(req, product);
        product.UpdatedAt = DateTimeOffset.UtcNow;
        await repo.UpdateAsync(product);
        return Results.Ok(mapper.Map<ProductResponse>(product));
    }}

    static async Task<IResult> DeleteProduct(int id, IProductRepository repo)
    {{
        var product = await repo.GetByIdAsync(id);
        if (product is null)
            return Results.Problem($"Product {{id}} was not found.", statusCode: 404);
        await repo.DeleteAsync(product);
        return Results.NoContent();
    }}
}}

Interview questions

Answer out loud first, then open each one to compare.

BasicWhat is the purpose of the Core/Infrastructure/Api layer split?
Core holds domain models, interfaces and business rules with no framework dependencies — it can be unit-tested without ASP.NET Core or EF Core. Infrastructure implements the interfaces against real storage. Api is the thin HTTP layer. This makes Core portable and maximally testable.
BasicWhy are unique index constraints on Slug important for the API?
Slugs are used in SEO-friendly URLs. A database-level unique index enforces that no two products share a slug, complementing the application-level 409 Conflict check. If the application check races (concurrent creates), the DB constraint is the safety net.
IntermediateHow does EF Core handle the self-referencing Category hierarchy?
You configure a self-referencing relationship with HasOne(c => c.Parent).WithMany(c => c.Children).HasForeignKey(c => c.ParentId). Loading the full tree requires either recursive Includes or a raw recursive CTE. For small catalogs, eager loading two levels is fine; for deep trees, prefer a raw SQL closure table.
IntermediateHow do you prevent the category tree endpoint from causing a cycle serialisation error?
The CategoryTreeResponse record maps children recursively, projecting to DTOs rather than returning EF entities. No navigation properties from EF entities reach the serialiser, so there is no cycle.

1. Dapper hot-list endpoint

Add a GET /api/v1/products/hot endpoint that returns the 10 cheapest in-stock products. EF Core would handle this fine, but this endpoint will be called on the homepage of a high-traffic site, so we hand-tune the SQL.

using Dapper;
using Microsoft.Data.SqlClient;

namespace Catalog.Infrastructure.Repositories;

public class ProductReadRepository(IConfiguration config)
{{
    private SqlConnection OpenConnection() =>
        new(config.GetConnectionString("Catalog"));

    // Hand-tuned read query: no EF overhead, one round-trip, neatly parameterised
    public async Task<IReadOnlyList<HotProductDto>> GetHotListAsync(int take = 10)
    {{
        const string sql = """
            SELECT TOP (@take)
                   p.Id,
                   p.Name,
                   p.Slug,
                   p.Price,
                   c.Name  AS CategoryName,
                   b.Name  AS BrandName
            FROM   Products  p
            JOIN   Categories c ON c.Id = p.CategoryId
            LEFT   JOIN Brands b ON b.Id = p.BrandId
            WHERE  p.IsActive = 1
              AND  p.StockCount > 0
            ORDER  BY p.Price ASC
        """;

        await using var conn = OpenConnection();
        var rows = await conn.QueryAsync<HotProductDto>(sql, new {{ take }});
        return rows.ToList();
    }}
}}

    int     Id,
    string  Name,
    string  Slug,
    decimal Price,
    string  CategoryName,
    string? BrandName);

BasicWhat is CQRS-lite and why use it?
A lightweight application of CQRS: reads (queries) and writes (commands) use separate code paths. Here EF Core handles writes — benefiting from the change tracker, model validation and migrations — while Dapper handles a performance-sensitive read endpoint with hand-written SQL. Full CQRS with separate read/write databases (from Week 21 onwards) is the more advanced form.
BasicHow do you prevent SQL injection in Dapper?
Always use parameterised queries with anonymous objects: conn.QueryAsync<T>(sql, new {{ id }}). Never interpolate user input into SQL strings. Dapper's parameterisation maps C# type names to SQL parameter names by convention.
IntermediateWhen would you choose Dapper over EF Core for a read endpoint?
When you need fine-grained SQL control — complex aggregations, window functions, CTEs, or heavily tuned joins. Also when profiling shows EF Core's expression translation or query plan is suboptimal. For standard CRUD and simple reads, EF Core's AsNoTracking is usually fast enough and far safer.
IntermediateWhat is the N+1 problem in EF Core and how do you fix it?
If you fetch N products then access product.Category inside a loop, EF Core fires one query for the list plus N queries for the categories — N+1 total. Fix with .Include(p => p.Category) in the original query, which generates a JOIN, or with AsSplitQuery() for multiple collection Includes.
