DAY 1 · MON

Production-readiness checklist for ASP.NET Core APIs

GoalAudit every API project from Weeks 17–21 against a production checklist and apply at least six concrete before/after fixes.

Key definitions

ProblemDetails
RFC 7807 JSON error envelope: type, title, status, detail, instance; returned by AddProblemDetails().
Health check
An endpoint (/healthz) that probes liveness/readiness so load balancers and k8s know if the pod is healthy.
Rate limiting
Middleware that throttles callers (fixed window, sliding window, token bucket, concurrency) so one client can't starve others.
Paging cap
A server-side maximum on pageSize (e.g. 100) that prevents a single request fetching millions of rows.
CancellationToken
Propagated from the HTTP context; pass it into every await so a disconnected client frees the database connection.
Connection-string hygiene
Storing connection strings in appsettings.Development.json (git-ignored), user-secrets, or environment variables — never in source control.
PII in logs
Logging emails, passwords, card numbers, Aadhaar IDs etc. Breaking regulation (DPDP Act in India) and leaking to log aggregators.
Auth on mutations
Requiring [Authorize] (or policy) on every POST/PUT/PATCH/DELETE endpoint. Anonymous writes are a critical vulnerability.
Migration committed
Every dotnet ef migrations add <Name> output committed to source control so another developer (or CI) gets the same schema.
Async all the way
Every I/O call uses await + an Async method (no .Result or .Wait()) to avoid thread-pool starvation.
Status-code contract
200 OK, 201 Created with Location header, 204 No Content, 400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found, 409 Conflict.
Idempotency
GET/PUT/DELETE are safe to retry. POST is not (unless given an idempotency key).
Quick notes
  • Run the checklist top-to-bottom for each project before you call it production-ready.
  • AddProblemDetails() + UseExceptionHandler together convert unhandled exceptions to ProblemDetails automatically.
  • Use builder.Services.AddHealthChecks().AddSqlServer(connStr) (requires the AspNetCore.HealthChecks.SqlServer NuGet package) in production.
  • RateLimiterOptions lives in the built-in Microsoft.AspNetCore.RateLimiting namespace (.NET 7+); no extra NuGet needed.
  • User-secrets (dotnet user-secrets init) store dev secrets outside the project folder, never in git.
  • Always log that an action happened, never what the sensitive value was.

using Microsoft.AspNetCore.Diagnostics;
using Microsoft.AspNetCore.Mvc;

public sealed class GlobalExceptionHandler(IProblemDetailsService problemDetails)
    : IExceptionHandler
{
    public async ValueTask<bool> TryHandleAsync(
        HttpContext httpContext, Exception exception, CancellationToken ct)
    {
        // Log the exception here (without PII!)
        httpContext.Response.StatusCode = exception is NotFoundException ? 404 : 500;
        return await problemDetails.TryWriteAsync(new()
        {{
            HttpContext = httpContext,
            Exception   = exception,
            ProblemDetails = new ProblemDetails
            {{
                Type    = "https://docs.yourapp.in/errors",
                Detail  = exception.Message,   // OK for dev; sanitise for prod
                Instance = httpContext.Request.Path
            }}
        }});
    }
}

public sealed class NotFoundException(string message) : Exception(message) {{ }}

Fix4_HealthChecks.cs
// Program.cs
builder.Services
    .AddHealthChecks()
    .AddSqlServer(                           // NuGet: AspNetCore.HealthChecks.SqlServer
        connectionString: builder.Configuration.GetConnectionString("Default")!,
        healthQuery: "SELECT 1",

app.MapHealthChecks("/healthz/live",  new HealthCheckOptions {{ Predicate = _ => false }});  // liveness: just 200
app.MapHealthChecks("/healthz/ready", new HealthCheckOptions {{ ResponseWriter = WriteJsonResponse }});

static Task WriteJsonResponse(HttpContext ctx, HealthReport report)
{{
    ctx.Response.ContentType = "application/json";
    var json = System.Text.Json.JsonSerializer.Serialize(new
    {{
        status  = report.Status.ToString(),
        entries = report.Entries.ToDictionary(
            e => e.Key,
            e => new {{ status = e.Value.Status.ToString(), description = e.Value.Description }})
    }});
    return ctx.Response.WriteAsync(json);
}}
// GET /healthz/ready → {{ "status":"Healthy", "entries":{{ "sqlserver":{{ "status":"Healthy" }} }} }}

7. Paging cap and async + CancellationToken

Fix6_PagingAsync.cs
// BEFORE: caller can ask for 1 000 000 rows
app.MapGet("/api/products", (int page = 1, int pageSize = 20, AppDb db) =>
    db.Products.Skip((page - 1) * pageSize).Take(pageSize).ToList());

// AFTER: cap pageSize, full async, CancellationToken
const int MaxPage = 100;

app.MapGet("/api/products", async (
    int page, int pageSize, AppDb db, CancellationToken ct) =>
{{
    page     = Math.Max(1, page);
    pageSize = Math.Clamp(pageSize, 1, MaxPage);    // ✓ server-enforced cap

    var total = await db.Products.CountAsync(ct);
    var items = await db.Products
        .OrderBy(p => p.Id)
        .Skip((page - 1) * pageSize)
        .Take(pageSize)
        .Select(p => new ProductDto(p.Id, p.Name, p.Price))
        .ToListAsync(ct);                           // ✓ async + CancellationToken

    return Results.Ok(new {{ page, pageSize, total, items }});
}});

Common mistakes

  • Returning 200 for created resources instead of 201 with a Location header.

  • No upper bound on pageSize — a single request can read millions of rows.
  • Storing connection strings in appsettings.json and committing them to a public GitHub repo.

Self-check questions

What does RequireAuthorization() do on a minimal API endpoint?It applies the default authorization policy (authenticated user). Without it the endpoint is anonymous.
Why pass CancellationToken to SaveChangesAsync?If the browser cancels the request mid-flight, EF Core cancels the in-progress database command, freeing the connection immediately instead of holding it until the query finishes.
What is a paging cap and why is it important?A server-enforced upper limit on the page size requested by clients. Without it, a client can request all rows in one call, causing high DB load, slow responses and potential OOM.

Interview questions

Answer out loud first, then open each one to compare.

BasicWhat HTTP status code should a POST that creates a resource return?
201 Created, with a Location response header containing the URL of the new resource. Returning 200 is incorrect and breaks clients that inspect status codes.
BasicWhat is ProblemDetails and why use it?
ProblemDetails is the RFC 7807 JSON error envelope: type, title, status, detail, instance. It gives every API a consistent error shape that clients can parse generically, replacing ad-hoc error strings.
IntermediateHow do health checks differ from a plain ping endpoint?
A health check actively probes dependencies (SQL Server, Redis, downstream APIs) and returns Healthy/Degraded/Unhealthy. A ping just checks the process is alive. Kubernetes uses both: liveness (ping) to restart crashed pods, readiness (dependency checks) to route traffic.
IntermediateHow does the built-in rate limiter work in .NET 7+?
Add builder.Services.AddRateLimiter(), configure a named policy (fixed window, sliding window, token bucket or concurrency), call app.UseRateLimiter(), and annotate routes with .RequireRateLimiting("policyName"). The middleware returns 429 when the limit is exceeded.
IntermediateWhat is the DPDP Act and how does it affect logging?
India's Digital Personal Data Protection Act (2023) restricts how personal data (names, emails, phone numbers, Aadhaar IDs) is collected and stored. Logging PII unnecessarily violates the purpose-limitation principle and exposes the organisation to penalties.
IntermediateHow do you store a connection string safely for a developer machine?
Run dotnet user-secrets init in the project, then dotnet user-secrets set "ConnectionStrings:Default" "...". Secrets are stored outside the repo in the OS user profile; builder.Configuration reads them automatically in Development.
DAY 2 · TUE

Postman collection for the Blog API

GoalBuild a complete, runnable Postman collection — environments, variables, login script, Bearer pre-request, pm.test checks — and run it with Newman in CI.

Key definitions

Postman collection
A named group of saved HTTP requests, organized into folders, that can be run together.
Environment
A named set of key-value variables in Postman (e.g. Local, Staging) switched without changing requests.
Collection variable
A variable scoped to the collection, shared by all requests inside it.
Pre-request script
JavaScript that runs before a request fires; used to set a Bearer token from a collection variable.
Test script
JavaScript that runs after a response arrives; pm.test() and pm.expect() assert correctness.
Login script
A test script on the login request that extracts the JWT from the response and stores it in a variable.
pm.test
Postman's assertion function: pm.test("name", () => pm.expect(x).to.eql(y)).
pm.environment.set
Sets an environment variable at runtime: pm.environment.set("token", jwt).
Collection runner
The Postman UI that executes all requests in order and shows pass/fail counts.
Newman
Postman's Node.js CLI runner; integrates Postman collections into CI pipelines.
CSRF
Cross-Site Request Forgery; Bearer tokens in Authorization headers are immune (browsers can't set custom headers cross-origin without CORS pre-flight).
OAuth2 flow
For Postman, usually the Authorization Code + PKCE or Client Credentials flow; we use a simpler username/password login that returns a JWT.
Quick notes
  • Keep Base URL in an environment variable so switching Local → Staging → Production changes one value.
  • The login request's test script is the keystone: it stores the token so every subsequent request can use it automatically.
  • Use pm.response.to.have.status(201) to assert status and pm.response.json() to inspect the body.
  • Pre-request scripts that read pm.collectionVariables.get("token") and set the Authorization header run before EVERY request in the folder.
  • Newman exit codes: 0 = all tests pass, non-zero = failures — CI can gate on this.
  • Export the collection and environment as JSON and commit them to source control in a tests/postman/ folder.

How does the login script share the token with subsequent requests?It calls pm.collectionVariables.set("token", body.accessToken). Collection variables are readable by pre-request and test scripts in every request inside that collection.

BasicWhat is a SQL execution plan and how do you read it?

BasicExplain the difference between an index seek and an index scan.

IntermediateWhat is the cartesian explosion problem in EF Core Include?

When the extra round trips cost more than the row-multiplication saving: very low-latency databases, queries with only one Include, or inside a serialisable transaction where split queries can read inconsistent snapshots across the two SELECTs.

            ?? throw new NotFoundException($"Todo {{id}} not found");
        if (item.UserId != userId) throw new ForbiddenException();
        await repo.DeleteAsync(item, ct);

Tip. Refactor in commits: (1) add projects, move entity; (2) add interface + implementation; (3) move service; (4) rewire Program.cs. Each commit should build and all Postman tests should still pass.

Common mistakes

  • Moving everything in one huge commit — if it breaks, you can't bisect.
  • Changing the endpoint URLs or the JSON field names during the refactor — that breaks clients.
  • Putting business logic (authorization checks like 'does this todo belong to this user') in the endpoint instead of the service.
  • Injecting AppDbContext directly into the service layer — the service layer should depend only on the interface.
  • Forgetting to register the new services in Program.cs — a startup exception is easy to miss.

Self-check questions

What is the dependency inversion principle in this context?The domain and application layers define interfaces; the infrastructure layer implements them. The API project references the application layer, not the infrastructure layer directly.
Why are private setters on a domain entity important?They enforce that state changes go through methods (Complete(), Rename()) where you can add validation and business rules. Direct property assignment bypasses those rules.
Why should DTOs never contain EF navigation properties?Navigation properties cause lazy or accidental loading, circular reference issues during JSON serialisation (StackOverflowException), and leak persistence concerns into the API contract.

BasicWhat are the layers in a clean ASP.NET Core solution?
Domain (entities, interfaces, value objects, no dependencies). Application (services, use-cases, DTOs; depends on Domain). Infrastructure (EF Core, email, external APIs; depends on Application interfaces). API/Presentation (endpoints, middleware; depends on Application, injects Infrastructure via DI).
BasicWhat is a DTO and why use one?
Data Transfer Object: a serialisable record/class returned by or sent to the API, with only the fields clients need. It decouples the API contract from the EF entity, prevents over-posting and over-fetching, and avoids JSON serialiser issues with navigation properties.
IntermediateHow do you avoid breaking the API contract during a refactor?
Keep endpoint URLs, HTTP methods and JSON field names identical. Run the full Postman collection after each commit. If you must rename a JSON field, add a JsonPropertyName attribute to map the old name.
IntermediateWhere should user-ownership checks (does this todo belong to this user) live?
In the application service, not in the endpoint. The service has the business rule; the endpoint only extracts the userId from the claim and calls the service. This keeps the rule testable without an HTTP context.
IntermediateWhat is an anemic domain model and why is it considered a problem?
An entity with only public properties and no behaviour — all logic lives in service classes. The problem is that the entity cannot enforce its own invariants; any code can set any property to any invalid state. The fix is to add behaviour methods and use private setters.

Interview questions

BasicWhat is Swagger / OpenAPI?
Swagger is an interactive UI for exploring and testing API endpoints, generated from the OpenAPI specification. In .NET, Swashbuckle scans controllers/endpoints at startup and serves the spec at /swagger/v1/swagger.json. Swagger UI at /swagger renders it. Disable in production or secure it behind auth.
BasicWhat does docker-compose up do?
It reads docker-compose.yml, pulls or builds images, creates a shared Docker network, starts all services in dependency order, and streams their logs. docker compose down stops and removes the containers; volumes persist unless you add -v.
IntermediateWhy use a multi-stage Dockerfile?
The build stage contains the .NET SDK (~700 MB). The runtime stage has only the ASP.NET runtime (~220 MB). The final image is leaner, has a smaller attack surface and deploys faster. The COPY --from=build line picks only the published output.
IntermediateHow do you apply EF Core migrations in a Docker container?
Either call db.Database.Migrate() at startup (simple, suits dev/staging), or run a separate dotnet ef database update job before the API starts (safer for production, avoids race conditions when multiple API instances start simultaneously).

BasicWhat does db.Database.Migrate() do?
It applies all pending EF Core migrations to the database in order, creating tables and altering schema as needed. It is safe to call on a database that is already up to date — it checks the __EFMigrationsHistory table and does nothing.
BasicWhat is the difference between authentication and authorization?
Authentication establishes who you are (validate the JWT, extract claims). Authorization decides what you are allowed to do (check roles/policies on the endpoint). In ASP.NET Core, UseAuthentication must come before UseAuthorization in the pipeline.
IntermediateHow does the Blog API know which user made the request?
The JWT middleware validates the token's signature and expiry, then sets HttpContext.User as a ClaimsPrincipal. The endpoint reads user.FindFirstValue(ClaimTypes.NameIdentifier) to get the userId from the sub claim.
IntermediateWhat is the best way to handle a 'not found' result in a minimal API?
Return Results.NotFound() (404) rather than null or 200. For consistency, use a global exception handler: throw a NotFoundException in the service layer; the handler converts it to 404 ProblemDetails automatically.
