DAY 1 · MON

ADO.NET: SqlConnection, SqlCommand, SqlDataReader

GoalOpen a real SQL Server connection with Microsoft.Data.SqlClient, run queries safely with parameters, and understand async patterns and connection pooling.

Key definitions

ADO.NET
Active Data Objects .NET — the low-level data-access API; every higher ORM sits on top of it.
Microsoft.Data.SqlClient
The modern cross-platform SQL Server driver (NuGet); replaces the old System.Data.SqlClient.
SqlConnection
Represents one connection to SQL Server; opening it checks out a pooled connection.
SqlCommand
Encapsulates a T-SQL statement or stored procedure to run against a connection.
SqlDataReader
A fast, forward-only cursor over result rows; call Read() once per row.
ExecuteScalar
Runs a command and returns the first column of the first row as object; good for COUNT/SUM.
ExecuteNonQuery
Runs INSERT/UPDATE/DELETE; returns the number of rows affected.
ExecuteReader
Runs a SELECT and returns a SqlDataReader.
Parameters
Typed values attached to a SqlCommand via SqlParameters; prevent SQL injection.
SQL injection
Attacker injects T-SQL by embedding it in a string concatenation; parameters stop it.
Connection pooling
ADO.NET reuses physical connections; opening/closing SqlConnection is cheap by design.
TrustServerCertificate
Connection-string key needed for local Docker SQL Server that uses a self-signed cert.
await using
Disposes an IAsyncDisposable asynchronously; use on SqlConnection and SqlCommand in async code.
Quick notes
  • Always use await using (or a using block) to close connections back to the pool.
  • Never concatenate user input into T-SQL strings; always use SqlParameter.
  • CommandTimeout defaults to 30 s; set it higher for reports, lower for OLTP.
  • SqlDataReader is forward-only and must be closed before the connection can run another command.
  • ExecuteScalar returns null if the result set is empty; cast to object then check.

1. Connection string and first query

BasicQuery.cs
// NuGet: Microsoft.Data.SqlClient
using Microsoft.Data.SqlClient;

const string ConnStr =
    "Server=localhost,1433;Database=StoreDb;User Id=sa;Password=YourStrong!Pass;" +
    "TrustServerCertificate=True;";   // needed when Docker uses a self-signed cert

await using var conn = new SqlConnection(ConnStr);
await conn.OpenAsync();             // checks out a pooled connection

const string sql = "SELECT ProductId, Name, Price FROM Products WHERE CategoryId = @catId";
await using var cmd = new SqlCommand(sql, conn);
cmd.Parameters.AddWithValue("@catId", 2);     // safe: parameterised

await using var reader = await cmd.ExecuteReaderAsync();
while (await reader.ReadAsync())
{
    int    id    = reader.GetInt32(0);
    string name  = reader.GetString(1);
    decimal price = reader.GetDecimal(2);
    Console.WriteLine($"  {id,4}  {name,-30}  ₹{price,8:N2}");
}
Tip. The connection string key TrustServerCertificate=True is fine for a local Docker instance. For production, use a properly signed certificate instead.

2. SQL injection — attack and fix

SqlInjection.cs
// ❌ VULNERABLE — attacker sends name = "'; DROP TABLE Products; --"
string userInput = Console.ReadLine()!;
string badSql = $"SELECT * FROM Products WHERE Name = '{userInput}'";
// Resulting T-SQL:  SELECT * FROM Products WHERE Name = ''; DROP TABLE Products; --'

// ✓ SAFE — parameter binding
await using var conn = new SqlConnection(ConnStr);
await conn.OpenAsync();
await using var cmd = new SqlCommand(
    "SELECT ProductId, Name FROM Products WHERE Name = @name", conn);
cmd.Parameters.Add("@name", System.Data.SqlDbType.NVarChar, 200).Value = userInput;

await using var reader = await cmd.ExecuteReaderAsync();
while (await reader.ReadAsync())
    Console.WriteLine(reader.GetString(1));
Best practice. Never use Parameters.AddWithValue for binary/date types — the driver infers the wrong SqlDbType. Use Parameters.Add(name, SqlDbType.Date).Value = val for explicit types.

3. ExecuteScalar and ExecuteNonQuery

ScalarNonQuery.cs
// ExecuteScalar — scalar result

5. Connection pooling explained

  1. The first Open() creates a real TCP connection to SQL Server.
  2. On Close() / Dispose(), ADO.NET returns it to an in-process pool keyed by connection string.
  3. The next Open() with the same string reuses that physical connection — typically <1 ms vs ~50 ms for a new one.
  4. Default pool: 1–100 connections. Tune with Min Pool Size and Max Pool Size in the string.
PoolDemo.cs
// All three share the pool — physical connections are reused
for (int i = 0; i < 5; i++)
{
    await using var c = new SqlConnection(ConnStr);
    await c.OpenAsync();                            // fast after first open
    Console.WriteLine($"State: {c.State}");         // Open
}   // Dispose() returns to pool, does NOT close the TCP connection
Avoid. Setting Pooling=False in the connection string disables pooling — every Open creates a new TCP connection. Never do this in production OLTP code.

6. Async pattern: async/await from top to bottom

DataAccess.cs
public static async Task<IReadOnlyList<Product>> GetByCategoryAsync(int categoryId,
    CancellationToken ct = default)
{
    var results = new List<Product>();

    await using var conn = new SqlConnection(ConnStr);
    await conn.OpenAsync(ct);

    await using var cmd = new SqlCommand(
        "SELECT ProductId, Name, Price FROM Products WHERE CategoryId = @cid ORDER BY Name", conn);
    cmd.Parameters.Add("@cid", System.Data.SqlDbType.Int).Value = categoryId;

    await using var reader = await cmd.ExecuteReaderAsync(ct);
    while (await reader.ReadAsync(ct))
    {
        results.Add(new Product(
            reader.GetInt32(0),
            reader.GetString(1),
            reader.GetDecimal(2)));
    }
    return results;
}

public record Product(int Id, string Name, decimal Price);
Tip. Pass a CancellationToken from your controller or top-level host all the way into OpenAsync and ReadAsync. When the HTTP client disconnects, the query is cancelled and the connection returns to the pool immediately.

Common mistakes

  • Forgetting TrustServerCertificate=True for a local Docker instance and getting a certificate error.
  • Building SQL strings with $"...{userInput}..." — use parameters.
  • Reading reader.GetString(0) when the column is NULL — check reader.IsDBNull(0) first.
  • Not disposing the reader before reusing the connection (a second command on the same connection while a reader is open throws InvalidOperationException).
  • Storing the connection as a singleton field — pool a string, not an open connection.

Self-check questions

What does await using do?It calls DisposeAsync() after the block, returning the connection to the pool asynchronously.
Why shouldn't you hold a SqlConnection open across a long operation?It holds a physical connection from the pool. Under load, other threads starve waiting for a free connection.

Interview questions

Answer out loud first, then open each one to compare.

BasicWhat is ADO.NET?
The base data-access layer in .NET. It provides SqlConnection, SqlCommand, SqlDataReader and DataAdapter. ORMs like Dapper and EF Core are built on top of it.
BasicHow do SqlParameters prevent SQL injection?
The driver serialises the value separately from the query text. The value is never interpreted as T-SQL, so appending ; DROP TABLE Products is just a string value.
BasicExplain connection pooling in ADO.NET.
When you call Dispose/Close, the physical TCP connection is kept alive in a pool keyed by connection string. The next Open with the same string reuses it, avoiding the ~50 ms cost of a fresh TCP handshake and login.
IntermediateWhat is the difference between ExecuteScalar, ExecuteNonQuery and ExecuteReader?
ExecuteScalar returns one value (first column, first row) — good for COUNT/SUM. ExecuteNonQuery runs DML and returns the rows-affected count. ExecuteReader opens a forward-only cursor for multi-row SELECT results.
IntermediateWhen would you use CommandBehavior.CloseConnection?
When you want the connection auto-closed when the reader is closed — useful when you return the reader from a method so the caller doesn't need to manage the connection explicitly. With async/await and proper disposal this is rarely needed.
IntermediateWhat is the risk of Parameters.AddWithValue?
The driver infers the SqlDbType from the .NET value. A string infers NVarChar(4000) but your column might be Varchar(50), causing an index-scan rather than a seek. Use Parameters.Add(name, SqlDbType.NVarChar, 50) to be precise.
DAY 2 · TUE

Dapper: micro-ORM on top of ADO.NET

GoalUse Dapper to map query results directly into C# objects with minimal ceremony, run multi-mapping, stored procedures and IN-list queries.

Key definitions

Dapper
A micro-ORM that extends IDbConnection with extension methods like Query<T> and Execute.
Query<T>
Runs a SELECT and materialises each row into a strongly-typed T using property-name matching.
QueryAsync<T>
The async variant of Query, returning IEnumerable<T> (materialised on return).
Execute
Runs INSERT/UPDATE/DELETE; accepts an anonymous object for parameters.
Anonymous params
An anonymous object new { Name = x, Price = y } whose property names match SQL parameter names.
Multi-mapping
Query<TFirst, TSecond, TReturn> joins two tables and maps them into separate objects.
QueryMultiple
Runs multiple SELECT statements in one round trip and reads each result set sequentially.
Stored procedure
A compiled T-SQL routine; Dapper calls it with commandType: CommandType.StoredProcedure.
IN-list
A variable number of values after IN (); Dapper expands a C# collection into (@p0,@p1,...).
DynamicParameters
Dapper's typed parameter bag; supports OUTPUT parameters and table-valued parameters.
Quick notes
  • Dapper maps by property name (case-insensitive) — column alias in SQL to match the property name when they differ.
  • Dapper materialises the result set before returning, so you can close the connection immediately after the call.
  • Use QueryFirstOrDefaultAsync<T> when you expect at most one row.
  • Dapper's IN-list expansion sends @ids0, @ids1, … — this prevents injection but generates a unique plan per list size.
  • DynamicParameters is needed for OUTPUT params and stored procedures that have both IN and OUT.

1. Installing and first query

DapperBasics.cs
// NuGet: Dapper  (also requires Microsoft.Data.SqlClient)
using Dapper;
using Microsoft.Data.SqlClient;

const string ConnStr = "Server=localhost,1433;Database=StoreDb;User Id=sa;" +
                       "Password=YourStrong!Pass;TrustServerCertificate=True;";

// Query<T> maps column names to property names (case-insensitive)

foreach (var p in products)
    Console.WriteLine($"  {p.ProductId,4}  {p.Name,-30}  ₹{p.Price,8:N2}");

Product? item = await conn.QueryFirstOrDefaultAsync<Product>(
    "SELECT ProductId, Name, Price FROM Products WHERE ProductId = @id",
    new { id = 7 });

Console.WriteLine(item is null ? "Not found" : $"Found: {item.Name}");

DapperExecute.cs
await using var conn = new SqlConnection(ConnStr);

// Anonymous object: property names become @name, @price, @categoryId
int inserted = await conn.ExecuteAsync(

    new { name = "Web Cam",  price = 2499m, categoryId = 3 },

3. Multi-mapping: JOIN two tables into two objects

DapperMultimap.cs
const string joinSql = @"
    SELECT p.ProductId, p.Name, p.Price,
           c.CategoryId, c.CategoryName
    FROM   Products p
    JOIN   Categories c ON c.CategoryId = p.CategoryId
    ORDER  BY c.CategoryName, p.Name";

await using var conn = new SqlConnection(ConnStr);

// First 3 columns → Product; next 2 → Category
IEnumerable<Product> rows = await conn.QueryAsync<Product, Category, Product>(
    joinSql,
    map: (product, category) => { product.Category = category; return product; },
    splitOn: "CategoryId");   // Dapper splits at the first column named CategoryId

foreach (var p in rows)
    Console.WriteLine($"  [{p.Category?.CategoryName}] {p.Name}  ₹{p.Price:N2}");

public class Category
{
    public int    CategoryId   { get; set; }
    public string CategoryName { get; set; } = "";
}

public class Product
{
    public int      ProductId  { get; set; }
    public string   Name       { get; set; } = "";
    public decimal  Price      { get; set; }
    public Category? Category  { get; set; }
}

6. IN-list queries

DapperInList.cs
// Dapper expands the collection automatically:  WHERE ProductId IN (@ids0, @ids1, @ids2)
var ids = new[] { 3, 7, 12, 19 };
await using var conn = new SqlConnection(ConnStr);
IEnumerable<Product> found = await conn.QueryAsync<Product>(
    "SELECT ProductId, Name, Price FROM Products WHERE ProductId IN @ids",
    new { ids });   // Note: no parentheses — Dapper adds them

foreach (var p in found)
    Console.WriteLine($"  {p.ProductId}  {p.Name}  ₹{p.Price:N2}");
Limit. SQL Server has an IN-list limit of 2 100 parameters by default. For large sets, batch into groups of 1000 or use a table-valued parameter.

Common mistakes

  • Forgetting splitOn in multi-mapping (default is 'Id'; use the actual column name).
  • Calling Query<T> (synchronous) in an async method instead of QueryAsync<T>.
  • Mismatch between SQL column alias and C# property name — alias the column in SQL to match.
  • Passing a large collection to IN-list without batching, hitting the 2100-parameter limit.
  • Forgetting commandType: CommandType.StoredProcedure — the default is Text, which wraps the proc name in a SELECT.

BasicWhat is Dapper and how does it relate to ADO.NET?
Dapper is a micro-ORM — a set of extension methods on IDbConnection. It sits directly on ADO.NET, using SqlCommand internally but handling the reader-to-object mapping for you, with minimal overhead.
BasicDapper vs EF Core: when would you pick each?
Dapper for maximum control over SQL, raw performance, complex reports or existing stored procedures. EF Core for create/update/delete, change tracking, migrations and teams that prefer not to write SQL by hand.
BasicHow do you call a stored procedure with Dapper?
Pass the procedure name as the SQL, and commandType: CommandType.StoredProcedure. Parameters match by name.
IntermediateWhat is DynamicParameters and when do you need it?
A typed bag for Dapper parameters that supports OUTPUT and RETURN values: var dp = new DynamicParameters(); dp.Add("@NewId", dbType: DbType.Int32, direction: ParameterDirection.Output); then read with dp.Get<int>("@NewId"). Required for stored procedures that return values via OUTPUT params.
IntermediateHow does Dapper's batch Execute work?
Passing an IEnumerable as the param argument makes Dapper iterate and run the statement once per item in a loop. It is NOT a single bulk SQL — use SqlBulkCopy or TVPs for high-volume inserts.
IntermediateCan Dapper be used with transactions?
Yes. Pass the transaction as the transaction argument: conn.Execute(sql, params, transaction: tx). The connection and transaction must both be open and must match.
DAY 3 · WED

EF Core: DbContext, DbSet, UseSqlServer, migrations

GoalDefine a model, wire up EF Core, add the first migration, and apply it to create the schema — the foundation every day this week builds on.

Key definitions

DbContext
EF Core's unit-of-work and gateway to the database; holds configuration and the tracked entity cache.
DbSet<T>
A typed collection representing a database table; source of LINQ queries.
UseSqlServer
Extension method (from Microsoft.EntityFrameworkCore.SqlServer) that tells EF Core to generate T-SQL for SQL Server.
Convention
A default EF Core rule: a property named Id or <ClassName>Id becomes the PK; string maps to nvarchar(max).
Migration
A generated C# file recording the incremental schema change; applied with dotnet ef database update.
ModelSnapshot
EF Core's record of the current model; used to generate the next migration diff.
dotnet ef
The EF Core CLI tool (dotnet-ef global tool) for migrations, scaffolding and dbcontext operations.
add migration
Computes the diff between ModelSnapshot and the current model and writes Up()/Down() methods.
update database
Runs pending migrations against the target database.
script migration
Generates an idempotent SQL script — safe to run on a CI server or in a DBA review.
Design-time factory
A class implementing IDesignTimeDbContextFactory<TContext> that the CLI uses to build a DbContext when no DI host is available.
Quick notes
  • Never commit a migration you haven't reviewed — look at the generated C# to confirm EF Core did what you intended.
  • Keep one DbContext per HTTP request (Scoped lifetime) in web apps; never Singleton.
  • dotnet ef migrations remove deletes the last unapplied migration file — only works before update database.
  • Always add MaxLength/Column annotations (or Fluent API) for string properties; nvarchar(max) blocks some indexes.
  • Use dotnet ef migrations script for production deployments rather than update database.

EF Core relationships: Fluent API and IEntityTypeConfiguration

GoalMap one-to-many and many-to-many relationships correctly, control cascade behaviour, and move configuration out of OnModelCreating into clean per-type classes.

Key definitions

Navigation property
A C# property pointing to a related entity or collection; EF Core uses it to build JOINs.
Foreign key
A scalar property (e.g. CategoryId) that holds the PK value of the related entity.
One-to-many
One Category has many Products; the FK lives on the many-side (Products.CategoryId).
Many-to-many
Order ↔ Product; EF Core 5+ creates a join table automatically via skip navigations.
Skip navigation
A direct collection on each end of a many-to-many without an explicit join entity.
Join entity
An explicit class (e.g. OrderLine) for a many-to-many when you need extra columns on the join row.
Required relationship
FK is non-nullable; deleting the principal cascades to dependents by convention.
Optional relationship
FK is nullable; delete of principal sets FK to NULL by convention.
Cascade delete
SQL Server and EF Core automatically delete dependent rows when the principal is deleted.
Fluent API
Calls to modelBuilder.Entity<T>() in OnModelCreating that override conventions.
IEntityTypeConfiguration<T>
Interface for a per-entity configuration class; keeps OnModelCreating clean.
HasOne/HasMany/WithMany/WithOne
Fluent API methods that fully describe a relationship.
Quick notes
  • Naming conventions handle most simple FKs. Use Fluent API when names deviate or you need extra control.
  • DeleteBehavior.Restrict prevents accidental cascade delete; prefer it for most business entities.
  • Skip navigations are the cleanest many-to-many when the join row has no extra columns.
  • Always put a unique index on the join table's composite PK — EF Core does this by convention.
  • Use IEntityTypeConfiguration<T> classes for each entity to keep OnModelCreating from growing uncontrollably.

DAY 5 · FRI

CRUD with EF Core and change tracking

GoalAdd, query, update and delete entities, understand how change tracking states work, and see how SaveChanges builds the SQL behind the scenes.

Key definitions

Change tracking
EF Core watches every entity it fetched and computes what changed when SaveChanges is called.
EntityState
Enum: Added, Modified, Deleted, Unchanged, Detached — the state of an entity in the DbContext.
Snapshot
A deep copy EF Core takes when it loads an entity; it diffs the current values against this on SaveChanges.
Add
context.Products.Add(p) — marks entity as Added; EF Core will INSERT on SaveChanges.
Update
context.Products.Update(p) — marks all scalar properties as Modified; EF Core will UPDATE on SaveChanges.
Remove
context.Products.Remove(p) — marks entity as Deleted; EF Core will DELETE on SaveChanges.
SaveChanges
Wraps all pending changes in a transaction and executes the SQL; returns rows affected.
No-tracking query
.AsNoTracking() — EF Core skips the snapshot overhead; use for read-only queries.
Entry
context.Entry(entity).State — inspect or manually set the EntityState.
Detached
Entity not tracked by any context; obtained from a no-tracking query or created with new.
Concurrency token
A [Timestamp]/rowversion column; EF Core adds WHERE RowVersion = @orig to UPDATE/DELETE.
Quick notes
  • Use AsNoTracking() for every read-only query — it can be 2–5× faster at scale.
  • context.Update(entity) marks ALL columns as modified; prefer fetching first and changing only the properties that changed.
  • context.SaveChanges() wraps all changes in a single implicit transaction.
  • Multiple Add calls followed by one SaveChanges is a single transaction; this is the unit-of-work pattern.
  • Always call SaveChangesAsync in async code.

1. Create (Add + SaveChanges)

await db.SaveChangesAsync();
// EF Core generated: INSERT INTO Categories (CategoryName) VALUES (N'Electronics')
// IDENTITY flows back automatically — category.CategoryId is now populated

var product = new Product { Name = "Noise Cancelling Headphones", Price = 4999m, CategoryId = category.CategoryId };

5. How SaveChanges builds SQL

  1. EF Core iterates every tracked entity and compares current values with the snapshot.
  2. It groups changes into INSERT / UPDATE / DELETE commands.
  3. It wraps them in an implicit BEGIN TRANSACTION … COMMIT.
  4. For IDENTITY PKs it appends OUTPUT INSERTED.[Id] so the C# object gets the generated key back.
SaveChangesDemo.cs
await using var db = new StoreDbContext(options);

// All three DML statements in ONE transaction
var cat = new Category { CategoryName = "Accessories" };
db.Categories.Add(cat);

var obsolete = await db.Products.FindAsync(3);
if (obsolete is not null) db.Products.Remove(obsolete);

var existing = await db.Products.FindAsync(5);
if (existing is not null) existing.Price *= 0.9m;      // 10 % discount

int changes = await db.SaveChangesAsync();              // commit: INSERT + DELETE + UPDATE
Console.WriteLine($"{changes} change(s) saved");

Common mistakes

  • Calling context.Update(entity) with a detached entity that's missing some properties — overwrites columns with default values.
  • Forgetting await before SaveChangesAsync — no data is saved, no exception, just silence.
  • Using the same DbContext instance for two parallel async operations — DbContext is not thread-safe.
  • Not using AsNoTracking in a report endpoint that returns thousands of rows — wastes memory on snapshots.
  • Modifying a property after SaveChanges and expecting EF to auto-save — you must call SaveChanges again.

using System.Data;
using Microsoft.Data.SqlClient;
using StoreData.Core;
using StoreData.Core.Models;

namespace StoreData.Data.Ado;

public class AdoCatalogDal(string connStr) : ICatalogDal
{
    public async Task<IReadOnlyList<Product>> GetAllAsync()
    {
        const string sql = @"
            SELECT p.ProductId, p.Name, p.Price, p.CategoryId, c.CategoryName
            FROM   Products p JOIN Categories c ON c.CategoryId = p.CategoryId
            ORDER  BY p.Name";

        var list = new List<Product>();
        await using var conn = new SqlConnection(connStr);
        await conn.OpenAsync();
        await using var cmd  = new SqlCommand(sql, conn);
        await using var reader = await cmd.ExecuteReaderAsync();
        while (await reader.ReadAsync())
            list.Add(Map(reader));
        return list;
    }

    public async Task<Product?> GetByIdAsync(int id)
    {
        const string sql = @"
            SELECT p.ProductId, p.Name, p.Price, p.CategoryId, c.CategoryName
            FROM   Products p JOIN Categories c ON c.CategoryId = p.CategoryId
            WHERE  p.ProductId = @id";
        await using var conn = new SqlConnection(connStr);
        await conn.OpenAsync();
        await using var cmd = new SqlCommand(sql, conn);
        cmd.Parameters.Add("@id", SqlDbType.Int).Value = id;
        await using var reader = await cmd.ExecuteReaderAsync(CommandBehavior.SingleRow);
        return await reader.ReadAsync() ? Map(reader) : null;
    }

    public async Task<int> InsertAsync(string name, decimal price, int categoryId)
    {
        const string sql = @"
            INSERT INTO Products (Name, Price, CategoryId)
            OUTPUT INSERTED.ProductId
            VALUES (@n, @p, @c)";
        await using var conn = new SqlConnection(connStr);
        await conn.OpenAsync();
        await using var cmd = new SqlCommand(sql, conn);
        cmd.Parameters.Add("@n", SqlDbType.NVarChar, 200).Value = name;
        cmd.Parameters.Add("@p", SqlDbType.Decimal).Value        = price;
        cmd.Parameters.Add("@c", SqlDbType.Int).Value            = categoryId;
        return Convert.ToInt32(await cmd.ExecuteScalarAsync());
    }

    public async Task<bool> UpdatePriceAsync(int id, decimal newPrice)
    {
        await using var conn = new SqlConnection(connStr);
        await conn.OpenAsync();
        await using var cmd = new SqlCommand(
            "UPDATE Products SET Price = @p WHERE ProductId = @id", conn);
        cmd.Parameters.Add("@p",  SqlDbType.Decimal).Value = newPrice;
        cmd.Parameters.Add("@id", SqlDbType.Int).Value     = id;
        return await cmd.ExecuteNonQueryAsync() == 1;
    }

    public async Task<bool> DeleteAsync(int id)
    {
        await using var conn = new SqlConnection(connStr);
        await conn.OpenAsync();
        await using var cmd = new SqlCommand(
            "DELETE FROM Products WHERE ProductId = @id", conn);
        cmd.Parameters.Add("@id", SqlDbType.Int).Value = id;
        return await cmd.ExecuteNonQueryAsync() == 1;
    }

    private static Product Map(SqlDataReader r) => new()
    {
        ProductId    = r.GetInt32(0),
        Name         = r.GetString(1),
        Price        = r.GetDecimal(2),
        CategoryId   = r.GetInt32(3),
        CategoryName = r.GetString(4),
    };
}

                .AsNoTracking()
                .Include(p => p.Category)
                .OrderBy(p => p.Name)
                .Select(p => new Product
                {
                    ProductId    = p.ProductId,
                    Name         = p.Name,
                    Price        = p.Price,
                    CategoryId   = p.CategoryId,
                    CategoryName = p.Category!.CategoryName
                })
                .ToListAsync();

    public async Task<Product?> GetByIdAsync(int id) =>
        await db.Products
                .AsNoTracking()
                .Include(p => p.Category)
                .Where(p => p.ProductId == id)
                .Select(p => new Product
                {
                    ProductId    = p.ProductId,
                    Name         = p.Name,
                    Price        = p.Price,
                    CategoryId   = p.CategoryId,
                    CategoryName = p.Category!.CategoryName
                })
                .FirstOrDefaultAsync();

    public async Task<int> InsertAsync(string name, decimal price, int categoryId)
    {
        var product = new StoreData.Core.Models.EfProduct
            { Name = name, Price = price, CategoryId = categoryId };
        db.Products.Add(product);
        await db.SaveChangesAsync();
        return product.ProductId;
    }

    public async Task<bool> UpdatePriceAsync(int id, decimal newPrice)
    {
        var product = await db.Products.FindAsync(id);
        if (product is null) return false;
        product.Price = newPrice;
        await db.SaveChangesAsync();
        return true;
    }

    public async Task<bool> DeleteAsync(int id)
    {
        int rows = await db.Products.Where(p => p.ProductId == id).ExecuteDeleteAsync();
        return rows == 1;
    }
}

7. Predict the output / does it compile? quiz

Q1. What does this print and why? 
await using var conn = new SqlConnection(ConnStr);
await conn.OpenAsync();
Console.WriteLine(conn.State);
await conn.CloseAsync();
Console.WriteLine(conn.State);
await conn.OpenAsync();
Console.WriteLine(conn.State);
Open, Closed, Open. CloseAsync returns the connection to the pool (the TCP socket stays alive). The second OpenAsync checks it back out.
Q2. Does this compile? 
IEnumerable<Product> products = await conn.QueryAsync<Product>("SELECT * FROM Products");
string first = products.First().Name;
string second = products.ElementAt(1).Name;
Yes, compiles and runs. Dapper materialises the result before returning, so iterating twice is safe. ElementAt on an IEnumerable is O(n) for a list, but it won't re-query the DB.
Q3. What happens? 
var cat = new Category { CategoryName = "Electronics" };   // already exists in DB
db.Categories.Add(cat);
await db.SaveChangesAsync();
DbUpdateException wrapping a SqlException number 2601 (unique index violation on CategoryName).
Q4. What does this UPDATE statement look like? 
var p = new Product { ProductId = 7, Price = 999m };
db.Products.Update(p);
await db.SaveChangesAsync();
UPDATE Products SET Name = '', Price = 999, CategoryId = 0 WHERE ProductId = 7 — context.Update marks ALL columns Modified. Name and CategoryId become their default values, overwriting real data. Always fetch first.
Q5. How many SQL queries does this run? 
var products = await db.Products.AsNoTracking().ToListAsync();
var count    = await db.Products.CountAsync();
Two. Each LINQ terminal (ToListAsync, CountAsync) is a separate database round trip. Use QueryMultiple (Dapper) or a single SELECT … ; SELECT COUNT(*) to combine them.

To measure fairly: same query, same data, same machine. The interface swap ensures we don't accidentally benchmark different SQL or different connection behaviour.
IntermediateADO.NET vs Dapper vs EF Core: how would you choose in a real project?
Use EF Core as the default for most entity CRUD and migrations. Drop to Dapper for complex reports, stored procedures and batch operations where SQL control matters. Use ADO.NET directly only for maximum performance paths or when neither ORM fits.
IntermediateWhat is the SqlException.Number property?
The SQL Server error code. Common ones: 547 = FK violation, 2627 = PK violation, 2601 = unique index violation, 18456 = login failed. Catching SqlException and checking Number lets you give the user a meaningful error message.
AdvancedHow would you implement a retry policy for transient SQL errors?
Wrap the DAL call in a Polly policy or use EF Core's built-in EnableRetryOnFailure in UseSqlServer. Transient SQL Server error codes include 1205 (deadlock), 40613, 40197. Retry with exponential back-off and a jitter.
